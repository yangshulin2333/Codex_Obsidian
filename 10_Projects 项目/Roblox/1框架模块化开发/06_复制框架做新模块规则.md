# 复制框架做新模块规则

## 基本规则

`YanzoFrame_V0` 本体只做底座维护。

开发新模块时，先复制一份框架，再在副本里开发。

不要把具体业务写回本体。

## 文件放置

通用规则：

```text
所有模块都需要的，放 Framework。
只有当前模块需要的，放 Module。
真实状态修改，放 Server Service。
玩家显示和输入，放 Client Controller。
手工 UI 外观，Studio 管。
```

建议新增目录：

```text
src/ServerScriptService/Server/Module/Services
src/StarterPlayer/StarterPlayerScripts/Client/Module/Controllers
src/ReplicatedStorage/Module/Shared/Config
src/ReplicatedStorage/Module/Shared/Net
```

## 模块开发顺序

```text
1. 写模块目标
2. 写 Config
3. 写 Server Service
4. 写 Remote 名字和请求结构
5. 写 Client Controller
6. 如果有 UI，先确认 Studio 对象边界
7. 跑验证
8. 写模块说明
```

## Config 规则

数值写配置表，不写死在逻辑里。

例如价格、经验、掉落、初始值，优先放在：

```text
ReplicatedStorage.Module.Shared.Config
```

## Remote 规则

具体模块不要把 Remote 名字直接写在逻辑里。

建议单独建模块 RemoteNames：

```text
ReplicatedStorage.Module.Shared.Net
```

命名带模块前缀：

```text
Shop.BuyItem
Inventory.EquipItem
Enemy.Hit
```

## UI / Studio 边界

Studio 管：

- 位置
- 大小
- 颜色
- 层级
- 字体
- 布局
- Workspace 手工摆放对象

代码只做：

- 找到对象
- 绑定按钮点击
- 改文本 / 数字
- 显示 / 隐藏
- 启用 / 禁用
- 播放简单反馈
- 克隆明确标记为 Template 的对象

实现 UI 前必须写清楚：

```text
对象放在哪里
对象叫什么名字
谁负责调位置
代码允许改哪些属性
代码不允许改哪些属性
```

## 复制后第一件事

先验证框架没坏：

```powershell
stylua --check src
selene src
powershell -ExecutionPolicy Bypass -File .\scripts\Validate-ModuleBase.ps1
```

验证通过后，再加模块代码。

## 未来 Shop 方向

不要先做大商城 UI。

如果做购买模块，优先研究：

```text
ProductConfig
Developer Product
ProcessReceipt
Entitlement
Offer 触点
```

这应该作为独立 CommerceCore 模块，不放进框架本体。
