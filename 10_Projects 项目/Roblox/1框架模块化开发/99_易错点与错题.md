# 易错点与错题

## table 是引用类型

```lua
local a = {}
local b = a
```

`b` 不是复制一张新表，而是和 `a` 指向同一张表。

所以：

```lua
Services = self._servicesByName
```

意思是：

```text
context.Services 指向 _servicesByName 指向的那张表。
```

## ServiceList 和 _servicesByName

`ServiceList` 是数组，管启动顺序。

```lua
{
	NetService,
	StorageService,
	StartupSmokeTestService,
}
```

`_servicesByName` 是字典，管按名字查服务。

```lua
{
	NetService = NetService,
	StorageService = StorageService,
}
```

## key 不是表

正确：

```lua
_servicesByName["NetService"] = NetService
```

错误理解：

```lua
_servicesByName[NetService] = NetService
```

左边 key 是字符串 `"NetService"`。

## 冒号和点

```lua
object:Start()
```

等价于：

```lua
object.Start(object)
```

冒号会自动把左边的表作为第一个参数传进去。

## 不同函数里的 self 不一定一样

在 `ServiceRegistry:Init()` 里：

```text
self = registry
```

在 `NetService:Init(context)` 里：

```text
self = NetService
```

不要把不同函数里的 `self` 混成同一个。

## context.Services 背后的链

```text
ServiceList
-> ServiceRegistry 第一轮注册
-> _servicesByName[service.Name] = service
-> _context.Services 指向 _servicesByName
-> context.Services.StorageService
```

关键表是 `_servicesByName`。

## Get 返回副本

`MemoryStorage:Get(key)` 返回的是 deepCopy 后的副本。

目的：

```text
防止外部代码直接改内部真实数据。
```

真正修改必须走：

```text
Set
Update
```

## Lifecycle 和 StorageConfig 不要混

`Lifecycle.AssertModule` 检查模块结构：

- 是否 table
- Name 是否有效
- Init 是否 function
- Start 是否 function

`StorageConfig.Validate` 检查数据结构：

- data 是否 table
- SchemaVersion 是否正确

## RemoteNames 不是连接

`RemoteNames.FrameworkPing` 只是统一保存的字符串名字。

真正连接客户端和服务端的是：

```text
RemoteFunction / RemoteEvent
```

## result.Ok 不是数据本体

```lua
result.Ok
```

判断请求是否成功。

真正数据在：

```lua
result.Data
```

## task.defer 的作用

`task.defer(function() ... end)` 是延后执行。

在客户端启动测试里，它用于避免 `InvokeServer` 等待服务端返回时卡住启动流程。

## 当前框架名

所有学习文档统一使用：

```text
YanzoFrame_V0
```

不再使用旧实验名。
