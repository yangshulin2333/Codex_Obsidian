# 商店宝箱更新操作手册（执行版）

> 本手册用于实际执行“商店宝箱”更新。  
> 规则来源、截图记录和待确认问题见：[[商店宝箱更新流程_协作整理版]]。  
> 本手册只写商店宝箱，不写新关卡地图更新流程。

## 0. 使用前先填本次参数

每次更新前，先把下面这些值填清楚。后面所有 Excel、Studio 对象、代码里的 id 都按这张表核对。

| 项目 | 本次填写 |
|---|---|
| 本次宝箱名称 | 例如：`baoxiang1` 或正式英文名 |
| 本次宝箱 id | 来自 `relics_gacha.xlsx.id`，例如：`29` |
| 强力角色 id | 来自 `character.xlsx.id`，例如：`121` |
| 强力角色模型名 | 来自 `ReplicatedStorage/Resource/character`，例如：`strong001` |
| 4 个遗物 id | 来自 `relics.xlsx.id`，例如：`188,189,190,191` |
| 1 档商品 id | 来自 `goods.xlsx.id`，例如：`123` |
| 3 档商品 id | 来自 `goods.xlsx.id`，例如：`124` |
| 8 档商品 id | 来自 `goods.xlsx.id`，例如：`125` |
| 宝箱 icon | 来自 `relics_gacha.xlsx.图标` |
| 代码文件 | `Client_ShopComponent.lua` |

注意：上面的数字都是示例。正式更新时，以当前表格的最新数据和本次资源为准。

## 1. 操作总顺序

严格按这个顺序做，避免表格、资源和代码互相对不上。

1. 复制或打开测试用 Roblox 项目，不直接在原始项目上冒险。
2. 导入强力角色模型到 `ReplicatedStorage/Resource/character`。
3. 如果遗物有模型，导入到 `ReplicatedStorage/Resource/Relics`。
4. 更新 `character.xlsx`，新增强力角色。
5. 更新 `relics.xlsx`，新增 4 个遗物。
6. 更新 `relics_gacha.xlsx`，新增或更新宝箱配置。
7. 更新 `goods.xlsx`，把商品 `args` 指向本次宝箱 id。
8. 保存所有 Excel。
9. 执行 `.\config_export.bat` 生成配置。
10. 修改 `Client_ShopComponent.lua` 的宝箱 id、商品 id、title、icon。
11. Rojo 同步到 Studio，必要时断开重连。
12. Play 测试商店展示、购买、奖励发放和数据保存。

## 3. 导入强力角色资源

在 Roblox Studio 中，将强力角色模型放到：

`ReplicatedStorage/Resource/character`

执行规则：

1. 模型变量名不能和已有角色重复。
2. 变量名可以按素材自定义，例如 `strong001`。
3. 后面 `character.xlsx.模型` 必须填这个变量名。

参考图：

![](assets/商店宝箱更新流程_协作整理版/file-20260708093514395.png)

检查：

| 检查项 | 通过标准 |
|---|---|
| 模型路径 | 模型在 `ReplicatedStorage/Resource/character` 下 |
| 模型名 | 不重复 |
| Excel 对应 | `character.xlsx.模型` 与 Studio 对象名完全一致 |

## 4. 更新 `character.xlsx`

打开：

`config/character.xlsx`

新增 1 行强力角色。

参考图：

![](assets/商店宝箱更新流程_协作整理版/file-20260708093514391.png)

字段填写：

| 字段 | 怎么填 |
|---|---|
| `id` | 接当前最大 id 递增 |
| `名字` | 根据素材风格生成正式显示名 |
| `图标` | 美术给图后填 `rbxassetid://...` |
| `等级` | 强力角色不填 |
| `品质` | 当前按最高品质 `6` |
| `伤害加成` | 复制或参考前面强力角色 |
| `血量加成` | 复制或参考前面强力角色 |
| `所属关卡` | 当前沿用强力角色写法，示例为 `Secret` |
| `关卡排序` | 最新关卡编号 +1 |
| `模型` | 填 `ReplicatedStorage/Resource/character` 下的模型变量名 |
| `武器类型` | 按角色实际武器填：1 大剑，2 长枪，3 锤子，4 单手剑 |
| `特效` | 十位对应武器类型，个位按项目规则 |
| `播放延迟` | 按武器类型填写 |
| `百分比` | 强力角色必须有值 |

检查：

| 检查项 | 通过标准 |
|---|---|
| id | 不重复 |
| 模型 | 和 Studio 强力角色模型名一致 |
| 百分比 | 已填写 |
| 等级 | 留空 |
| 品质 | 使用强力角色规则 |

## 6. 更新 `relics.xlsx`

打开：

`config/relics.xlsx`

本次宝箱是 4 个遗物 + 1 个强力角色，所以这里新增 4 行遗物。

参考图：

![](assets/商店宝箱更新流程_协作整理版/file-20260708093514390.png)

![](assets/商店宝箱更新流程_协作整理版/file-20260708093514327.png)

字段填写：

| 字段 | 怎么填 |
|---|---|
| `id` | 接当前最大 id 递增，连续新增 4 个 |
| `名字` | 自定义，或根据素材让 AI 生成 |
| `图片` | 美术素材上传后的 `rbxassetid://...` |
| `品质` | 当前按 `1,2,3,4` 填 |
| `套装` | 没有套装可留空 |
| `评分` | 看着填，和同档遗物强度大致匹配 |
| `模型` | 只给图片时留空；给模型时填 `Resource/Relics` 下模型变量名 |
| `类型` | 必须和模型部位对应 |
| `伤害` | 看着填，参考同档遗物 |
| `经验` | 看着填，参考同档遗物 |
| `血量` | 看着填，参考同档遗物 |
| `移速` | 看着填，参考同档遗物 |
| 备注列 | 写清来源，例如 `商城购买` |

类型对照：

| 类型值 | 含义 |
|---|---|
| `1` | 背饰 |
| `2` | 颈部 |
| `3` | 腰带 |
| `4` | 手部 |
| `5` | 帽子 |
| `6` | 鞋子 |
| `7` | 武器 |

重点检查：

1. `模型` 有值时，必须能在 `ReplicatedStorage/Resource/Relics` 找到同名对象。
2. `类型` 必须和模型对应。例如翅膀填 `1`，武器填 `7`。
3. 只给图片时，`模型` 留空，当前按记录 `类型=1` 处理。
4. 四个新增遗物 id 后面要填到 `relics_gacha.xlsx.遗物id`。

## 8. 更新 `goods.xlsx`

打开：

`config/goods.xlsx`

这里改的是已有商品的 `其他参数 args`，不要随便改 Roblox 后台商品 id。

参考图：

![](assets/商店宝箱更新流程_协作整理版/file-20260708093514374.png)

需要改的行：

| `goods.xlsx.id` | 名字 | `其他参数 args` |
|---|---|---|
| `123` | `Suit1` | `宝箱id,1` |
| `124` | `Suit2` | `宝箱id,3` |
| `125` | `Suit3` | `宝箱id,8` |

示例：

| `goods.xlsx.id` | 示例 `args` |
|---|---|
| `123` | `29,1` |
| `124` | `29,3` |
| `125` | `29,8` |

检查：

1. `args` 第一位必须是本次 `relics_gacha.xlsx.id`。
2. `args` 第二位沿用原有档位，不随意改。
3. 不要把 `goods.xlsx.商品id` 当成这里代码里用的 `goods.xlsx.id`。

## 10. 修改 `Client_ShopComponent.lua`

打开：

`src/ReplicatedStorage/Script/Client/Component/Client_ShopComponent.lua`

这一步必须让商店显示、预览、购买实际发奖都指向同一个宝箱。

### 10.1 修改 `c:ClickShopBox(count)`

搜索：

```lua
function c:ClickShopBox(count)
```

把里面的三个 `goods_id` 更新成本次 `goods.xlsx.id`。

示例：

```lua
if count == 1 then
    goods_id = 123
elseif count == 3 then
    goods_id = 124
elseif count == 10 then
    goods_id = 125
end
```

参考图：

![](assets/商店宝箱更新流程_协作整理版/file-20260708093514370.png)

注意：代码里第三档是 `count == 10`，但 UI 上可能显示 `x8`。先不要自行改条件名，只替换对应商品 id，除非同事确认这里需要重构。

### 10.2 修改 `c:MouseEnterRelicsItem(idx,isSuit)`

搜索：

```lua
function c:MouseEnterRelicsItem(idx,isSuit)
```

把这里的宝箱 id 改成本次 `relics_gacha.xlsx.id`。

示例：

```lua
local cfg = relice_gacha_cfg[29]
```

参考图：

![](assets/商店宝箱更新流程_协作整理版/file-20260708093514330.png)

如果这里没改，鼠标悬停奖励时可能还是旧宝箱信息。

### 10.3 修改 `c:LoadEgg()`

搜索：

```lua
function c:LoadEgg()
```

同步两个地方。

商品 id：

```lua
local id1,id3,id10 = 123,124,125
```

宝箱 id：

```lua
local gacha_id = 29
```

参考图：

![](assets/商店宝箱更新流程_协作整理版/file-20260708093514329.png)

检查：

| 代码字段 | 必须对应 |
|---|---|
| `id1` | 1 档 `goods.xlsx.id` |
| `id3` | 3 档 `goods.xlsx.id` |
| `id10` | 8 档或第三档 `goods.xlsx.id` |
| `gacha_id` | 本次 `relics_gacha.xlsx.id` |

| `icon` | `relics_gacha.xlsx.图标` |

## 14. 高风险点

1. `goods.xlsx.id` 和 `goods.xlsx.商品id` 不是同一个概念，代码里用的是 `goods.xlsx.id`。
2. `relics_gacha.xlsx.id` 要同时同步到 `goods.xlsx.args` 和 `Client_ShopComponent.lua`。
3. `relics.xlsx.模型` 有值时，必须来自 `ReplicatedStorage/Resource/Relics`。
4. `relics.xlsx.类型` 必须和模型部位一致。
5. 只改购买 id、不改 `title/icon`，会导致玩家看到旧宝箱。
6. 只改 UI、不改 `MouseEnterRelicsItem`，会导致悬停奖励提示仍是旧宝箱。
7. 只改配置表、不执行 `config_export.bat`，游戏里可能仍用旧配置。
