# 巅峰进化新关卡更新操作手册（执行版）

> 本手册面向实际执行人员，目标是按顺序完成一次新关卡更新。  
> 如果需要查看规则来源、截图证据和待确认问题，见：[[新关卡更新流程_协作整理版]]。

## 0. 使用前先填这张表

每次更新新关卡前，先把本次参数写清楚，后面所有表格和 Studio 对象都按这里核对。

| 项目 | 本次填写 |
|---|---|
| 当前正式最新关卡 | 例如：13 |
| 本次新增关卡 | 例如：14 |
| 新关卡英文名 | 例如：Thunder Peak Ruins |
| 新关卡模型名 | 例如：stage14 |
| 上一关模型名 | 例如：stage13 |
| 新角色 id 范围 | 例如：114-120 |
| 新怪物 id 范围 | 例如：93-99 |
| 新宠物 id 范围 | 例如：298-312 |
| 新扭蛋 id 范围 | 例如：44-46 |
| 新升级 id 范围 | 例如：26-27 |
| 测试账号 UserId | 例如：10804390126 |

注意：上面的数字只是示例。正式更新时，以当前项目表格里的最大值和美术交付资源为准。

## 1. 操作总顺序

严格按这个顺序做，避免表格和 Studio 对象互相对不上。

1. 复制一份 `.rbxl` 项目做测试，不直接改原始项目。
2. 准备美术交付资源：角色、怪物、地图、宠物、蛋、icon。
3. 更新 Excel 配置表。
4. 在 Studio 中导入和重命名资源。
5. 调整 Stage 内怪物点位、扭蛋、升级雕像、传送门。
6. 保存所有 Excel 表。
7. 执行 `.\config_export.bat`。
8. 打开 Studio 测试权限。
9. 加测试账号 GM 白名单。
10. Play 测试新关卡。
11. 按检查清单逐项验收。

## 3. 更新 `stage.xlsx`

先更新 `stage.xlsx`，因为新关卡名字会被后面的角色、怪物、传送门使用。

### 3.1 新增一行关卡

打开 `stage.xlsx`，在最后一关下面新增一行。

| 字段 | 怎么填 |
|---|---|
| `id` | 接上一关递增 |
| `名字` | 按地图素材生成英文名，例如 `Thunder Peak Ruins` |
| `解锁需要等级` | 上一关等级 +7 |
| `模型` | 新 Stage 模型名，例如 `stage14` |
| `icon` | 场景截图上传后的 `rbxassetid://...` |
| `最后一个蛋id` | 先空着，等 `gacha.xlsx` 配完后回填本关最后一个扭蛋 id |

### 3.2 检查

| 检查项 | 通过标准 |
|---|---|
| 关卡名 | 后面所有 `所属关卡` 都和这里完全一致 |
| 模型名 | Studio 中 `ReplicatedStorage/Resource/stage` 下存在同名模型 |
| icon | 正式上线必须换成新关卡截图或美术图 |
| 最后一个蛋id | 最后回填 `gacha.xlsx` 本关最后一个 id |

## 4. 更新 `character.xlsx`

一关普通角色固定 7 个。

### 4.1 新增 7 行普通角色

| 字段 | 怎么填 |
|---|---|
| `id` | 接上一角色 id 递增，一共 7 个 |
| `名字` | 根据角色素材风格生成英文名 |
| `图标` | 美术提供，上传后填 `rbxassetid://...` |
| `等级` | 没有强力角色插入时，按上一关继续 +1 |
| `品质` | 固定 `2,2,3,3,4,4,4` |
| `伤害加成` | 高于上一关最后一个角色，按旧表曲线增加 |
| `血量加成` | 高于上一关最后一个角色，按旧表曲线增加 |
| `所属关卡` | 填 `stage.xlsx.名字`，必须完全一致 |
| `关卡排序` | 新关卡编号，例如第 14 关填 `14` |
| `模型` | 填 Studio 中角色模型对象名 |
| `武器类型` | 1 大剑，2 长枪，3 锤子，4 单手剑 |
| `特效` | 十位 = 武器类型，个位默认 7 |
| `播放延迟` | 按武器类型填，见下表 |
| `百分比` | 普通角色不填 |

### 4.2 播放延迟对应表

| 武器类型 | 武器 | 播放延迟 |
|---|---|---|
| 1 | 大剑 | 0.2 |
| 2 | 长枪 | 0.3 |
| 3 | 锤子 | 0.3 |
| 4 | 单手剑 | 0.25 |

### 4.3 强力角色注意事项

如果看到已有行的 `百分比` 字段有值，通常代表强力角色。

处理规则：

1. 强力角色的 `关卡排序` 要比最新普通关卡大 1。
2. 例如模拟新增第 14 关时，原来 `关卡排序=14` 的强力角色要改成 `15`。
3. 不要把普通新关卡 7 个角色也改成 15。

### 4.4 Studio 角色资源操作

路径：

`ReplicatedStorage/Resource/character`

操作：

1. 将外包/美术给的新角色模型导入到 `Resource/character`。
2. 如果是模拟测试，可以先复制旧关卡 7 个角色模型。
3. 模型命名一般前两位代表关卡数，例如第 14 关可用 `14011` 到 `14017` 这种风格。
4. 回到 `character.xlsx`，把 `模型` 字段填成 Studio 里实际对象名。
5. 每个角色模型内部的武器对象必须叫 `weapon`，不要改成别的名字。

检查：

| 检查项 | 通过标准 |
|---|---|
| 角色数量 | 新关卡普通角色 7 个 |
| 模型字段 | 和 Studio 对象名完全一致 |
| `所属关卡` | 和 `stage.xlsx.名字` 完全一致 |
| `weapon` | 每个角色模型内部都有 `weapon` |

## 5. 更新 `monster.xlsx`

一关怪物固定 7 个，最后一个是 Boss。

### 5.1 新增 7 行怪物

| 字段 | 怎么填 |
|---|---|
| `id` | 接上一怪物 id 递增，一共 7 个 |
| `名字` | 根据怪物素材风格生成英文名 |
| `是否是boss` | 前 6 个空，最后 1 个填 `1` |
| `boss特效` | 只填 Boss 行，参考前几关 |
| `血量` | 高于上一关最后一个怪物，按旧表曲线增加 |
| `大小` | 复制前一关规律 |
| `模型` | 填 Studio 中 `Resource/monster` 下怪物模型名 |
| `奖励奖杯` | 按旧表曲线增加 |
| `奖励经验值` | 按旧表曲线增加 |
| `所属关卡` | 新关卡编号，例如 `14` |
| `攻击力` | 按旧表曲线增加 |
| `钻石` | 按旧表曲线增加 |
| `概率%` | 参考旧表，通常保持旧规律 |
| `掉落活动币` | 按旧表曲线增加 |

其他未说明字段不要乱填。

### 5.2 Studio 怪物资源操作

怪物模型资源路径：

`ReplicatedStorage/Resource/monster`

操作：

1. 导入新关卡怪物模型。
2. 按当前最大模型名继续命名。
3. 回填 `monster.xlsx.模型`。

怪物点位路径：

`ReplicatedStorage/Resource/stage/<新关卡模型>/monsterPos`

操作：

1. 打开新 Stage，例如 `stage14`。
2. 找到 `monsterPos`。
3. 将里面点位对象名改成 `monster.xlsx.id`。
4. 例如新怪物 id 是 `93-99`，点位对象名也要是 `93-99`。

注意：`monsterPos` 对应的是 `monster.xlsx.id`，不是 `monster.xlsx.模型`。

## 6. 更新 `playerLv.xlsx`

一关新增 7 行等级奖励。

| 字段 | 怎么填 |
|---|---|
| `id` | 接上一行递增 7 个 |
| `图片` | 美术提供 |
| `下级经验` | 高于上一关，按旧表曲线增加 |
| `奖励模型id` | 填 `character.xlsx.id` |

重点：`奖励模型id` 对应的是 `character.xlsx.id`，不是角色名字，也不是 `character.xlsx.模型`。

检查：

| 检查项 | 通过标准 |
|---|---|
| 行数 | 新增 7 行 |
| 奖励模型id | 每个都能在 `character.xlsx.id` 找到 |
| 经验 | 比上一关高，曲线合理 |

## 7. 复制角色武器到 `Resource/weapon`

路径：

| 资源 | 路径 |
|---|---|
| 角色武器来源 | `ReplicatedStorage/Resource/character/<角色模型>/weapon` |
| 武器目标目录 | `ReplicatedStorage/Resource/weapon` |

操作：

1. 逐个打开新关卡角色模型。
2. 找到角色内部的 `weapon`。
3. 复制一份 `weapon`。
4. 粘贴到 `ReplicatedStorage/Resource/weapon`。
5. 将复制出来的武器改名为项目现有命名规则对应的名字。

当前截图看更像按角色模型编号命名，例如 `14014`。如果同事确认要按 `character.xlsx.名字` 命名，则以同事规则为准。

检查：

| 检查项 | 通过标准 |
|---|---|
| 武器数量 | 新关卡 7 个角色都有对应武器 |
| 命名 | 与项目现有 `Resource/weapon` 规则一致 |
| 结构 | `Handle` 等关键结构保留 |

检查：

| 检查项 | 通过标准 |
|---|---|
| 数量 | 新增 15 个宠物 |
| 品质 | 1 到 5 循环三轮 |
| 模型 | 和 Studio `Resource/Pet` 对象名一致 |
| 获取途径 | 都是本次新关卡 |

## 9. 更新 `gacha.xlsx`

一关新增 3 个蛋。

### 9.1 新增 3 行扭蛋

| 字段 | 怎么填 |
|---|---|
| `id` | 接上一扭蛋 id 递增 3 个 |
| `价格` | 比上一关贵，按旧表曲线增加 |
| `购买类型` | 默认 `3` |
| `关卡` | 新关卡编号，例如 `14` |
| `宠物id` | 每 5 个宠物一组，填英文逗号分隔 |
| `权重` | 复制上一关同位置权重 |
| `图片` | 美术提供 |

示例：

| 蛋 | 宠物 id |
|---|---|
| 第 1 个蛋 | `298,299,300,301,302` |
| 第 2 个蛋 | `303,304,305,306,307` |
| 第 3 个蛋 | `308,309,310,311,312` |

注意：宠物 id 必须用英文逗号 `,`，不要用中文逗号 `，`。

### 9.2 回填 `stage.xlsx`

回到 `stage.xlsx`。

将 `最后一个蛋id` 填成当前关卡最后一个 `gacha.xlsx.id`。

例如第 14 关新增扭蛋 `44,45,46`，则 `stage.xlsx.最后一个蛋id = 46`。

### 9.3 Studio Gacha 操作

Stage 内路径：

`ReplicatedStorage/Resource/stage/<新关卡模型>/Gacha`

要处理两个文件夹：

| 文件夹 | 用途 |
|---|---|
| `collider` | 玩家触发购买的触发块 |
| `model` | 场景里看到的蛋和底座 |

操作：

1. 打开新关卡 Stage。
2. 找到 `Gacha/collider`。
3. 将里面 3 个触发块名字改成 `gacha.xlsx.id`，例如 `44,45,46`。
4. 调整触发块位置，保证玩家站在地面上能触发。
5. 找到 `Gacha/model`。
6. 放入 3 个蛋和底座。
7. 调整摆放位置。
8. 每个蛋模型设置 `PrimaryPart`，指向蛋本体或项目中对应的主部件。

### 9.4 `Resource/Egg` 操作

路径：

`ReplicatedStorage/Resource/Egg`

操作：

1. 把 `Resource/Egg` 拖到 Workspace 下方便调整。
2. 放入新关卡 3 个蛋。
3. 调整大小。
4. 每个蛋整理成 Model。
5. 每个蛋设置 `PrimaryPart`。
6. 每个蛋模型名改成 `gacha.xlsx.id`，例如 `44,45,46`。

检查：

| 检查项 | 通过标准 |
|---|---|
| `gacha.xlsx` | 新增 3 行 |
| `stage.xlsx.最后一个蛋id` | 等于本关最后一个扭蛋 id |
| `Gacha/collider` | 名字和 `gacha.xlsx.id` 一致 |
| `Gacha/model` | 3 个蛋摆放正确，PrimaryPart 已设置 |
| `Resource/Egg` | 3 个蛋存在，命名和 `gacha.xlsx.id` 一致 |

## 10. 更新 `upgrade.xlsx`

### 10.1 新增升级项

| 字段 | 怎么填 |
|---|---|
| `id` | 接上一升级 id 递增 |
| `名字` | 选择未满的升级类型 |
| `属性` | 和名字对应，例如 `hp`、`exp` |
| `加成` | 按旧表同类规则填写 |
| `价格` | 按旧表同类规则递增 |
| `所属世界` | 新关卡编号，例如 `14` |
| 说明列 | 中文说明，与名字/属性一致 |

不要选择：

- `遗物上限+1`
- `宠物栏上限+1`

这两个已经满了。

### 10.2 Studio Upgrade 操作

路径：

`ReplicatedStorage/Resource/stage/<新关卡模型>/Upgrade`

操作：

1. 打开新关卡 Stage。
2. 找到 `Upgrade` 文件夹。
3. 将升级模型或触发块对象名改成 `upgrade.xlsx.id`。
4. 调整触发块位置，让玩家能在地面上触发。

检查：

| 检查项 | 通过标准 |
|---|---|
| 表格 id | 连续递增，无重复 |
| Studio 对象名 | 与 `upgrade.xlsx.id` 一致 |
| 类型 | 不使用已满的两类升级 |
| 触发块 | 玩家能正常触发 |

## 11. 处理传送门和唯一 Part

### 11.1 新关卡返回上一关

路径：

`ReplicatedStorage/Resource/stage/<新关卡模型>/teleport`

操作：

1. 打开新关卡 Stage。
2. 找到 `teleport`。
3. 确认存在返回上一关的传送门。
4. 修改传送门文字。
5. 文字从 `stage.xlsx` 取上一关名字，不手写猜。
6. 检查触发块位置。

### 11.2 上一关进入新关卡

路径：

`ReplicatedStorage/Resource/stage/<上一关模型>/teleport`

操作：

1. 回到上一关 Stage。
2. 找到通往下一关的传送门。
3. 修改传送门文字。
4. 文字从 `stage.xlsx` 取新关卡名字和等级。
5. 检查触发块位置。

### 11.3 移动唯一 Part

上一关里有一个所有关卡唯一的 `Part`。

操作：

1. 在上一关 Stage 中找到这个唯一 `Part`。
2. 将它移动到新关卡 Stage。
3. 确认上一关不再保留该 `Part`。
4. 确认新关卡中存在该 `Part`。

检查：

| 检查项 | 通过标准 |
|---|---|
| 新关卡返回上一关 | 可以从新关卡回到上一关 |
| 上一关进入新关卡 | 可以从上一关进入新关卡 |
| 传送门文字 | 与 `stage.xlsx` 一致 |
| 唯一 Part | 只在新关卡存在 |

## 13. 测试前设置

### 13.1 打开体验设置

在 Roblox Studio 的体验设置中，打开测试所需权限。

重点检查：

- 允许 Studio 访问 API 服务
- 允许第三方销售
- 允许第三方传送
- 允许网络/图像 API
- 允许加载第三方素材

注意：这些是测试需要。正式发布前是否保持打开，要按项目原规则确认。

### 13.2 加 GM 白名单

脚本：

`src/ServerStorage/Script/Server/Module/GMCommand.lua`

找到 `white_id_list`，加入测试账号 UserId：

```lua
[10804390126] = "test2"
```

要求：

1. 方括号里填 Roblox UserId，不是昵称。
2. 右侧字符串只是备注。
3. 只给测试账号加。

### 13.3 用 GM 指令准备测试数据

Play 后，在聊天或项目指定 GM 入口输入：

```text
.add_lv 97
.add_gems 999999999999999999999999
```

用途：

| 指令 | 用途 |
|---|---|
| `.add_lv 97` | 升级到足够进入新关卡 |
| `.add_gems ...` | 增加钻石，测试购买和升级 |

## 14. 快速传送和 Rojo 排查

### 14.1 打开 TeleportGui

Play 后打开：

`Players/<自己的角色名>/PlayerGui/TeleportGui`

例如：

`Players/yangshulin2333/PlayerGui/TeleportGui`

操作：

1. 选中 `TeleportGui`。
2. 在属性面板勾选 `Enabled`。
3. 游戏画面出现传送界面。
4. 直接选择新关卡测试。

### 14.2 Rojo 不同步时

如果 Studio 里看不到最新配置或资源：

1. 确认本地文件已保存。
2. 确认 `.\config_export.bat` 已执行。
3. 手动断开 Rojo。
4. 重新连接 Rojo。
5. 重新 Play 测试。

如果多次重连仍不对，检查导出产物、文件路径和 Rojo 项目映射。

## 15. 游戏内验收清单

完成以上步骤后，按下面清单逐项测试。

| 模块 | 要验证什么 |
|---|---|

## 17. 仍需同事确认的问题

这些问题没有确认前，不建议直接上线：

| 问题 | 风险 |
|---|---|
| `特效=28` 这类值是否有效 | 与“个位 1-7”规则冲突 |
| `character.xlsx.模型` 字段为空是否允许 | 角色模型可能加载失败 |
| `character.xlsx.所属关卡` 是否必须和 `stage.xlsx.名字` 完全一致 | 关卡归属可能读不到 |
| `Resource/weapon` 命名到底按模型编号还是角色名字 | 武器加载可能错位 |
| `stage.xlsx.icon` 正式尺寸是否固定 722x130 | UI 显示可能异常 |
| 伤害和血量是否有公式 | 数值平衡风险 |
| 强力角色是否只靠 `百分比` 字段识别 | 可能误改强力角色排序 |
