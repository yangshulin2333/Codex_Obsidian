# 3D 主岛与 2D 旅途表现方案

用户已确认第一版采用“3D 岛屿生活＋2D 远方旅行”。玩家在岛上经营，伙伴外出探索；建模集中在玩家能走到、操作和共同生活的地方，远方见闻使用插画与简单动态。确认本方案不代表正式美术已完成，也不启动代码修改、资源生成或上传。

## 场景分工

| 内容 | 表现方式 | 体验职责 |
|---|---|---|
| 四人共享主岛、住宅、港口、箱区、商店、拍卖区域 | 3D | 玩家走动、经营与现场交互，看到其他玩家；拍卖区域当前仍为白模预留 |
| 伙伴在岛上的休息、看书、短距离散步 | 3D | 看见伙伴生活在玩家身边；日常行为仍待接入 |
| 近岸海面、船只离港与归航的可见航段 | 3D | 连接伙伴出门与回家的表现，不制作完整可探索海洋 |
| 远方打捞地点与休闲旅游目的地 | 2D 插画与少量动态 | 展示伙伴的旅途；第一版不制作玩家可进入的远方 3D 关卡 |
| 明信片、照片、见闻和旅行记录 | 2D 图片与文字 | 阅读、收藏与回看；具体收获规则由对应玩法确定 |

近岸可以看见，不要求把视线内外的所有海洋都建成可探索地图。第一版玩家可活动空间按主岛与港口规划，近岸用于环境与船只出入港；边界提示和越界处理需另行接入、验证。以后确有玩家登陆探索玩法，再单独制作相应目的地的 3D 场景。

## 离港与归航衔接

1. 伙伴在主岛形成计划和准备，由服务端到期决定出发。
2. 伙伴操作 3D 小船离港，船在远处逐渐淡出；玩家角色继续留在岛上。
3. 玩家主动打开可关闭的旅行观察窗，查看伙伴的 2D 旅途画面；关闭后继续经营岛屿。
4. 伙伴归航时，3D 船从远处接近码头，伙伴回到岛上。

观察窗是在看伙伴，不是把玩家角色传送到远方。界面开关不暂停任务；船只淡出、靠岸动作和图片播放结束也不触发奖励结算。

## 第一版美术制作范围

- 浅滩、近海两套分层背景，包含天空、海面和远景元素。
- 伙伴与小船形象配少量云浪、小船起伏等动态，复用基础动画和素材，不制作长篇连续动画。
- 明信片采用不同构图表现旅行见闻，可复用海域素材，但应保持收藏内容的区别。
- 3D 和 2D 统一伙伴轮廓、角色比例、配色以及船只特征，建立同一位伙伴从家出发、旅行再回家的联系。

具体素材沿用已确认的资源规格；角色与画风细化、尚未确定的新图片尺寸、动作帧数和分项预算按制作任务补齐。上述方向不要求现在生图或上传图片。

## 逻辑与表现解耦

服务端管理计划、绝对时间、补给、箱位和奖励。3D 模型、伙伴动作、2D 观察窗与文字只展示这些状态，不参与决定是否出发或发放收获。

模型通过稳定的定位、站位及交互锚点接入；图片通过已有资源配置接入。更换外观不修改航海规则，缺失或加载中的美术资源不重抽计划和奖励。生活行为与任务状态的分工见 [[05_玩家职责与Demo游戏闭环]]，两类出游的资源边界见 [[04_打捞远航与休闲旅游_方向记录]]。

2D 方案主要减少远方场景的建模与互动空间制作工作，仍需控制图片数量、尺寸和素材复用。是否满足手机性能目标需用实际设备验证，不能仅因采用 2D 就宣称性能已达标。
