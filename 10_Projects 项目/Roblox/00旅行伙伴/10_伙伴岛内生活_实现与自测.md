# 伙伴岛内生活：实现与自测

工程：`F:\HunyueRoblox\TravelBuddy`。本阶段让伙伴在岛上空闲时自主待机、看书和短距离散步，旅行准备会打断生活。代码、原生资源和普通导表已完成，待用户自测；遵守用户要求，本轮没有运行测试、格式校验、构建或 Studio 验收。

规则承接 [离线多趟与收获汇总](09_离线多趟与收获汇总_实现与自测.md)，旅行 v5 存档、自动入库与离线多趟继续沿用。

## 玩家能看到的行为

旅行阶段优先：在途、归航、休息和准备时，伙伴服从当前旅行状态。只有进入岛内空闲，才在下列生活活动中按配置权重选择；还有其他可选活动时，避免立即重复上一项。

| 活动 | 岛上表现 |
|---|---|
| `Idle` 待机 | 在个人休息位置停留 |
| `Reading` 看书 | 到个人看书位置，显示独立阅读道具 |
| `Walking` 散步 | 沿个人地块的四个散步点走一小段路线 |

行囊没补给、箱区满、玩家暂缓或船施工，只会阻止下一趟出游，不会关闭伙伴的岛内生活。开始准备或出发时，当前看书、散步立即让位；归家仍先按原有规则靠岸和休息，结束后再由旅行条件决定准备或生活。

生活不消耗补给、物品或金币，不发奖励，不开箱、出售或上架。它不改变玩家经营资产，也不成为出游的新条件。

## 逻辑与模型分开

`CompanionLifeDomain` 只读取公开旅行状态并安排会话活动；`TravelService` 提供时钟和独立生活随机流。生活选择不会消耗旅行决策或奖品的随机流。公开状态为 `CompanionActivity`，包含 `Kind/Serial/StartAt/EndAt`；旅行数据版本没变化时，也按生活序号推送，客户端按序号防止旧响应覆盖新活动。

生活记录只存在于当前在线会话，不写入永久存档。离线不会逐次补演无收益的看书、散步；重进先恢复旅行时间轴，再按当前旅行阶段安排生活。服务端即使长时间没有调度，也只从当前时刻开始一项活动。

World 服务消费活动状态来定位和表现伙伴，不选择活动、不决定奖励。资源合同如下：

| 资源 | 职责与替换要求 |
|---|---|
| 世界个人区的 `LifeAnchors` | 保留 `Rest`、`Read`、`Walk1`～`Walk4`；它们决定休息、看书和散步位置。有世界锚点目录时优先使用 |
| 世界 `LifeArea.Appearance` | 保存生活区域外观。替换美术时可调整外观，保留独立世界锚点的名称与层级 |
| `CompanionLifeArea` Template | 根 Model 直接包含 `LifeAnchors` 和 `Appearance`，`PivotPart` 为原点部件。旧岛没有世界 `LifeAnchors` 时克隆到个人 Runtime，模板原点按 `HomeAnchor` 对齐；模板外观可单独替换 |
| `ReadingBook` Template | 可单独换成正式阅读道具；跟随伙伴模型 pivot，不依赖 Frog 内部零件名称 |
| 伙伴模型 | 沿用原有 PrimaryPart、pivot 与所有权合同；更换外观不修改生活选择逻辑 |

默认 Rojo 没有映射现有手工 Workspace 岛，服务端资源与代码同步后，旧岛重新 Play 会通过上述模板获得生活样板，不必导入整岛。已有世界 `LifeAnchors` 时不重复克隆生活区域；制作自定义岛时，可保留这些独立世界点并按需要摆放 `LifeArea` 外观。原生静态岛资源也已定向追加四个地块的生活点与外观，本轮没有执行作者脚本的全岛重生成。

缺少生活锚点时，表现回退到可用的 Rest/Home 站位；缺少阅读道具时只省略道具，不影响生活选择。旅行、存档和资产逻辑继续运行，离开释放个人区时清理运行道具与生活区域。固定点位切换、简易姿态和步行动画是当前样板，没有寻路避障；正式伙伴动作和美术仍待替换。

## 本轮配置

正式 `TravelConfig.xlsx` 的 `TravelSettings` 已写入七行配置（A38:C44），准备工作簿脚本同步维护这些默认值。

| 配置 ID | 当前默认值 | 用途 |
|---|---:|---|
| `LifeMinSeconds` / `LifeMaxSeconds` | 30 / 60 | 正式每项空闲生活的持续时间范围 |
| `StudioLifeMinSeconds` / `StudioLifeMaxSeconds` | 5 / 10 | Studio 每项空闲生活的持续时间范围 |
| `LifeIdleWeight` | 1 | 待机权重 |
| `LifeReadingWeight` | 2 | 看书权重 |
| `LifeWalkingWeight` | 2 | 散步权重 |

生活时长使用独立配置，不乘旅行 `TimeScale`。活动每次重新选取且排除上一项，因此这些权重不等于最终出现次数的固定比例；首次也不保证选择看书或散步。

本轮已执行 `scripts/Import-GameConfig.ps1` 普通导表，结果为 `CONFIG_IMPORT_OK`。这是实现依赖的生成步骤，不代表测试或验收已完成，生成配置继续由 Excel 工具维护。

## 用户自测

1. **空闲切换**：停止并重新 Play，保持岛内空闲，观察多次待机、看书和散步切换；首次不保证看书或散步。Studio 每项约 5～10 秒，正式为 30～60 秒，有其他活动可选时不立即重复上一项。
2. **等待仍生活**：分别检查无行囊补给、箱满、暂缓与船施工，确认伙伴继续生活，满足旅行条件后再准备。
3. **旅行打断**：看书或散步中装好行囊并恢复出游，确认准备立即打断生活；观察出发、归航、休息和再次准备，不出现生活位置覆盖船上或归航位置。
4. **资产边界**：记录金币、行囊、背包、封箱及图鉴，观察几项生活后核对；生活不扣款、不发奖、不处理封箱，正常旅行变化按旅行规则判断。
5. **重进恢复**：活动中退出重进，确认当前旅行阶段先恢复，生活重新安排；不重播离线生活、不产生生活收益，已有旅行记录和未读汇总保留。
6. **个人区与状态显示**：观察自己的伙伴与活动提示，确认散步留在个人区；多人时不使用别人的生活点，较早的响应不会使活动回到上一项。手机上确认活动提示可见。

模型替换自测：按当前岛的接入方式替换世界 `LifeArea.Appearance` 或模板 `CompanionLifeArea.Appearance`，并替换 `ReadingBook` 外观，保留稳定锚点与 Template 合同，再观察看书和散步；移除一个锚点或道具时确认表现回退且业务仍可正常运行。

尚未验证：以上玩法与替换、多人、手机、真实持久化和请求时序。没有运行自动测试、格式校验、构建或 Studio 验收；源代码与资源需用户现场确认，旧构建 Place 不代表本轮已验证。
