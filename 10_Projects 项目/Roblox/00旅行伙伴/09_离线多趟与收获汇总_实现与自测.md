# 离线多趟与收获汇总：实现与自测

工程：`F:\HunyueRoblox\TravelBuddy`。本阶段接上“装好行囊 → 伙伴连续自主出游 → 归家自动入库 → 上线集中查看收获”。代码已实现，待用户自测；遵守用户要求，本轮没有运行自动测试、格式检查、构建或 Studio 验收。

规则承接 [伙伴白模与归家循环](07_伙伴白模与归家循环_实现验收.md)。该文档中的“离线只补一趟”和“只保存最近收获”是上一阶段状态，当前以本文件为准。

## 玩家流程

1. 在补给商店购买补给，再到自己的准备桌装入行囊，最多三份。仓库补给不会自动装入行囊。
2. 未暂缓、船可用、有行囊补给和空箱位时，伙伴自行准备与出发；每趟消耗一份行囊补给并预约一格箱位。
3. 在线或离线都按保存的时间推进。归家时封箱、特产和明信片自动入库，随后休息；条件满足便准备下一趟。
4. 上线后通过“查看汇总”集中查看未读收获，也能从“查看旅行记录”再次查看最近记录。查看只标已读，不发奖、不影响伙伴休息或下趟出发。

三份行囊支持连续三趟的前提是时间足够、箱位足够、未暂缓且船可用。Lv1 住宅最多三只未开封箱，Lv2 最多六只；出发前已有封箱会占用容量。

## 时间推进与等待条件

服务器从上次保存的推进时刻开始，依次处理准备完成、出发、归家、靠岸、休息结束和设施施工完成。每次历史补算最多完成三趟；达到上限后，剩余准备从当前时刻开始，后续刷新不会继续补发同一段旧时间的收获。

新航次保存实际 `StartAt/EndAt`。休息从实际归家时间计算，归航表现按原有靠岸时间处理；离线不会等玩家上线后再重放每趟动画，也不会从上线时刻重置已经结束的休息。登录时已经完成的住宅或船只升级，只在它真实的施工截止时刻之后生效，不追溯改变更早的旅行条件。

| 条件 | 伙伴行为 |
|---|---|
| 行囊补给耗尽 | 等待玩家装载；仓库有补给也不会自行取用 |
| 未开封箱占满箱区 | 等待玩家腾出箱位；不会自行开箱、出售或上架 |
| 玩家暂缓出发 | 保留暂缓状态，等待主动恢复；已经出发的航次仍正常归家 |
| 船只施工中 | 等待实际完工时刻，完工后重新检查条件 |
| 归航靠岸或休息尚未结束 | 等到对应截止时刻，再检查下一趟条件 |

准备期间条件不满足时，不继续倒数一个失效的出发时间；恢复条件后重新准备。未读收获不属于等待条件。

## 未读汇总与最近记录

这两部分独立保存，不能用最近记录的长度代替未读总数。

| 数据 | 保存与展示方式 |
|---|---|
| 最近旅行记录 | 保留最近十趟，界面按最新在前显示；包括海域、航程、封箱、特产、明信片和查看状态。新记录保存实际出发与归家时刻 |
| 全部未读汇总 | 累计未查看趟数、带回封箱数，以及各特产与明信片的数量；旧记录被十条上限截去后，未读累计仍保留 |
| 查看状态 | 一次查看将当时这批未读记录标为已读并清空对应汇总，历史记录继续保留 |

汇总中的“带回封箱数”是这批旅行的收获数量，不等于当前未开封箱库存。玩家开箱后，旅行记录仍保留，封箱状态显示为已处理；开箱商品和木材继续按原有开箱逻辑进入背包。

查看面板保存打开时的批次快照，服务端确认已读后仍保留正在阅读的内容。标记请求受最新 `JourneyId` 和账号版本限制：通知出现、打开面板与已读回执之间若又有伙伴归家，旧请求不能把新一批收获一并误标；关闭后可再查看新的汇总。

记录只包含已经公开的旅行收获信息。封箱内物品、品质与实际价值仍沿用当前保密规则；本阶段没有接入封箱品质展示。

## 存档与实现边界

业务数据升级为 v5，继续使用原有存档名称、Storage 后端与账号模块。`ReturnHistory` 保存最近记录，`UnreadReturnSummary` 保存全部未读累计；推进时间、旅行顺序和已读位置单独持久化。

旧档只迁移它已经保存的 `LatestReturn`，有已读标记便保留已读，未读则生成一趟未读汇总；没有记录便保持空历史。不会根据旧封箱、图鉴或物品库存虚构更早的旅行，也不会通过迁移重新发奖。旧档从可确认的准备、在途、休息或施工截止点恢复时间轴；没有已保存依据的在家等待时间从本次加载开始。已有航次仍按保存的截止时间处理，已有准备按保存的 `Plan.ReadyAt` 恢复，不用计划创建时间猜测离线准备进度。

归家入库与结算标识在同一账号事务中修改，已经结算的航次不会因重进、重复刷新或查看而再发奖。客户端只显示和请求；旅行推进、扣补给、容量检查与奖励仍由服务端负责。Framework 没有加入旅行历史或汇总业务。

本轮完成代码与文档静态复核，并执行实现所需的普通导表，没有产生新的构建 Place；旧 `build/TravelBuddy-Demo.rbxlx` 和此前验收结果不代表本轮代码已验证。接入最新本地代码后，需停止并重新 Play。

## 用户自测顺序

请使用正常保存的测试账号，不修改存储名称；真实离线保存需要已发布测试 Place 和可用的 DataStore，Studio 模拟数据不能替代真实持久化验收。

1. **三份行囊连跑**：箱区留至少三格，装三份行囊，恢复出游。伙伴准备或航行时退出，等足够覆盖三趟准备、航程与休息后重进。确认至多补完三趟，行囊按实际趟数消耗，封箱、特产和明信片自动入库；收获未查看也能继续正常推进。
2. **时间不足**：只等到一趟完成、第二趟仍准备或航行时重进。确认只结算已到期航次，后续截止时刻继续沿原时间轴；上线不会立即发出未来的奖励。
3. **条件等待**：分别检查无行囊补给、只剩一格箱位、暂缓和船施工。确认伙伴按条件等待；仓库补给不自动扣除。腾出箱位、装载补给、恢复或完工后才重新准备。
4. **汇总与幂等**：归家后记录箱数、特产、卡片和金币，打开“查看汇总”，关闭后再查看，退出重进再查看。确认查看只改变已读状态，资产不增加，历史仍在。
5. **查看期间新归家**：打开上一批收获面板时让下一趟接近归家，检查新归家仍产生未读提示，旧面板内容可继续阅读；关闭后再查看新的汇总。
6. **十条上限**：多轮装载、腾出箱位，累计超过十趟且暂不查看汇总。确认详细记录只保留最近十趟，未读汇总仍包含全部未查看趟数及特产、卡片数量；查看后总数清零，历史不清空。
7. **旧档恢复**：使用已有 v4 存档重进，确认金币、补给、背包、封箱、图鉴和升级保留；已有最近收获最多迁移一条，不凭空新增历史或奖励。

尚未验证：以上实际玩法、真实持久化、多人隔离、手机滚动与触摸、查看请求和归家同时发生的现场表现，以及自动检查与构建。请将用户自测结果另行记录，不能把本文件的“已实现”当作“已验收”。
