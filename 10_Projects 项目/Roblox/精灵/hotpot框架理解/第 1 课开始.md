这节的目标不是一次讲完全部框架，而是先让你看懂这一句背后的“类系统”：

```lua
local c = hotpot.class.new(script, hotpot.files.HotpotScreenBase())
```

**1. Lua 里的 table 是万能容器**
Lua 里没有传统的 `class` 关键字。它主要靠 `table` 表来装数据和方法。

比如：

```lua
local c = {}

c.name = "BagGui"

function c:Show()
    print("show ui")
end
```

这里 `c` 是一个表。它里面有：

```text
c.name
c.Show
```

注意这句：

```lua
function c:Show()
end
```

等价于：

```lua
function c.Show(self)
end
```

所以冒号 `:` 的意思是：自动多传一个 `self`。

比如：

```lua
c:Show()
```

等价于：

```lua
c.Show(c)
```

先记住：冒号就是帮你自动传 `self`。

**2. setmetatable 是给 table 加隐藏规则**
普通 table 访问不存在的字段，会得到 `nil`。

```lua
local child = {}
print(child.Show) -- nil
```

但是我们可以给它加一个“备用查找规则”：

```lua
local parent = {}

function parent:Show()
    print("parent show")
end

local child = {}

setmetatable(child, {
    __index = parent
})

child:Show()
```

运行时发生的是：

```text
1. child 自己没有 Show
2. Lua 发现 child 有 metatable
3. metatable 里有 __index = parent
4. Lua 去 parent 里找 Show
5. 找到了，所以执行 parent.Show
```

这就是 Lua 模拟继承的核心。

对应到你的项目：

```text
BagGui 自己没有 Show
HotpotScreenBase 有 Show
BagGui 继承 HotpotScreenBase
所以 BagGui 对象可以调用 Show
```

**3. __call 是让 table 可以像函数一样调用**
正常 table 不能这样：

```lua
local c = {}
c()
```

会报错，因为 `c` 是表，不是函数。

但如果加 `__call`：

```lua
local c = {}

setmetatable(c, {
    __call = function()
        print("c 被调用了")
    end
})

c()
```

这时 `c()` 就能执行。

所以以后你看到项目里：

```lua
return c()
```

不要理解成 `c` 是普通函数。它其实是：

```text
c 是一个 table
但是它有 __call
所以可以被当成函数调用
```

**4. 看你项目的 Class.lua**
核心在 [Class.lua](D:/SVN/src/ReplicatedStorage/Hotpot/Common/Class.lua:10)：

```lua
function module.new(classScript, baseClassScript)
    local c = {}

    if baseClassScript then
        c.super = require(baseClassScript)
    end

    c.class = classScript.Name

    local meta = {__index = c}

    return setmetatable(c, {
        __index = c.super,
        __call = function(_, ...)
            local obj = setmetatable({}, meta)

            if c.ctor then
                local arg = {...}
                local r, e = xpcall(function()
                    c.ctor(obj, table.unpack(arg))
                end, debug.traceback)

                if not r then
                    warn(e)
                else
                    return obj
                end
            end

            return obj
        end
    })
end
```

我们拆开。

**5. local c = {}**
```lua
local c = {}
```

创建一个空表。

这个 `c` 以后就是“类表”。

比如 `BagGui.lua` 里：

```lua
local c = hotpot.class.new(...)
```

这里返回的 `c` 就代表 `BagGui` 这个类。

**6. c.super = require(baseClassScript)**
```lua
if baseClassScript then
    c.super = require(baseClassScript)
end
```

如果传了父类脚本，就 `require` 它。

比如：

```lua
hotpot.class.new(script, hotpot.files.HotpotScreenBase())
```

第二个参数是 `HotpotScreenBase` 的 `ModuleScript`。

所以这里会做：

```lua
c.super = require(HotpotScreenBase这个ModuleScript)
```

结果就是：

```text
c.super = HotpotScreenBase 类表
```

以后 `BagGui` 想调用父类构造函数，就能写：

```lua
c.super.ctor(self, uiInst)
```

**7. c.class = classScript.Name**
```lua
c.class = classScript.Name
```

如果当前脚本是 `BagGui.lua`，那么：

```lua
script.Name
```

就是：

```text
BagGui
```

所以：

```lua
c.class = "BagGui"
```

这个主要用于记录类名、调试、对象管理。

**8. local meta = {__index = c}**
```lua
local meta = {__index = c}
```

这个 `meta` 是给“对象 obj”用的。

后面创建对象时：

```lua
local obj = setmetatable({}, meta)
```

意思是：

```text
obj 自己没有某个方法时，就去 c 这个类表里找
```

例如：

```lua
obj:SetPotionCapacity(1, 10)
```

实际查找过程是：

```text
1. obj 自己有没有 SetPotionCapacity？没有
2. obj 的 metatable.__index 是 c
3. 去 c 里找 SetPotionCapacity
4. 找到了 BagGui:SetPotionCapacity
5. 执行它
```

所以 `meta = {__index = c}` 是“对象继承类方法”。

**9. return setmetatable(c, {...})**
```lua
return setmetatable(c, {
    __index = c.super,
    __call = function(_, ...)
        ...
    end
})
```

这是给“类表 c”自己加规则。

注意这里有两层：

```text
obj 的 metatable:
__index = c
对象找不到方法，就去类表 c 找

c 的 metatable:
__index = c.super
类表 c 找不到方法，就去父类 c.super 找
```

这就是继承链：

```text
obj -> BagGui 类表 c -> HotpotScreenBase 父类表 -> GameObject -> BaseObject
```

所以当你写：

```lua
bagGui:Show()
```

查找过程是：

```text
1. bagGui 对象自己有没有 Show？没有
2. 去 BagGui 类表 c 找 Show？没有
3. BagGui 类表 c 的 __index 是 c.super
4. 去 HotpotScreenBase 找 Show
5. 找到了，执行
```

这就是为什么 `BagGui.lua` 没写 `Show()`，但 `bag_gui:Show()` 能用。

**10. __call 创建对象**
这一段：

```lua
__call = function(_, ...)
    local obj = setmetatable({}, meta)

    if c.ctor then
        local arg = {...}
        c.ctor(obj, table.unpack(arg))
        return obj
    end

    return obj
end
```

意思是：当你调用 `c()` 时，创建一个对象。

所以：

```lua
function c.new()
    return c()
end
```

等价于：

```text
BagGui.new()
-> 调用 c()
-> 触发 __call
-> 创建 obj
-> 调用 c.ctor(obj)
-> 返回 obj
```

这就是这个项目里的“new 对象”。

**11. c.ctor(obj, ...) 是什么**
如果你写：

```lua
function c:ctor()
end
```

等价于：

```lua
function c.ctor(self)
end
```

所以这里：

```lua
c.ctor(obj, table.unpack(arg))
```

就是手动调用构造函数，并且把 `obj` 当成 `self` 传进去。

所以 `BagGui` 的：

```lua
function c:ctor()
    local uiInst = hotpot:GetPath("ui.BagGui", _G.Resource)
    uiInst = hotpot:CloneInst_Loop(uiInst)
    c.super.ctor(self, uiInst)
end
```

真正执行时，`self` 就是刚创建出来的 `bagGui` 对象。

**12. 今天这一节先记住**
你现在先不用记所有细节，先抓住这条链：

```text
hotpot.class.new(...)
创建类表 c

c.super
保存父类

setmetatable(c, { __index = c.super })
让类可以继承父类方法

c()
触发 __call

__call 里面创建 obj

setmetatable(obj, { __index = c })
让 obj 可以使用 c 里的方法

c.ctor(obj)
初始化这个对象
```

把它翻译成一句人话：

```text
Class.lua 用 table + setmetatable 模拟了“类、对象、构造函数、继承”。
```
