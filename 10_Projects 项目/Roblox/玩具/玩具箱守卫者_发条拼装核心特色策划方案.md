# 玩具箱守卫者：发条拼装核心特色策划方案

版本：Work v1.0  
用途：用于确定本项目的核心特色、系统边界、Demo 范围和后续策划方向  
目标读者：策划负责人、Roblox 独立开发者、美术同伴  

---

## 0. 策划结论

本项目当前最大问题不是题材不好，而是缺少一个玩家一进游戏就能记住的“招牌动作”。

推荐把项目核心特色定为：

> **发条拼装台：打怪捡零件，拼出永远有用的发条玩具。**

玩家不是单纯刷怪升级，也不是单纯抽宠物，而是：

```text
打怪掉零件
↓
选择零件
↓
拧发条小游戏
↓
拼出发条玩具
↓
发条玩具进入玩具箱
↓
玩家决定用途：上阵、装配、升星、合成、收藏、派遣
```

这个特色的关键不是“随机出什么”，而是：

> **所有拼出来的东西都有价值。好的能上阵，普通的能升星，重复的能合成，低品质的也能收藏或派遣。**

这会让玩家形成一个长期心理：

```text
我打怪不是只为了金币。
我是在收集零件，拼出更多玩具。
多一个玩具也不亏，因为它总有用途。
```

## 1. 你现在应该拍板的核心决定

作为策划负责人，不要一开始把所有可能性都打开。先拍板以下决定。

| 决策项 | 推荐决定 | 原因 |
|---|---|---|
| 核心系统名 | 发条拼装台 | 有画面感，符合玩具箱题材 |
| 拼装产物名 | 发条玩具 | 比“宠物”“模块”“装备”更宽 |
| 收藏系统名 | 玩具箱 | 和游戏名、世界观统一 |
| Demo 核心用途 | 上阵、装配、升星、收藏 | 够展示特色，开发量可控 |
| 拼装方式 | 3 个零件槽 + 拧发条小游戏 | 半可控随机，玩家有参与感 |
| 失败处理 | 不失败，不销毁材料 | 低龄玩家友好，避免挫败 |
| 重复处理 | 自动转碎片 | 避免“抽到垃圾”的负面感 |
| 品质表达 | 粗糙、良好、精巧、大师、奇迹 | 更像手工拼装，不像赌博抽卡 |

如果没有特殊原因，以上就是当前版本的默认方案。

## 2. 核心卖点

### 2.1 对外一句话

> **打怪捡零件，亲手拼出能战斗、能装配、能成长的发条玩具。**

### 2.2 更短的宣传句

> **刷怪捡零件，拼出你的发条玩具箱。**

### 2.3 玩家记忆点

玩家玩 3 分钟后，应该能说出：

```text
这个游戏是打怪捡零件，然后拼玩具的。
```

玩家玩 10 分钟后，应该能说出：

```text
玩具不只是跟着打怪，还能装到武器上、升星、收藏。
```

---

## 3. 为什么核心产物必须叫“发条玩具”

不要把拼装结果限定为“宠物”或“武器模块”。

### 3.1 如果只做宠物

问题：

- 屏幕会乱。
- 玩家不可能同时带很多个。
- Roblox 多人同屏时性能压力会变大。
- 重复宠物容易变成垃圾。

### 3.2 如果只做武器模块

问题：

- 视觉记忆弱。
- 玩家看不到自己“拼出了什么”。
- 小孩玩家不容易理解数值插件。
- 玩具题材的可爱感会变弱。

### 3.3 发条玩具的优势

发条玩具是一个“通用资产”。

| 用途 | 玩家理解 | 系统价值 |
|---|---|---|
| 上阵 | 跟着我打怪 | 战斗伙伴 |
| 装配 | 装到武器上 | 技能模块 |
| 部署 | 放到地上帮忙 | 炮台/陷阱 |
| 升星 | 重复变强 | 重复消耗 |
| 合成 | 拼成新玩具 | 进化系统 |
| 收藏 | 放进玩具箱 | 长期收集 |
| 派遣 | 派去工坊干活 | 离线/轻挂机收益 |

Demo 不需要一次做完 7 种用途，但策划定义必须从一开始就这么设计。

## 4. 半可控随机设计

这个系统不能是纯随机，也不能完全固定。

最佳结构是：

```text
零件决定结果倾向
小游戏决定工艺品质
随机词条提供惊喜
Boss 材料提高稀有上限
```

### 4.1 三个零件槽

| 槽位 | 作用 | 示例 |
|---|---|---|
| 核心槽 | 决定玩具类型倾向 | 泡泡核心、磁铁片、发条核心 |
| 身体槽 | 决定外形和基础属性 | 木块身体、铁皮身体、纸箱外壳 |
| 动力槽 | 决定行为倾向 | 小齿轮、弹簧、发条 |

玩家会产生明确判断：

```text
我放泡泡核心，所以更可能出泡泡类玩具。
我放弹簧，所以更可能出速度型玩具。
我放磁铁片，所以更可能出吸取类玩具。
```

### 4.2 拧发条小游戏

小游戏只做一个轻量 timing 操作。

```text
指针旋转
玩家按住或点击拧发条
指针进入绿色区域时松手
根据结果得到 Perfect / Good / Bad
```

结果影响：

| 结果 | 影响 |
|---|---|
| Perfect | 品质更高，可能多一个词条 |
| Good | 正常品质 |
| Bad | 品质较低，但仍然成功 |

重要规则：

> **Bad 也给玩具，不销毁材料。**

失败不应该让玩家空手。这个项目面向小孩和青少年，空手失败会产生强挫败。

## 5. 品质系统

不建议直接叫普通、稀有、史诗、传说。那样太像抽卡。

推荐叫“工艺品质”。

| 品质 | 玩家理解 | 实际影响 |
|---|---|---|
| 粗糙 | 做得一般 | 基础属性低，但升星便宜 |
| 良好 | 正常成品 | 标准属性 |
| 精巧 | 做得不错 | 属性更好 |
| 大师 | 高级成品 | 属性高，可能有额外词条 |
| 奇迹 | 极少见成品 | 属性高，外观特效更明显 |

核心规则：

> **品质影响强度和上限，但不决定有没有用。**

例如：

```text
粗糙磁铁小车虽然战斗弱，但仍然能帮忙吸材料。
粗糙泡泡小兵虽然伤害低，但可以作为泡泡系升星材料。
粗糙积木炮车虽然输出低，但可以派遣去工坊。
```

## 6. “永远有用”的价值设计

这是整个系统最重要的部分。

玩家不能觉得：

```text
又出了垃圾。
```

玩家应该觉得：

```text
这个虽然不是最好的，但也能用来升星、合成、收藏、派遣。
```

### 6.1 每个玩具至少 3 个用途

Demo 阶段每个发条玩具至少具备：

```text
上阵效果
装配效果
收藏/升星价值
```

正式版再扩展：

```text
部署效果
合成用途
派遣用途
区域机关用途
```

### 6.2 重复玩具处理

推荐规则：

```text
重复玩具
↓
自动转为该玩具碎片
↓
碎片用于升星
↓
满星后继续重复
↓
转成通用发条经验或合成材料
```

不要让玩家手动处理大量重复垃圾。

### 6.3 低品质玩具处理

低品质玩具不能直接废弃。

| 低品质用途 | 说明 |
|---|---|
| 升星材料 | 同名玩具碎片可升星 |
| 合成材料 | 作为高级玩具合成消耗 |
| 收藏进度 | 放进玩具箱激活图鉴 |
| 派遣单位 | 派去工坊获得基础材料 |
| 新手过渡 | 前期仍可上阵或装配 |

## 7. Demo 玩具设计

Demo 不建议只做 3 个，太少体现不出拼装系统。

推荐做 6 个基础发条玩具。

| 玩具 | 类型 | 上阵效果 | 装配效果 | 收藏效果 |
|---|---|---|---|---|
| 泡泡小兵 | 泡泡/远程 | 自动发射泡泡弹 | 武器有概率发射泡泡 | 泡泡类伤害 +1% |
| 弹簧球球 | 弹簧/速度 | 冲撞敌人 | 攻击后小幅冲刺 | 弹簧类冷却 -1% |
| 发条机器人 | 机械/近战 | 近战敲击 | 每 5 次攻击触发重击 | 机械类生命 +1% |
| 积木炮车 | 炮台/远程 | 原地射击 | 技能变成短时炮台 | 炮台类伤害 +1% |
| 磁铁小车 | 磁力/辅助 | 吸取附近掉落 | 增加拾取范围 | 材料掉落吸取 +1% |
| 木马骑兵 | 移动/冲锋 | 短距离冲锋 | 普攻后小概率突进 | 移动类玩具速度 +1% |

其中最关键的是：

> **磁铁小车必须保留。**

原因：

它能告诉玩家：

```text
发条玩具不只是打怪伙伴。
它还可以改善刷怪体验。
```

这会让系统立刻比普通宠物游戏更高级。

## 8. Demo 材料设计

Demo 材料不要太多。

推荐 6 种。

| 材料 | 来源 | 倾向 |
|---|---|---|
| 小齿轮 | 积木兵、基础敌人 | 基础品质 |
| 木块身体 | 积木兵 | 基础身体 |
| 弹簧 | 弹簧球敌人 | 速度/冲撞 |
| 泡泡核心 | 新手任务 | 泡泡/控制 |
| 磁铁片 | 磁铁怪或区域宝箱 | 吸取/辅助 |
| 发条核心 | 小 Boss | 机械/高级上限 |

## 9. 推荐前 10 分钟体验

这段非常重要。核心特色必须在前 3 分钟出现。

### 0:00 - 1:00

玩家进入训练区，击败 3 个积木兵。

获得：

```text
小齿轮
木块身体
```

### 1:00 - 3:00

系统引导玩家第一次进入发条拼装台。

第一次拼装由系统半保底：

```text
小齿轮 + 木块身体 + 泡泡核心
= 高概率获得泡泡小兵
```

目的：

让玩家稳定学会“我能拼玩具”。

### 3:00 - 5:00

泡泡小兵自动跟随玩家攻击。

玩家感知：

```text
我拼出来的东西真的能帮我打怪。
```

### 5:00 - 7:00

玩家击败弹簧球敌人，获得弹簧。

系统提示：

```text
不同零件会影响拼装结果。
```

### 7:00 - 8:30

玩家第二次拼装。

可能获得：

```text
弹簧球球
木马骑兵
磁铁小车
```

### 8:30 - 10:00

解锁装配功能。

玩家可以选择：

```text
泡泡小兵上阵
弹簧球球装配到武器
```

玩家此时应该理解：

```text
发条玩具不是单一宠物。
它可以上阵，也可以装配。
```

## 10. Demo 最小功能范围

1 个月 Demo 不要做太大。

### 必做

| 功能 | 说明 |
|---|---|
| 发条拼装台 | 3 槽材料 + 拧发条小游戏 |
| 发条玩具箱 | 查看已获得玩具 |
| 上阵 | 选择 1 个玩具跟随战斗 |
| 装配 | 选择 1 个玩具装到武器 |
| 升星 | 重复玩具转碎片并升星 |
| 收藏加成 | 获得玩具后解锁微小图鉴加成 |
| 6 个发条玩具 | 展示不同用途 |
| 6 种材料 | 支撑半可控拼装 |

### 暂不做

| 功能 | 暂不做原因 |
|---|---|
| 派遣 | 需要额外收益系统，后续版本再做 |
| 复杂合成树 | 会拖慢 Demo |
| 多个上阵玩具 | 容易屏幕乱和性能压力 |
| 交易系统 | 风险高，1 个月不适合 |
| 高级词条洗练 | 太像重度数值游戏 |
| 付费抽取 | 早期不要碰，容易破坏口碑 |

## 11. UI 流程建议

### 11.1 发条拼装台 UI

核心信息：

```text
核心槽
身体槽
动力槽
预测倾向
拧发条按钮
品质结果
获得玩具展示
```

玩家选材料时，要显示倾向：

```text
泡泡类概率提高
速度类概率提高
磁力类概率提高
```

不要显示过于复杂的精确概率。Demo 阶段可以用文字描述。

### 11.2 玩具箱 UI

核心标签：

```text
全部
上阵
装配
可升星
收藏
```

每个玩具卡显示：

```text
名字
品质
星级
类型标签
上阵效果
装配效果
碎片进度
```

### 11.3 结果展示 UI

拼装完成后必须有仪式感。

展示顺序：

```text
拧发条完成
光效爆开
玩具模型出现
显示名字
显示品质
显示用途按钮：上阵 / 装配 / 放入玩具箱
```

## 12. 系统规则建议

### 12.1 拼装结果计算

建议简单规则：

```text
基础玩具池 = 当前区域可获得玩具
核心槽增加类型权重
身体槽增加基础外形权重
动力槽增加行为权重
拧发条结果决定品质修正
Boss 材料提升高品质上限
```

### 12.2 品质不影响用途

无论什么品质，都能：

```text
放入玩具箱
参与升星
作为合成材料
提供收藏进度
```

品质只影响：

```text
基础数值
词条数量
外观光效
成长上限
```

### 12.3 每日或长期目标

后续可以扩展：

```text
今日拼装 3 次
收集 3 个泡泡类玩具
用磁力类玩具吸取 100 个掉落物
把任意发条玩具升到 2 星
```

这能让拼装系统成为每日循环的一部分。

## 13. 风险控制

### 13.1 不要做成纯抽卡

避免：

```text
付费抽取
强概率刺激
失败吞材料
只追求稀有度
低品质完全没用
```

应该强调：

```text
我是拼出来的。
我选的材料影响结果。
我操作小游戏影响品质。
每个玩具都有用途。
```

### 13.2 不要一开始做太多上阵单位

Demo 只允许：

```text
1 个上阵玩具
1 个装配玩具
```

后续最多再扩展到：

```text
2 个上阵玩具
```

不要变成满屏跟随物。

### 13.3 不要让配方太复杂

Demo 阶段不做复杂公式。

玩家只需要知道：

```text
材料会影响方向。
拧发条会影响品质。
重复会变碎片。
```

我建议你现在按以下方案继续推进：

```text
核心特色：发条拼装台
核心产物：发条玩具
核心循环：打怪 -> 掉零件 -> 拼装 -> 玩具箱 -> 上阵/装配/升星/收藏
Demo 玩具数：6 个
Demo 材料数：6 个
Demo 上阵数量：1 个
Demo 装配数量：1 个
Demo 品质：粗糙、良好、精巧、大师、奇迹
Demo 重复处理：自动转碎片
Demo 失败处理：不失败，不销毁材料
```

这个方案的强点是：

```text
有记忆点
有可玩操作
有半可控随机
有长期收集
重复不亏
低品质不废
1 个月 Demo 可实现
```

## 16. 给策划新手的判断标准

你以后判断一个功能该不该做，可以用这 5 个问题。

| 问题 | 如果答案是否，就先别做 |
|---|---|
| 玩家 3 分钟内能不能理解？ | 理解不了就太复杂 |
| 这个功能能不能强化“拼玩具”特色？ | 不能强化就可能跑题 |
| 失败或重复时玩家会不会觉得亏？ | 会亏就要补出口 |
| 能不能在 1 个月 Demo 里做出可玩闭环？ | 做不完就砍 |
| 美术能不能用少量资源表达出来？ | 表达不出就降级 |

当前阶段，你不需要像老策划一样一次想完整商业化系统。

你只需要先守住一句话：

> **这个游戏的核心乐趣，是打怪捡零件，拼出永远有用的发条玩具。**
