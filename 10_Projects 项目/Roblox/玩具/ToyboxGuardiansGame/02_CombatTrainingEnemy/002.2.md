我认为你是对的。`002.1_CombatTrainingEnemyQualityPass` 这个名字太像“打包修一下”，边界会再次变糊。正确做法应该沿用你贴的这个标准：继续拆成小闭环，每个闭环都有前置、目标、接口、默认规则、验收、不做内容。

我建议不用一个大 `QualityPass` 直接实现，而是这样拆：

```
002.1A EnemyHealthPresentation
002.1B LootDropModelAndLanding
002.1C ModularPickupMotion
002.1D RewardFeedbackBridge
```

**002.1A EnemyHealthPresentation / 训练怪血条表现**

目标：

- 把头顶 `20 / 20` 升级成世界血条。
- 有血量填充条、数字、死亡状态。
- 后续普通怪、精英怪、Boss 可以复用同一套血条结构。

不做：

- 玩家 HUD 血条。
- Boss 专属大血条。
- 正式 UI 皮肤。

验收：

- 攻击后血条填充从满格变半格再变空。
- 数字同步 `20 -> 10 -> 0`。
- 死亡时显示明确状态，比如灰掉、空血条、Dead。
- 不依赖 Server Output 才能判断是否生效。

**002.1B LootDropModelAndLanding / 掉落物模型与落地**

目标：

- SmallGear 掉落物变成可识别模型。
- 掉落物生成后有落地过程。
- 落地前不可拾取，落地后才进入可拾取状态。

不做：

- 多种材料掉落。
- 稀有品质光效。
- 磁铁扩大拾取范围。

验收：

- 击败 M001 后，玩家能看出掉的是小齿轮。
- 掉落物不是抽象球，不是纯 SurfaceGui。
- 掉落物有出现、落地、停留三个状态。
- 其他玩家仍然看不到私有掉落。

**002.1C ModularPickupMotion / 模块化拾取吸走**

目标：

- 做吸走，但只做“表现模块”。
- 当前 SmallGear 拾取复用它。
- 后续磁铁玩家、磁铁玩具可以直接调用同一套运动逻辑。

边界：

- Server 决定是否拾取。
- Client 播放吸走动画。
- Client 不决定奖励、不决定拾取成功。

验收：

- SmallGear 拾取时飞向玩家。
- 吸走速度、目标、曲线由配置控制。
- 未来可以把目标从玩家改成磁铁点，而不是重写掉落系统。

**002.1D RewardFeedbackBridge / 奖励临时反馈**

目标：

- 正式 HUD 前，也让玩家看到获得了什么。
- 显示 `+1 SmallGear` 和 `+4 Exp`。
- 只是临时反馈桥，不替代 `003_PlayerHUD`。

不做：

- 等级条。
- 资源栏。
- 玩家属性面板。
- 完整 Toast 系统。

验收：

- 拾取后玩家能看到 `+1 SmallGear`。
- 击败或拾取链路中能看到 `+4 Exp`。
- 反馈来自 Server payload，不由 Client 自己猜。

所以我的修正意见是：`002.1` 应该是父级补充计划，不应该直接作为实现卡。真正实现卡应该继续拆成 `002.1A / 002.1B / 002.1C / 002.1D`。这样边界清楚，也能逐个验收，不会再把“能跑”和“能玩”混成一个结论。
