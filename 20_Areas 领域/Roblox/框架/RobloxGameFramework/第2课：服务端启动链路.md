这节只掌握一件事：

```
Roblox 服务端启动后，框架如何把所有 Service 按顺序启动起来？
```

核心链路是：

```
Main.server.lua
-> ServiceRegistry.new()
-> registry:Init()
-> registry:Start()
-> ServiceList 里的每个 Service
```

**1. 服务端入口**

入口文件：

[Main.server.lua (line 1)](D:/AI/Codex/ToyBox/RobloxGameFramework/src/ServerScriptService/Server/Main.server.lua:1)

核心只有三步：

```
local registry = ServiceRegistry.new()
registry:Init()
registry:Start()
```

这就是框架规则里说的：

```
Main.server.lua 只启动 ServiceRegistry。
```

它不直接启动 `DataService`、`NetService`、战斗系统、奖励系统。  
这样好处是入口非常干净，以后排查启动问题时，第一眼就知道：

```
所有服务端模块都必须从 ServiceRegistry 进去。
```

**2. ServiceList 是启动名单**

文件：

[ServiceList.lua (line 7)](D:/AI/Codex/ToyBox/RobloxGameFramework/src/ServerScriptService/Server/Framework/Runtime/ServiceList.lua:7)

它返回一个数组 table：

```
return {
	require(FrameworkServices.DataService),
	require(FrameworkServices.NetService),
	require(FrameworkServices.PlayerSessionService),
	...
}
```

这个顺序是有意义的。

因为 `ServiceRegistry` 后面用的是：

```
for _, service in ipairs(self._services) do
```

`ipairs` 会按数组顺序从上到下遍历。

所以现在服务端启动顺序就是：

```
DataService
NetService
PlayerSessionService
PermissionService
DevCommandService
MonetizationService
FeatureService
ExampleGameService
StartupSmokeTestService
```

你之前问过 `return {}` 顺序问题，这里就是实际例子：

```
ServiceList 里的 return {} 本身不会“自动启动”服务。
但 ServiceRegistry 用 ipairs 读取它时，会按自上而下顺序处理。
```

**3. require 做了什么**

比如这一行：

```
require(FrameworkServices.DataService)
```

意思是：

```
读取 DataService.lua
执行这个 ModuleScript
拿到它 return 出来的 table
```

`DataService.lua` 最后是：

```
return DataService
```

所以 `ServiceList` 拿到的是：

```
DataService 这个服务表
```

不是文件名，也不是字符串。

**4. Init 第一阶段：注册和准备引用**

文件：

[ServiceRegistry.lua (line 55)](D:/AI/Codex/ToyBox/RobloxGameFramework/src/ServerScriptService/Server/Framework/Runtime/ServiceRegistry.lua:55)

`Init()` 做两轮事情。

第一轮：检查并登记所有 Service。

```
Lifecycle.AssertModule(service, "Service")
self._servicesByName[service.Name] = service
```

意思是：

```
检查这个模块是不是合格 Service。
然后按 Name 放进字典。
```

例如：

```
self._servicesByName["DataService"] = DataService
self._servicesByName["NetService"] = NetService
```

第二轮：调用每个 Service 自己的 `Init(context)`。

```
service:Init(self._context)
```

`context` 里面现在有：

```
{
	Logger = Logger,
	Services = self._servicesByName,
}
```

所以 Service 在 `Init` 阶段可以拿到：

```
统一 Logger
其他 Service 字典
```

**5. Start 第二阶段：真正开始运行**

文件：

[ServiceRegistry.lua (line 89)](D:/AI/Codex/ToyBox/RobloxGameFramework/src/ServerScriptService/Server/Framework/Runtime/ServiceRegistry.lua:89)

`Start()` 做的是：

```
for _, service in ipairs(self._services) do
	if service.Start ~= nil then
		service:Start()
	end
end
```

这时才真正连接 Roblox 事件、启动运行逻辑。

比如 `DataService:Start()` 会连接：

```
Players.PlayerAdded
Players.PlayerRemoving
```

所以你可以这样理解：

```
Init = 先认识大家，准备引用
Start = 正式开始工作
```

**6. Lifecycle 是质检员**

文件：

[Lifecycle.lua (line 5)](D:/AI/Codex/ToyBox/RobloxGameFramework/src/ReplicatedStorage/Framework/Shared/App/Lifecycle.lua:5)

它检查每个 Service：

```
必须 return table
必须有 Name
如果有 Init，Init 必须是 function
如果有 Start，Start 必须是 function
```

这能防止低级错误，比如：

```
local BadService = {}
return BadService
```

但忘了写：

```
BadService.Name = "BadService"
```

框架会直接报错，而不是运行到一半才出问题。

**7. 这一课最重要的脑图**

```
Main.server.lua
  |
  v
ServiceRegistry.new()
  |
  v
读取 ServiceList
  |
  v
Init()
  |
  |-- 检查每个 Service 是否合格
  |-- 按 Name 放进 _servicesByName
  |-- 调用每个 service:Init(context)
  |
  v
Start()
  |
  |-- 按 ServiceList 顺序调用每个 service:Start()
  |
  v
服务端框架启动完成
```

**8. 你现在要记住的判断标准**

以后新增一个服务端功能，比如 `FirstLoopService`，它不能直接写到 `Main.server.lua`。

正确路线是：

```
创建 FirstLoopService.lua
-> return 一个带 Name / Init / Start 的 table
-> 加进 ServiceList.lua
-> 由 ServiceRegistry 统一启动
```

这就是框架的服务端接入方式。

下一课建议讲客户端对应链路：

```
Main.client.lua
-> ControllerRegistry
-> ControllerList
```

它和服务端非常像，但职责不同：客户端 Controller 只负责输入、UI、VFX、音频表现。
