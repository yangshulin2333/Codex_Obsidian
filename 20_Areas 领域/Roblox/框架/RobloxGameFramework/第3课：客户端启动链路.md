
这一课对应服务端第二课，只是把 `Service` 换成 `Controller`。

核心链路：

```
Main.client.lua
-> ControllerRegistry.new()
-> registry:Init()
-> registry:Start()
-> ControllerList 里的每个 Controller
```

**1. 客户端入口**

入口文件：

[Main.client.lua (line 1)](D:/AI/Codex/ToyBox/RobloxGameFramework/src/StarterPlayer/StarterPlayerScripts/Client/Main.client.lua:1)

核心代码：

```
local registry = ControllerRegistry.new()
registry:Init()
registry:Start()
```

它和服务端 `Main.server.lua` 很像。区别是：

```
Main.server.lua 启动服务端 Service
Main.client.lua 启动客户端 Controller
```

客户端 Controller 运行在玩家电脑上，所以只能负责：

```
输入
UI
镜头
音效
VFX
向 Server 发请求
```

不能负责：

```
发奖励
改存档
决定伤害
决定掉落
决定货币变化
```

**2. ControllerList 是客户端启动名单**

文件：

[ControllerList.lua (line 7)](D:/AI/Codex/ToyBox/RobloxGameFramework/src/StarterPlayer/StarterPlayerScripts/Client/Framework/Runtime/ControllerList.lua:7)

当前顺序是：

```

```

和 `ServiceList` 一样，这里的 `return {}` 本身只是返回一个数组。  
真正按顺序执行的是 `ControllerRegistry` 里的：

```
for _, controller in ipairs(self._controllers) do
```

所以客户端 Controller 也是自上而下启动。

**3. ControllerRegistry 做什么**

文件：

[ControllerRegistry.lua (line 12)](D:/AI/Codex/ToyBox/RobloxGameFramework/src/StarterPlayer/StarterPlayerScripts/Client/Framework/Runtime/ControllerRegistry.lua:12)

它和 `ServiceRegistry` 结构几乎一样：

```
创建实例
保存 ControllerList
创建 _controllersByName 字典
准备 context
Init 阶段登记所有 Controller
Start 阶段启动所有 Controller
```

`context` 这里比服务端多了一个重点：

```
self._context = {
	Logger = Logger,
	Net = NetClient,
	Controllers = self._controllersByName,
}
```

也就是说，每个 Controller 的 `Init(context)` 可以拿到：

```
Logger        打日志
Net           调用服务端 Remote
Controllers   访问其他 Controller
```

**4. Init 阶段**

对应：

[ControllerRegistry.lua (line 30)](D:/AI/Codex/ToyBox/RobloxGameFramework/src/StarterPlayer/StarterPlayerScripts/Client/Framework/Runtime/ControllerRegistry.lua:30)

它做两件事：

```
先检查每个 Controller 是否合格
再调用每个 controller:Init(context)
```

合格标准和 Service 一样：

```
必须 return table
必须有 Name
Init 如果存在，必须是 function
Start 如果存在，必须是 function
```

**5. Start 阶段**

对应：

[ControllerRegistry.lua (line 55)](D:/AI/Codex/ToyBox/RobloxGameFramework/src/StarterPlayer/StarterPlayerScripts/Client/Framework/Runtime/ControllerRegistry.lua:55)

它会按 `ControllerList` 顺序调用：

```
controller:Start()
```

这时才真正开始连接 UI、输入、表现逻辑。

你可以这样记：

```
Init = 准备引用
Start = 开始干活
```

**7. 第三课脑图**

```
玩家进入游戏
  |
  v
StarterPlayerScripts/Client/Main.client.lua
  |
  v
ControllerRegistry.new()
  |
  v
读取 ControllerList
  |
  v
Init()
  |-- 检查 Controller
  |-- 按 Name 放进 _controllersByName
  |-- 调用 controller:Init(context)
  |
  v
Start()
  |-- 按顺序调用 controller:Start()
  |
  v
客户端启动完成
```

**8. 以后做 Toybox 时怎么用**

比如 `001_FirstLoop` 要做一个按钮：

```
FirstLoopController
```

它应该做：

```
找到 FirstLoopDebugGui
绑定 GrantSmallGearButton
点击时通过 context.Net 请求 FirstLoop.GrantSmallGear
拿到 Server 返回后刷新 UI
```

它不应该做：

```
自己增加 SmallGear
自己决定奖励成功
自己改玩家数据
```

下一课建议讲：

```
NetService / NetClient / NetResult
```

这就是 Client 和 Server 如何安全通信，也是 `001_FirstLoop` 真正要用到的核心。
