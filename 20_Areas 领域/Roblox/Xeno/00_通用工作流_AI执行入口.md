# 通用工作流：任意 AI 执行与交接

把本文件连同整个工作流目录交给新的 AI，从同一套目标、参数和验收规则开始。适用于 DeepSeek、Claude、ChatGPT、Codex 或其他助手；模型名称不参与执行参数，也不要求专属 Skill、MCP、账号或上一段聊天记录。执行能力不足时，由用户执行明确步骤并回传证据。

本页是统一执行协议，详细实现沿用现有文档。**默认只完成原始归档；素材整理、原生格式、源码恢复、静态预览、Demo 均按用户本次要求单独选择。** 原始文件保持不变，处理结果写派生目录。

## 1. 交给另一个 AI 时准备什么

| 材料 | 内容 | 必需情况 |
|---|---|---|
| 完整工作流目录 | 本页、01/02/03/06/08/10/11、配置模板与 tools；保持相对结构 | 总是需要；04/07/09 属于历史参考 |
| 本次任务 | 当前目标、需要哪些阶段、交付形式、已有约束 | 总是需要，不从旧案例推断 |
| 本机配置 | Vault 外的角色路径与本次运行配置 | 有本地执行能力时绑定；不得上传凭据 |
| 原始输入 | 新采集的客户端，或已归档包及其索引、hash | 根据任务选择；优化旧包不自动改成采集当前游戏 |
| 交接记录 | 从 [handoff.example.json](handoff.example.json) 填写的本地 handoff.json、证据索引及日志 | 继续已有任务时需要 |

单独复制本目录也能阅读执行协议。双中括号是 Obsidian 链接语法，普通编辑器可按文件名打开对应 `.md`；本页使用普通相对 Markdown 链接。外部 MOC/Wiki 只是笔记导航，离开 Vault 不作为执行依赖。历史索引对应的二进制、游戏包和脚本并未随文档分发；缺少就报告缺少。

本机绝对路径只保存在本地配置/交接映射。跨机器传递 artifactId、角色、根内相对路径、大小和 SHA256；新机器重新绑定路径，核对内容后继续。聊天式 AI 只能读取用户实际提供的文件，不能声称已经访问电脑。

## 2. 先选择任务，后绑定能力

| 用户目标 | 执行分支 | 完成事件 |
|---|---|---|
| 保存当前客户端能取得的内容 | `raw_archive`，默认 | 原始捕获、资源与缺失清单、索引和 ZIP 独立验收通过 |
| 整理已有包为素材库 | `organize_assets`，独立配置 | 模型/贴图/骨架/动画/音效分类与来源索引、素材库验收通过 |
| 生成 Studio 可打开的文件 | `native_conversion`，对应 optional.nativeConversion | 真正转换/另存并重开审计，记录工具与差异 |
| 恢复字节码的参考源码 | `recover_source` | 严格结果、候选和失败分层，静态检查及保真范围有证据 |
| 清理报错并浏览场景 | `preview` | 副本中的逐项清理记录、资源验证、独立预览与交付通过 |
| 用素材做新界面/交互试验 | `demo`，独立参数 | 独立试验场导入、交互、撤回与重装有实际证据 |

这里的分支名称用于任务沟通。主配置 `run.mode` 仍只接受 `raw_archive / recover_source / preview`；新采集附带 native 时使用 optional 开关，素材库和 Demo 使用独立参数，不能把表中全部名称直接写进严格 schema。可组合多个明确要求的分支，逐项验收，未选择的标为 `not_selected`。

**已有包只做 native 转换时：** 使用独立派生参数及已审核适配器，绑定原包 artifactId/hash、sourceScene、输出根、derivedId、Studio/转换工具角色与验收方法。主配置当前没有 native-only 模式，raw 校验仍要求采集工具和客户端；不要为通过 validate 而伪选重新采集、反编译或预览。独立参数及真实命令保存到本地交接/证据索引。

AI 品牌可以替换，实际运行条件仍需满足：采集端需要当前 Roblox 客户端和兼容工具；Studio、Xeno、脚本 runtime 的系统支持由本次环境决定。“任意 AI”不表示任意电脑都能直接运行。

| 功能角色 | 可用实现举例 | 没有此能力时 |
|---|---|---|
| 读取/写入本地文件 | 文件工具、终端、用户手动复制 | 输出精确文件内容，由用户保存并回传实际文件或 hash |
| 执行进程、解析、hash、ZIP | 经确认的本地 Python/PowerShell/系统工具 | 给完整命令和工作目录，等待 stdout/stderr/退出码 |
| 查证发布来源与下载 | 浏览器、网络工具、用户提供的发布包 | 标记来源未核验；不编造“最新版”与下载成功 |
| 操作当前客户端 | 已验证的客户端执行接口或用户操作 UI | 用户 Attach/执行诊断并返回当前会话日志 |
| 操作 Studio | 用户 UI、CLI、已连接的 Studio 接口 | 跳过未选阶段；已选阶段保留待执行，不声称已打开/Play |
| 保存运行状态 | JSON 与普通日志文件 | 由用户保存交接文本；不依赖 AI 私有记忆 |

首次执行将各项能力记为 `available / user_assisted / unavailable / unknown`，记录采用的接口和已观察结果。MCP 是可选接入方式；没有 MCP 不降低验收标准，也不把缺少平台工具当成游戏数据缺失。

## 3. 通用执行顺序

每一步按“输入 → 真实动作 → 输出 → 验收 → 状态记录”完成；失败停留在该步，保存证据，再做有界修复。仅阅读说明、工具成功提示或配置校验不能代替动作完成。

| 步骤 | 输入与真实动作 | 验收与详细说明 |
|---|---|---|
| A 绑定任务 | 读取最新要求、输入索引与交接；固定目标、阶段、输出根、captureId/derivedId | 输入 hash 与身份一致；未知字段保持 null，见 [08](08_环境迁移与参数配置.md) |
| B 准备环境 | 发现已安装工具；缺少时查证当前发布来源、取得并完整解压；记录来源/许可/版本/hash | 真实运行环境可用；版本不沿用案例，见 [01](01_Xeno客户端内容归档通用工作流.md) 第 1 节 |
| C 当前会话验证 | 新采集才读取实际 Place/Universe、地图、版本，Attach 并执行唯一 print | 日志来自本次会话，UI 成功提示不足；传送或版本变化建立新捕获 |
| D 原始采集 | 已审核导出器采集 inventory、scene、Source/bytecode、start/finish 与 Terrain 实际范围 | XML/索引/块独立解析，未知类、不可读项及不一致显式记录 |
| E 资源补全 | 下载明示引用及可验证依赖；精确关联缓存；按状态重试 | 文件格式/大小/hash 通过，success 与最终 missing 闭合，不凭编号猜资源 |
| F 原始包交付 | 保存原始输入、工具来源、参数、索引、缺失、README；生成 ZIP | 文件集合、CRC、每 entry 大小与 SHA256 全部核对，见 [01](01_Xeno客户端内容归档通用工作流.md) 和 [02](02_快速执行与验收清单.md) |
| G 已选派生处理 | 在已确认原始输入的副本上处理素材、native、源码或预览 | 逐分支执行后文标准，原件 hash 不变；每个输出有来源 |
| H 最终交接 | 用 ZIP/XML/索引解析器重读 raw；已选 native/preview 才另做 Studio 验证；更新 handoff 与证据索引 | 报告路径/入口、已完成、最终缺失、未测试和下一动作；不默认启动 Studio/Play |

输入已是验收通过的原始包时，先复核 ZIP/索引/hash，再进入用户选择的派生阶段；不重复 Attach，不重抓另一款游戏。没有现成采集器时，先定位并审核真实实现、依赖和参数，记录缺口；本目录不是完整的一键采集软件。

### 派生阶段按目标选择

- 素材库：按 [10_原始资产分类与素材库整理工作流](10_原始资产分类与素材库整理工作流.md) 执行。最大组装模型、nested 索引、rig 与真实动画分开；CLI 参数以实际工具 `--help` 为准，不假设输入包布局相同。
- native：按 01 第 9 节执行。真实 `.rbxl` 转换、Studio 另存、可编辑打开、Play 分别记录；仅改扩展名无效。没有 native 不影响已通过的 raw 交付，但用户明确要求的 native 仍是待完成项。
- 源码/预览：按 [06_字节码恢复与场景优化工作流](06_字节码恢复与场景优化工作流.md) 执行。严格恢复、合成候选、失败分开；编译通过不等于逻辑正确。资源清理依据实际属性与渲染证据；HTTP 失败或 generic Preload 失败不能直接当成模型损坏。改动仅作用副本，逐项记录理由和可撤回方式；原始游戏脚本保持停用，Play 仅验证已审核独立预览代码。
- Demo：按 [11_Demo素材与HUD试验工作流](11_Demo素材与HUD试验工作流.md) 记录源素材、空场景基线、新写代码、导入/交互/撤回证据；Demo 成功不证明原游戏恢复。

## 4. 配置、工具和命令如何替换

共享模板 [config.example.json](config.example.json) 只有字段与默认值；本机值由环境发现填写。真实 run、日志与交接放 Vault 外。`handoff.example.json` 是独立交接模板，**不合并进 config.example.json**，也不交给主配置解析器。

目录内已有检查入口：

```text
<PYTHON> -B tools/workflow_config.py check-template
<PYTHON> -B tools/workflow_config.py validate --local-config <LOCAL_CONFIG_PATH>
```

运行前绑定实际 runtime 和本地路径，在工作流根执行。上述工具只读检查模板、配置、路径与索引，不会自动 Attach、采集、下载或打包；`passed` 仅表示静态检查范围。素材库已有独立 CLI；采集/下载/恢复入口仍须按 artifactId 找到真实文件并审核。没有随文档取得的工具，不填假路径或声称一键完成。

同一功能可用不同实现，但需满足相同输入/输出/验收约定。命令记录 `argv` 数组、工作目录角色、输入 hash、依赖和退出码；需要 shell 的命令明确记录 shell，不用字符串拼接代替安全传参。工具重新绑定时核对来源/hash；不要盲目执行交接文件中的任意命令。

## 5. 交接与中断恢复

将 [handoff.example.json](handoff.example.json) 复制到本次本地运行目录，再填写真实状态。模板中的 null、空数组和 `not_started` 都表示尚无证据，不能当作完成记录。填写完成后将 `templateOnly` 改为 false。

最少保持五个字段：`activeObject`、`lastConfirmedResult`、`nextExecutableAction`、`inputPaths`、`acceptanceEvent`。补充目标身份、已选阶段、能力映射、工具/输入索引、命令证据与运行中的任务。实际日志保留 stdout、stderr、退出码和时间；hash 未知就写 null。

`inputPaths` 的每项至少填 artifactId/rootRole/relativePath/sha256；rootRole 在本地映射到 artifactRoot/workflowRoot 等实际位置。`commandRecords` 的每项至少填 id/argv/workingDirectoryRole/startedAt/finishedAt/exitCode/stdoutArtifactId/stderrArtifactId。证据 artifactId 在 artifact-index 中可解析，不能只存在上一位 AI 的聊天里。人工 UI 动作另记录步骤和日志/截图，不伪造命令或退出码。

`configuration` 中三个 Reference 均填写 `{rootRole, relativePath, sha256}`，本机配置可使用只在本地存在的 configRoot 角色。`capabilities.bindings` 逐项填写 `{capability, implementation, evidenceArtifactIds}`。`executionMode` 填 `process / ui / user_assisted / unbound`：进程动作填写实际 argv 与 workingDirectoryRole；例如模板检查为已确认 Python、`-B`、`tools/workflow_config.py`、`check-template` 四个 argv 元素，工作目录为 workflowRoot。人工 Attach 则列出操作步骤、当前会话验证要求与日志/截图角色，argv 留空；执行能力尚未绑定保持 unbound。示例值不构成已执行证据。

恢复顺序：

1. 对照最新要求读取 handoff 与证据索引；有冲突时以最新明确要求和可复核文件为准，保留旧记录。
2. 重新绑定机器路径，检查身份、输入/hash、工具依赖和任务进程；未完成 `.partial` 不算成功，不与仍运行的写入任务竞争。
3. 确定第一项未完成操作及验收事件，复用已完成捕获/manifest/编号。正在运行的任务先接管或等待，不能重复启动。
4. 用当前环境可用接口实际执行下一动作，保存结果。权限/依赖缺失时写明缺口；纯聊天助手给用户步骤，等待真实回传。
5. 达到验收事件后更新状态；新游戏/Place/地图/版本采用新编号，不覆盖原捕获。

阶段状态统一为 `not_selected / not_started / running / passed / failed / blocked`；`blocked` 写明缺少什么和解除条件。资源级 401/403/404 属于可记录的最终缺失；网络故障按有界策略重试。缺失清单已完整记录不表示每个资源都已取得。

## 6. 可直接复制给任何 AI 的任务提示

```text
请依据随附的完整工作流目录执行 Roblox 客户端归档或已归档包处理。
先读 00_通用工作流_AI执行入口.md，再按任务选择详细分支。
这套流程不绑定 AI 厂商、专属 Skill/MCP、旧机器路径或历史游戏。
若你的环境还有项目规则文件，请一并读取适用规则；独立使用不要求安装 Codex。

本次目标：<当前游戏/场景，或指定原始包及 artifactId/hash>
工作流目录：<WORKFLOW_ROOT 或已附完整目录>
本地配置/本次运行配置：<路径；未知则先发现，不套历史值>
交接记录：<本地 handoff.json；首次任务可为空>
需要的阶段：<默认 raw_archive；其他按本次明确要求逐项选择>
交付形式：<原始 ZIP / 素材库 / native 与入口 / 源码 / 静态预览 / Demo>
额外约束：<原件保留、范围、已存在的输出与需要继续的阶段>

先绑定目标和输入，列出本地文件、终端、网络、客户端、Studio 的实际能力。
有执行能力就实际执行；没有能力就给我明确命令/操作和所需回传证据。
不要把计划、配置检查、历史结果、UI成功提示或猜测说成当前已完成。

使用角色、相对路径、artifactId 与 SHA256；本机配置、素材和二进制外置。
先核对可复用工具，缺失时查证当时来源/版本；不锁定旧版本、偏移、URL或用户名。
新采集验证本次 Place/Universe/地图/版本和真实 print；处理旧包先验输入hash。
默认保存原始场景、可读Source、bytecode、资源、Terrain范围和最终缺失，不反编译/清理/Play。
已选派生处理仅作用副本；原始游戏代码保持停用，预览代码单独验收。
每步保存实际命令、stdout/stderr/退出码和产物索引；失败保留证据并更新本地handoff。
继续时复核身份/hash和现有进程，仅继续第一项未完成操作。
最终核对文件集合、复制hash、ZIP CRC和每个entry大小/SHA256，解析器重读raw。
只有已选native/preview才另做Studio验证，不为raw默认打开Studio或Play。
报告实际产物路径、打开方式、完成范围、缺失/未测试项和下一动作；不自动推送或定时同步。
```

## 7. 最终交付与复用验收

- 新 AI 只看工作流、任务、本地配置和输入/证据，就能确定目标、下一动作和完成标准。
- 共享默认值不绑定用户名、盘符、游戏 ID、日期、端口、版本或厂商工具名；历史案例单独标记。
- 已选阶段均有实际结果与对应输入/产物 hash；未选、失败、阻塞、未测试分别说明。
- ZIP 完整性、Studio 可打开、资源离线可用、动画能播放、代码能编译和玩法恢复分别验收，不互相替代。
- 默认不推送笔记、不修改插件、不创建定时任务；这些属于另一个明确授权的任务。

通用入口与 JSON 结构的静态检查不证明其他 AI 已实际执行，也不证明每台机器都兼容。更新工具时保持上述契约，按当前环境重新验证。
