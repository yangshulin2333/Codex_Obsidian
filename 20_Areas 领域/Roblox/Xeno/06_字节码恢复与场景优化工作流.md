# 字节码恢复与场景优化工作流

**本页不是默认下载阶段。** 只有用户明确要求“转 Luau 源码/恢复源码”才选择阶段 1 `recover_source`；明确要求静态预览才选择阶段 2 `preview`。配置见 [[08_环境迁移与参数配置]]。原始包保存的证据支持以后重新尝试，不保证任何版本都能恢复。

只需要“模型、贴图、骨骼动画、音效素材库”时，先按 [[10_原始资产分类与素材库整理工作流]] 运行独立 `organize_assets` 分支。按原结构分类/提取模型不要求反编译，且不会隐式开启本页的源码恢复、场景清理或Play。

接在 [[01_Xeno客户端内容归档通用工作流]] 的原始归档验收之后：把已保存的客户端字节码转为可读参考源码，在派生场景中清理实际加载失败的依赖，加入独立预览入口，最后交付原生 `.rbxl` 和经过校验的 ZIP。

这里的“优化”目标是稳定查看已捕获场景和源码。反编译源码是重建结果；编译通过不证明运行等价；预览通过不代表恢复了原游戏玩法。未复制到客户端的服务端逻辑仍无法从这批字节码恢复。

## 阶段 1：字节码恢复为参考源码

### 1. 保留原件，建立派生工作目录

1. 按输入归档 artifactId/hash 确认目标项目、PlaceId、UniverseId、捕获范围和归档日期；输入来自已保存原始包，不从当前正在玩的游戏或历史案例取得。读取原始 `scripts/index.json`，分别统计有字节码、已有 Source、空块、无可恢复输入的记录。
2. 原始 `.rbxl`、`.rbxlx`、脚本索引和字节码保持只读；记录长度及 SHA-256。工作目录、候选场景、最终包使用独立路径，拒绝覆盖唯一原件。
3. 每个输出保留原实例 `referent`、完整路径、索引、输入字节码 SHA-256、输出文件路径和 SHA-256。同内容可以复用计算结果，但不能丢失不同实例的映射。

建议目录：

```text
原归档/                         原始证据保留
优化工作目录/
  decompile/                    工具来源、样本、恢复和验证
  resource-audit/                属性、下载文件和实际失败证据
  preview-controls/             独立预览脚本
  候选场景与处理报告
最终预览包/
  项目_优化预览场景.rbxl
  启动场景.cmd
  local-content/                已验证的配套素材
  local-content-manifest.json
  scripts/readable/             严格恢复结果
  scripts/candidates/           合成控制流候选，独立保存
  scripts/original-bytecode/    原始输入资料
  scripts/unrecovered-listings/  失败记录与反汇编
  scripts/reports/               Source、AST、来源与复制校验
  validation/                   Studio与打包验收
```

### 2. 识别字节码，先验证小样本

- 解析实际字节码格式、版本、原型、主块、常量和操作码编码；未知尾部或字段单独记录。工具声明“支持 Luau”不足以证明兼容本次输入。
- 从官方项目发布页取得本地反编译工具及官方 Luau 解析、编译、AST 工具。保存发布版本、来源、许可、下载包和执行文件 SHA-256；能取得发布资产摘要时逐项核对。
- 先选择不同长度、复杂度和版本的样本，验证工具输出和诊断，再进行全量。原始游戏脚本与生成的游戏脚本都不在这一阶段执行，也不发送到远程反编译服务。
- 恢复工具、编译器、API dump 与操作码编码来自本次原始包的版本/格式证据，参数存入本次配置，不锁定旧工具名或乘数。历史 EvoMon 验证值只保留在“07”和下方历史基线。
- 首轮采用严格控制流重建，未启用假定无 NaN、假定标准库或实验算术循环改写。工具输入的 Base64 包装只是不可执行的输入资料，不是恢复源码。

### 3. 全量恢复，并把质量分层记录

| 检查 | 验收和处理 |
|---|---|
| 输入长度与 SHA-256 | 必须与原索引一致；不一致就停止该记录 |
| 源码解析与重新编译 | 分别记录退出码和诊断；成功结果才进入主要源码目录 |
| AST 与字节码结构 | 对照函数节点数与原型数减主块；数量差异进入人工复核清单，不能用数量一致证明语义一致 |
| 二进制字符串 | 对非 UTF-8 常量保留数字转义等无损表示，并与输出 AST 的实际字符串字节核对 |
| 空编译块 | 明示输入本来为空，不计为找回隐藏逻辑 |
| 严格恢复失败 | 保留原字节码、失败原因与反汇编；合成调度器候选另存，不混入严格结果 |

写回派生场景时再次验证输出源码哈希。Script / LocalScript 默认停用；独立预览入口不 `require` 原 ModuleScript。没有真实 Source 的脚本占位可在派生场景降为 Folder，原索引、字节码和失败证据继续保留。不要把所有脚本同时启用作为“效果验证”。

阶段 1 完成后可只交付参考源码、索引和质量报告，不强制改写场景或生成 Play 入口。以下阶段 2 必须另有明确预览需求才开启。

## 阶段 2：独立静态预览与场景处理

### 4. 按实际属性处理失效资源

先形成“实例路径 → 类 → 属性 → URI → 本地文件 → 状态和证据”的清单。规范化资源键并检查文件类型、大小、哈希、依赖和用途；错误响应、缓存碎片或能解析的文件不自动等于可渲染资源。

优先使用 Studio 正常编辑加载、被动渲染日志和具体属性用途验证。将账号权限拒绝、资源不存在、缺失内置资源、格式不支持、网络暂时失败、引擎派生请求分别记录。只在派生副本中清理已经定位的失败项，不能从一条错误推断同 ID 的所有属性都不可用。

**Generic URI `PreloadAsync` 失败不能作为 Mesh、动画或字体一律不可用的依据。** 历史 EvoMon 案例保留原 Mesh URI 和已有几何，没有按通用探测失败批量替换 MeshPart。动画关键帧 `.rbxm` 能反序列化也不代表它可直接充当可播放的 AnimationId。

| 派生预览的清理对象 | 处理原则 |
|---|---|
| 已确认不可用的图片、音频、视频、特效引用 | 按具体属性清空或删除失效资源实例；保留主体结构，记录原 URI 与原因 |
| 字体与内置默认素材 | 核验所选 Studio 的文件及实际 FontFace 用途；按当前安装可用字体配置 fallback；历史 EvoMon 缺失 Arial 时选 Arimo |
| 本地 PBR 支持缺口 | 确认本机支持缺口时按实际用途降级 SurfaceAppearance / MaterialVariant，清空变体引用和基础材质覆盖，保留父 MeshPart；接受白色或基础材质的外观变化 |
| PackageLink | 解除云包更新链接，保留普通模型本体 |
| 重复 Content 属性别名 | 保留一个有效的可序列化表达，避免重复警告；按类和匹配 API 核对 |
| 删除对象留下的 Ref | 只清空指向明确已删除对象的引用，记录改动 |

权限清理不会赋予素材访问权限。网络暂时失败应先有限重试；无法确认用途或来源的资源保留到待核对清单，不把“报错少了”当作内容完整。

### 5. 打包和部署本地配套素材

1. 为可用文件建立独立命名空间的 `rbxasset://` 映射；字体 JSON 等依赖同步改写，并记录派生文件与原文件哈希关系。
2. 将素材与 manifest 放入最终包。启动器先检查包内长度、SHA-256 和所选 Studio，再部署到该 Studio 版本的专属 `content` 子目录；部署后核对实际文件。
3. 启动器使用包内相对路径与本机 `studioExecutable`，未配置时只在当前用户安装根/已登记自定义根发现候选；候选多于一个先核对实际版本，不固定旧版本目录。`启动场景.cmd -CheckOnly` 只检查，不部署、不打开 Studio。正常启动才安装素材并打开包内 `.rbxl`；不修改执行策略或安全设置。
4. 换电脑或 Studio 更新后重新运行安装入口。只复制 `.rbxl` 不包含配套素材；只有文件能读取仍不足以证明所有属性支持本地 URI。

清单统计以本次实际复制/部署文件与 hash 为准；历史 EvoMon 的 668 个配套文件等数字见“07”。文件在包里不表示全部被场景实际调用，也不表示剩余引用完全离线。

### 6. 构建独立静态预览入口

- 修复与真实服务同名的归档 Folder；例如需为 `Players`、`StarterPlayer` 同名快照重命名，并把错误放在 Folder 下的专用脚本容器降为普通 Folder。
- 停用旧 ScreenGui，固定 Workspace 动态 Parts，避免缺失原逻辑时下落。原捕获人物、NPC、宠物仍作为静态内容保存。
- 按本次预览需求登记独立入口角色、名称和 hash：禁止预览玩家 Avatar 自动加载；提供 Scriptable 自由相机、场景地点切换和操作面板。地点来源于实际保存的场景，坐标需按目标项目重新生成。
- 若没有玩家 Avatar 的静态多岛屿预览实测发生流式卸载，可在派生副本关闭 `StreamingEnabled`，避免已保存区域自动卸载。这个设置是预览用途决策，不是生产游戏的通用性能优化。

### 7. Studio 与最终包验收

1. 生成标准 `.rbxl`，记录实际生成工具并做二进制重开；再用独立验证副本做 Studio 编辑加载和 Play，检查原游戏脚本停用、只运行预览入口、相机、地点切换和 UI。实际转换器、兼容性与版本由本次配置选择并记入 provenance，Studio 负责加载与预览验证；历史生成路径见“07”，不能借旧原始归档的 SaveAs 证明新生成过程。
2. 读取本次编辑与运行日志，记录权限和加载错误；核对动态零件、模型数量、PBR/云链接清理情况与 `StreamingEnabled`。复测失败就回到具体实例和属性，不靠泛化删除消声。
3. 核验素材部署、启动器 CheckOnly、Source 索引路径及哈希；打包排除 `.lock`、缓存、临时文件和中间 XML，分析原件继续留在工作目录。
4. 验证 ZIP CRC、完整文件集合、每项大小与 SHA-256，并保存最终 ZIP 和 `.rbxl` 的 SHA-256。
5. README 明示：源码重建质量、合成候选和失败数量、外观降级、在线/缓存依赖、换机部署方式与测试范围。

## 历史案例基线：EvoMon

来源为 `Roblox_EvoMon客户端补全归档V2_含启动入口_20261009`，PlaceId `134381727982611`、UniverseId `9826885587`。2026-10-10 本机 Studio `0.742.0.7421053` 验证；版本为历史记录。

| 项目 | 已记录结果 |
|---|---|
| 输入 | 2,787 份字节码：2,786 份 v13、1 份 v9，2,522 个独立内容哈希 |
| 严格恢复 | 2,780 份通过解析和重新编译；含 15 份原本为空的块，非空源码 2,765 份 |
| 待复核 | 57 份 AST 函数数不同；2 份合成调度器候选独立保存、未写回场景；5 份仍未恢复 |
| 二进制常量 | 2 个实例、1 个独立字节码中的非 UTF-8 字符串已核对保真 |
| 静态预览 | 固定 3,872 个 Workspace Parts；旧 UI 停用，两个独立预览入口；原游戏代码未运行 |
| Studio 结果 | 编辑加载、Play、地点切换与面板通过；本次测试权限/加载错误为 0 |
| 最终包 | 6,269 个文件，90,375,653 字节；CRC、文件集合、逐项大小与 SHA-256 通过 |

最终 ZIP SHA-256：`396a21ce89b299c13e8f80acd6ceb28ac79e0d1b04bec202d1d5877157ff2235`。原生场景 SHA-256：`1066c844f56db29a36b827b23e31229b205685471248f83b09188326a7aeaac4`。

本次仍有在线或缓存 Mesh URI，PBR 降级后可能出现白色或基础材质。一次无报错预览不能认证每个归档对象、未来账号权限或网络条件，也没有恢复原服务端玩法。下一步应从 57 份结构差异及具体交互依赖继续核对，保持预览与玩法重建分开。
