# 快速执行与验收清单

默认阶段 0：先归档可取得的原始内容，完成验收后停止。路径与角色映射见 [[08_环境迁移与参数配置]]；详细证据规则见 [[01_Xeno客户端内容归档通用工作流]]。不能从案例自动取得游戏 ID、版本、工具路径或脚本名。

## 可复用的 Codex 任务提示

本机配置、run 配置与 artifact-index 均由本地环境发现/本次实际捕获填入；未知 ID 先读当前客户端再确认，不把模板 null 替换为旧案例。

## 阶段 0 验收

1. **环境与本次身份：** 本地配置可解析；当前 Player/Xeno/实际 workspace 已验证；captureId 唯一；目标 Place/Universe/地图与实际一致。空/未知参数不得静默代入历史值。
2. **真实执行与工具：** Attach 握手和唯一 print 出现；实际导出器及依赖已审阅；匹配 API dump、来源、许可证、hash 和有效参数已保留。
3. **原始捕获：** inventory/start/finish/pipeline 一致；XML 独立解析；原始 Source、placeholder、bytecode、error 分开，复制 hash 一致；Terrain 的实际读取范围、未扫描范围与失败清楚。
4. **全部明示资源：** 清单及可验证依赖逐项尝试；success 都有文件/格式/大小/hash；final missing 与历史尝试记录分开，数量闭合；动画/HLS/缓存按实际证据分类。
5. **未来输入与迁移：** artifact-index 使用角色/相对路径/hash；bytecode、API dump、导出器/patch/许可证/版本记录齐全，缺口明确；真实机器路径不进入共享笔记。
6. **正式包：** 无运行中的 partial/lock 混入，raw 不被派生结果覆盖；复制/ZIP 集合/CRC/逐 entry 大小/hash 通过，README 明示已取得/缺失/未覆盖。

## 明确请求后才开启

- **可选 `organize_assets`：** 按 [[10_原始资产分类与素材库整理工作流]] 对已归档输入分类、导出最大不重叠模型包并索引所有nested Model；mesh与组装模型、rig与关键帧动画分开，贴图保留PBR/UI/particle用途，文件按SHA去重。独立素材库配置/输出，原件前后hash一致；不恢复源码，不自动Studio/Play。此阶段使用单独asset-library配置，不改主run.mode。
- **可选 native：** 对 raw 的副本另存原生 `.rbxl`、恢复 Terrain 并重开验证。沿用同一原始 captureId 作为来源，另建 derivedId；实际保存工具/版本与 hash 单独验收。
- **阶段 1 `recover_source`：** 按 [[06_字节码恢复与场景优化工作流]] 记录版本/编码、来源/hash，抽样后批量，严格结果/合成候选/失败分开；官方静态检查、AST 差异与二进制字符串保真有证据。原始游戏逻辑保持停用。
- **阶段 2 `preview`：** 明确请求静态浏览才做资源清理、部署和独立入口；Play 只验证已审核预览脚本，不能等同原玩法恢复。

## 中断与换环境

交接记录绑定 activeObject、lastConfirmedResult、nextExecutableAction、inputPaths 和 acceptanceEvent，保留命令数组、运行身份、hash、阶段状态、任务/lock/partial 与真实失败。继续只启动第一项未完成操作，不覆盖 raw，不把读取说明当执行完成。

下载断线：先核对已完成 manifest/hash，再补未完成增量。传送/地图替换/版本变化：停止旧捕获，以新编号重做身份/真实 print/API匹配。换机：只修改本地环境角色映射，先验 ZIP 与索引再发现工具；历史未通过项仍为未通过。见“08”。
