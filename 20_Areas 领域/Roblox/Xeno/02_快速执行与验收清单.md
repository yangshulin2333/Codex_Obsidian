# 快速执行与验收清单

详细步骤、参考实现和来源见 [[01_Xeno客户端内容归档通用工作流]]；异常判断见 [[03_故障排查与适用边界]]。本页用于下次启动任务和阶段交接，不代替主流程的参数与范围审核。

## 可复用的 Codex 任务提示

先填写尖括号参数；不能确认的楼层留“待核对”。不要只更改游戏名字就沿用历史脚本。

```text
请归档当前 Roblox 客户端可读内容，使用 Xeno 作为采集入口，最终交付有完整性校验的 ZIP。

目标游戏：<GAME_NAME>
预期 PlaceId：<PLACE_ID>
预期 UniverseId：<UNIVERSE_ID>
目标场景/当前楼层：<SCENE_OR_FLOOR>
捕获编号：<CAPTURE_ID>
本机 Xeno workspace：<XENO_WORKSPACE>
原始证据与处理中间目录：<ARCHIVE_ROOT>
最终交付目录：<PACKAGE_ROOT>

先读取本库 AGENTS.md 和“01_Xeno客户端内容归档通用工作流”。核对正在运行的 Player 版本、Xeno 当前来源/版本/hash、当前 PlaceId、GameId 及真实地图/楼层证据。大厅和实战分别核对；每阶段再次检查，传送、地图替换或断线后停止旧捕获，并为新状态建立新编号。

Attach 成功必须有当前客户端的真实诊断 print 输出。历史参考脚本中的游戏 ID、版本、hash、日期、workspace 和输出目录要集中参数化；依赖审核并固定本地，匹配当前 API dump。不直接执行历史固定二进制补丁。不启动原游戏脚本或 Studio Play；采集工具与数据处理脚本先审核再运行。

采集 inventory、原始 scene.rbxlx、start/finish/pipeline 与未知 class 映射。保留原始证据，复制前后核对 SHA256；静态分类可读 Source、占位错误、bytecode 和无法解析 payload，不把 placeholder 或文件出现当成功。资源增量引用要有原始字节/路径/hash 证据，独立 verifier 通过才发布。

仅处理本次明示资源 URI、已取得文件的依赖及可证明缓存关联；正常记录 401/403/404 与本地缺失，不使用凭据或猜测地址绕过。HLS 分别统计 master、variant、segment 和实际可播放结果。动画以实际容器内 KeyframeSequence/Keyframe/Pose 或 CurveAnimation 数据判断。

Terrain 先采元数据和局部探针，必要时在明确范围分块保存 SolidMaterial、SolidOccupancy、LiquidOccupancy；独立检查索引/RLE，缺块保留 raw 并重读修复。只声称有证据的范围，恢复后重开 native 验证。

用 Roblox Studio Edit 模式真正另存 scene.rbxl，保留原始 XML；比较主要地图树、Source/bytecode、关键资源与已知属性别名/缓存差异。提供可在完整解压后使用的 Studio 启动入口和 CheckOnly。多场景保持独立资料与入口。

交付 raw/native、已验证 assets/scripts/terrain、README、最终成功/缺失 manifest、阶段 validation、file-checksums 和 package-verification。排除 partial/lock/临时下载、运行日志、内部缓存及 audit readback。校验复制 hash、ZIP 文件集合、CRC 和每 entry 的大小/SHA256，并报告 ZIP hash。

最终说明实际捕获场景/楼层、打开方法、受限资源、未加载地图、server-only 内容与未测试玩法。EXE、游戏素材和大 ZIP 保留在工作目录，Obsidian 只存小型文档与来源索引。
```

## 七阶段验收

每阶段勾选后再进入下一阶段。失败时保留记录，写明可继续的范围。

### 1. 工具与目标参数

- [ ] 下载包装完整解压；来源、版本、大小、SHA256 已记录，依赖按当前 ReadMe 处理。
- [ ] 当前运行的 Player 版本/hash 可确认；参考代码已审查、参数化，输出目录不覆盖已有捕获。
- [ ] Place/Universe、地图/楼层、时间与 Streaming 状态有实际证据。

### 2. Attach 与离线工具

- [ ] Attach 握手及唯一真实 print 在当前 Roblox 输出出现。
- [ ] 离线依赖/许可证/hash 与匹配 API dump 已准备；远程反编译和隐式加载已审查。

### 3. 原始捕获

- [ ] inventory → XML → Terrain probe 的 pipeline、start/finish、完成标记一致。
- [ ] 所有目标 ID 一致；XML 独立解析通过；复制前后大小/SHA256 一致。
- [ ] Source/placeholder/bytecode/error 分类真实；静态增量证据独立验证通过。

### 4. 素材与 Terrain

- [ ] 每个素材 success 都对应可核验文件；最终缺失和历史尝试分别记录，数量闭合。
- [ ] 模型/动画按实际数据分类；HLS 与缓存只写实际取得的结果。
- [ ] Terrain 零值/局部范围证据保留；非空扫描的索引、维度、RLE、hash 通过独立验证。

### 5. Studio 原生场景

- [ ] Edit 模式真正保存 `.rbxl`，原始 `.rbxlx` 保留，最终 native hash 已记录。
- [ ] 主要地图树、脚本/关键引用比较通过；差异与 decoder 未覆盖项解释清楚。
- [ ] 最终 native 重开可编辑；需要地形恢复时，重开后三通道验证对应此 native。

### 6. 包与入口

- [ ] README 包含捕获范围、打开方法和限制；入口 CheckOnly 通过，多场景来源独立。
- [ ] 仅验收产物入包；partial/lock/临时文件与内部缓存未混入。

### 7. ZIP 与交付

- [ ] 复制后 hash、ZIP 文件集合、CRC、每 entry 大小/SHA256 全通过，ZIP hash 已输出。
- [ ] 交付路径、实际场景/楼层、缺失资源、server-only/未加载内容和未测试玩法表述准确。

## 归档后可选：源码恢复与静态预览优化

使用 [[06_字节码恢复与场景优化工作流]]，案例见 [[07_EvoMon优化预览版案例与验收]]。该分支在独立副本上进行，不把修改后的预览场景替换成唯一原始捕获。

- [ ] 记录 bytecode 版本/编码、工具来源与 hash；抽样后批量，严格结果、合成候选与失败分开。
- [ ] 官方语法/重新编译、AST 结构及二进制字符串保真检查通过；差异与未恢复条目列明。
- [ ] 恢复源码默认停用，独立预览不 require 原游戏模块；服务端缺失不伪造。
- [ ] 按实际属性/正常渲染日志清理；不把 HTTP 拒绝或通用 URI Preload Failure 当成整件模型不可用。
- [ ] 本地素材用途、依赖重映射、专属 content 部署及包内/已部署 SHA 均验收；PBR 降级明确记录。
- [ ] 静态 Parts、旧 GUI、服务快照重名和无效容器已处理；按静态预览需要判断 Streaming/Avatar 设置。
- [ ] 最终 native Edit/Play 与独立入口实际通过，ZIP 全验；可预览、可编译、原玩法可运行分别表述。

## 断线或换场景后的交接记录

记录最后通过阶段、当前 PID/版本、Place/Universe/地图状态、原始文件 hash、运行中任务与 lock/partial、尚未完成项目和下一步验证。网络恢复后先看本地完成记录和 manifest，再确定补哪些增量；不要因断线重新覆盖 raw。

换场景、换版本或客户端重启后，重新做身份与真实 print 验证。跨时间段的合并应保留来源及时间，不能写成单一瞬时快照。
