# 环境迁移与参数配置

把共享工作流、机器环境、本次运行与已归档资源分开存放。换电脑只重新发现工具并改本地角色映射；游戏 ID、捕获时间和脚本入口属于本次 run，不进入共享模板。所有默认值指向阶段 0 原始归档；素材库整理、恢复源码、静态预览均为明确请求后开启的独立阶段。

## 1. 三层配置与解析基准

| 层 | 文件/角色 | 可同步内容 | 路径解析 |
|---|---|---|---|
| 共享工作流 | 本目录、`config.example.json`、`tools/workflow_config.py` | 文档、模板、只读工具、小型历史索引 | 工作流根由检查脚本自身位置确定，无固定盘符/用户名 |
| 机器环境与本次参数 | Vault外的 `config.local.json`；可另用 `run.local.json` | 真实机器文件不进入笔记同步 | `environment.paths` 相对值以workflow根解析，或配置环境变量/本机绝对值 |
| 捕获与派生 | `artifactRoot` 下的capture/derived/package | 素材/二进制/ZIP单独迁移，笔记仅索引 | 包内相对路径、artifactId、角色、大小、SHA256 |

`config.local.json` 可包含完整模板；独立的 `run.local.json` 仅包含 `run` 对象，用来覆盖本次字段，不修改机器环境。解析器拒绝未知顶层/字段、未知角色和未设置的环境变量；不把拼写错误静默回退为默认。`null` 代表待发现，不能直接当成可执行路径。

环境路径可以使用 `${ENV_NAME}`（跨平台）或 `%ENV_NAME%`（Windows）；相对路径以脚本确定的workflow根为基准。外置输出必需填写 `artifactRoot`，不能位于 `vaultRoot` 内。真实配置和本地映射不得复制进共享workflow目录；工具检查会拒绝这个位置。保持工作流原文件名以兼容 Obsidian 链接，不把工具当前安装名绑定为固定脚本名。

## 2. 在新环境发现，而不是复制旧路径

1. 确认当前运行的 Player 进程、可执行文件、版本和日志。当前进程对应文件优先于“最新安装目录”；没有运行时记录就把身份保持未确认。
2. 查找本地已安装 Xeno 目录及实际workspace，核对完整依赖、来源/hash、文件 API 和一份可清理诊断文件的实际写入。不能只因目录叫workspace就认定可用。
3. 从 PATH 或已配置目录发现 Python；本检查脚本仅用标准库。其他实际采集/下载脚本先读取import和依赖清单，再分别检查版本与小样本。用不同runtime时登记角色，不抄Codex安装包内部路径。
4. 只有选择native/预览才发现Studio。先用明确的本机配置；否则检查当前用户环境变量给出的Roblox安装根、已登记自定义安装根和实际Studio进程。发现多个version目录时根据本次引擎兼容与真实版本选择，不能只按目录名或修改时间猜“最新版”。
5. Lune/反编译器/Luau工具只在对应可选阶段发现，记录来源/版本/许可/hash/格式支持。API dump 必须匹配当前实际Player，并保留匹配依据。
6. 历史资源只设 `historicalEvidenceRoot` 映射；使用 [[09_历史案例资源索引]] 的rootRole/relativePath定位，按已知hash重验。缺文件写unresolved，不生成“已迁移”状态。

Windows可用于只读发现的示例，字段来自当前进程/环境，不包含机器默认绝对路径：

```powershell
Get-Process RobloxPlayerBeta,RobloxStudioBeta -ErrorAction SilentlyContinue |
  Select-Object Id,ProcessName,Path
Get-Command python,python3,py -ErrorAction SilentlyContinue |
  Select-Object Name,Source
if ($env:LOCALAPPDATA) {
  $robloxVersionsRoot = Join-Path $env:LOCALAPPDATA 'Roblox/Versions'
  if (Test-Path -LiteralPath $robloxVersionsRoot) {
    Get-ChildItem -LiteralPath $robloxVersionsRoot -Directory |
      Select-Object Name,FullName
  }
}
```

这些发现命令不启动/下载工具、不Attach、不执行采集脚本。找到候选后仍须审核与真实print/小样本验证。

## 3. 建立本地配置并核对

先绑定工作流根和Vault外本地配置目录。可从当前Xeno目录打开终端，`Get-Location` 取得workflow根；共享模板可相对复制到自己的本地目录。`python` 替换为上一步确认的runtime，若用Windows `py`，传 `-3`。所有示例运行前必须把 typed slots 绑定为实际路径/ID。

```powershell
# 在工作流根执行；localConfigDirectory由用户当前环境选择，必须在Vault外。
$workflowRoot = (Get-Location).Path
$localConfigPath = Join-Path $localConfigDirectory 'config.local.json'
New-Item -ItemType Directory -Path $localConfigDirectory -Force | Out-Null
if (Test-Path -LiteralPath $localConfigPath) {
  throw '本地配置已存在；先核对，不覆盖已有环境映射。'
}
Copy-Item -LiteralPath (Join-Path $workflowRoot 'config.example.json') -Destination $localConfigPath

# 只读共享模板校验：不会建立输出目录，也不会启动外部工具。
python ./tools/workflow_config.py check-template

# 填完本机角色与本次run后核对路径/身份/必需输入；只输出JSON。
python ./tools/workflow_config.py validate --local-config $localConfigPath
# 若本次参数另存，显式传入覆盖文件：
python ./tools/workflow_config.py validate --local-config $localConfigPath --run-config $runConfigPath
```

不要在没有校验时覆盖已有本地配置。模板不带真实游戏ID、用户名、日期、安装版本、二进制位置或已确认状态。首次接入游戏先从客户端读Place/Universe，再填本次expected值；之后各采集步骤断言身份一致。检查工具只验证配置/文件/hash，它的 `status=passed` 不代表真实Attach、游戏捕获或下载完成。

## 4. 参数与功能角色

| 文档占位 | 配置字段 | 规则 |
|---|---|---|
| `<WORKFLOW_ROOT>` | 检查脚本自身的上级目录 | 随文件夹迁移自动变化，不写死 |
| `<XENO_WORKSPACE>` | `environment.paths.xenoWorkspace` | 本地发现并验证；与Xeno内部相对writefile路径分开 |
| `<ARCHIVE_ROOT>` | `artifactRoot` + `run.paths.captureRelativeDir` | captureId唯一，拒绝覆盖已有完成捕获 |
| `<PACKAGE_ROOT>` | `artifactRoot` + `run.paths.packageRelativeDir` | 与capture/derived路径分开，不覆盖raw |
| `<STUDIO_EXE>` | `environment.paths.studioExecutable` | 可选阶段才要求实际文件存在 |
| `<GAME_NAME>/<PLACE_ID>/<UNIVERSE_ID>` | `run.identity` | 来源为本次实际客户端/身份核验 |
| `<CAPTURE_ID>/<SCENE_LABEL>/<FLOOR_OR_ROUND>` | `run.identity` | captureId为唯一安全目录段；未知楼层可null，不猜测 |
| `<PLAYER_VERSION>` | `run.versions` | 本次Player/engine/Xeno/API dump实际记录，无旧版本fallback |
| 实际脚本名 | `run.inputs.<功能角色>` | 角色值为artifactId；artifact-index提供rootRole/relativePath/hash |
| 源码/预览输入 | `inputArchiveArtifactId` + `derivedId` | 原始capture的可核验副本，不能改为当前游戏 |

本次 `artifact-index.json` 位于解析后的capture根，结构与 `history-artifacts.json` 的 `artifacts` 一致：每项有 `artifactId`、`role`、`rootRole`、`relativePath`、`knownSha256`/`sha256` 和 `bytes`（有实际文件时）。本次必需输入已审核并登记：exporterOriginal/exporterReviewed/fullApiDump/captureEntrypoint/downloadEntrypoint/verificationEntrypoint；恢复时另登记sourceRecoveryEntrypoint。工具可位于artifactRoot或本次capture根，索引解析不允许 `..` 越界或符号链接逃出所选根。工具来源/许可/版本等详情写provenance，不靠命令路径证明来源。

模板中的下载并发/超时/重试是可调整初值；排除树默认空，必要排除逐项记录原因。Terrain bounds/resolution/chunkSize由当前已加载区域决定，未配置时不能把历史扫描框填入。日期/进程ID/端口/坐标/补丁字节由当前观测记录，与工具查找的路径配置分开。

## 5. 阶段选择与复用原始包

| 模式 | 默认开关/输出 | 必须另行选择的动作 |
|---|---|---|
| `raw_archive` | 原始XML/实际Source/bytecode/全部明示可取资源/原始Terrain；decompile=false | 默认关闭nativeConversion/sourceRecovery/staticPreview/playPreview |
| `recover_source` | 对inputArchiveArtifactId副本恢复参考源码/质量分层/静态验证 | sourceRecovery=true、export.decompile=true；保留原件，匹配版本/编码/toolchain，无原游戏执行 |
| `preview` | 对已确认输入派生静态预览，独立控制入口与素材部署 | staticPreview=true；Play需要playPreview=true且实际只运行审核过预览脚本 |

raw模式可在明确需要原生格式时单独设nativeConversion=true；不自动开启源码/预览。当前默认任务仅运行阶段0；保存完整输入让以后仍能匹配新工具尝试，但受缺失、bytecode版本/优化与工具可用性限制，不能承诺还原原始Luau文本/注释/变量名或完整玩法。

本配置检查工具不是导出器/下载器调度器。适配历史实现时，将参数转换集中到单一适配层；向进程传命令数组和路径参数，记录命令/退出码；客户端writefile读取本次相对prefix配置。检查通过后仍按“01/02”的真实执行与阶段验收运行，不自动把配置pass当游戏完成。

### 独立素材库配置：organize_assets

[[10_原始资产分类与素材库整理工作流]] 使用 `asset-library.config.example.json`，不扩展主配置的run.mode/严格schema。共享模板的archive、output、luneExecutable、输入artifactId/hash均为null；真实值放Vault外的 `asset-library.local.json`。相对本机路径以该本地配置文件所在目录解析，不以当前shell目录猜测；工具入口仍相对工作流根。

| 本地角色 | CLI参数/内容 | 迁移规则 |
|---|---|---|
| `environment.paths.archive` | `--archive`，已解压原始归档根 | 对应rawArchive输入artifactId/hash；只读，不能输出到其内部 |
| `environment.paths.output` | `--output`，独立派生素材库根 | Vault外，与archive互不包含；产物manifest只写相对paths |
| `environment.paths.luneExecutable` | `--lune-executable`，本机已审核解码器 | 换机重新发现/hash/版本/小样本；不带旧runtime绝对位置 |
| `input.*RelativePath` | 原scene/下载manifest/脚本索引的根内相对路径 | 未知结构先查实际archive索引，不能沿用旧游戏布局 |
| 功能角色 | `assetClassifier/modelBundleExtractor/libraryVerifier` | 当前工具位于 `tools/asset_library/`，读取实际CLI/--help后绑定 |

模板policy保持raw只读、convertToLuau/executeGameScripts/launchStudio/play=false；modelExportMode=maximal_non_overlapping且全nested索引、animation class解析、SHA去重、用途/缺失保留。标准库 `check-template` 校验共享模板和新文档链接；它不把本地null值解析成实际工具，也不声称素材生成已成功。

工具未接受 `--config` 时，适配层读本地配置、扩展环境变量/相对路径后显式传CLI参数；不能把本模板当作已实现的自动调度器。字段传参、工具退出码、模型重开/素材hash独立验收写validation。具体命令以本次已审阅工具为准，不把功能角色字面值直接作为脚本名执行。

### 独立 Demo 试验参数

[[11_Demo素材与HUD试验工作流]] 是明确授权后的派生试验，不新增主配置的 `run.mode` 或放宽现有严格 schema。Demo 复现包的 `build-manifest.json` 保存可迁移的输入 hash、目标证据、根内文件路径与策略；本机配置单独保存 `archiveRoot`、`sourceScene`、`libraryRoot`、`demoRoot`、`bridgeRoot`、`bridgeBaseUrl`/`localPort`、`studioId` 与本次目标 `expectedPlaceId`/`expectedUniverseId`。这些角色由当次适配脚本显式传入；当前通用配置检查工具不负责解析或调度 Demo 运行。

换机后重新发现 Python、必要的原生解码器、Studio 与桥端口，选择新的空白试验场并再次确认身份。服务端只绑定回环地址，输入服务根、capture 输出根和目标场景均须明确绑定；导入脚本从参数取得桥 URL，不固化旧地址/目录/端口。运行结束关闭桥，必要的 HTTP 设置恢复到本轮记录值。

模板 UI 与客户端 `PlayerGui` 已捕获动态 HUD 分别溯源。`ScreenGui` 直接位于 `StarterGui` 下以满足 `ResetOnSpawn=false` 的保留条件，不能为了分组再套 Folder。缺失图片与仍在线的资源 URL 分别保留状态；本地文件副本并不自动使新项目拥有访问权。控制器属于 `fresh-demo-code`，原脚本恢复与执行保持关闭。

迁移后先运行包内 `python tools/verify_demo_package.py --package .`，必要时通过 `--source-scene` 显式传入本机原场景做 hash 复核。再按“11”实际导入、Play、交互、撤回和再次导入；旧机器运行截图与静态包校验不替代本机验收。

## 6. 历史资源迁移与单项核对

```powershell
# artifactId从09或history-artifacts.json读取；先填写本地historicalEvidenceRoot。
python ./tools/workflow_config.py resolve-artifact --local-config $localConfigPath --artifact-id $artifactId
```

命令输出当前解析路径、是否存在、大小、实际SHA256和knownSha256匹配状态；hash未记录时明确输出未重验身份，路径不存在时返回失败。不要把解析后的机器绝对路径复制回共享笔记。旧本机根角色缺失时重设本地配置；相对文件夹结构保留，或在本地额外映射后重新核验。

换机清单：

- 迁移完整工作流目录与已验收ZIP/原始包；先核对ZIP hash、CRC、entry集合与每文件hash。
- 新建Vault外本地配置，重新发现Player/Xeno/workspace与可选工具；不把旧配置绝对路径逐项照搬。
- 重验artifact-index，保留未取得/未恢复/未测试状态；重启/传送后重新身份/print/API匹配。
- 仅继续checkpoint第一项未完成操作，复用已有captureId/hash/manifest；新场景或版本使用新captureId。
- Obsidian Git等笔记同步独立设置，历史05不要求沿用旧账号/仓库/周期，不自动启用。

## 7. 静态自检范围

`check-template` 验证JSON模板、安全默认模式、字段/角色、历史索引重复/越界、内部Markdown/Obsidian链接和共享文档中剩余机器绝对路径；外部MOC/Wiki链接作为完整Vault依赖单独报告。`validate` 在本机绑定实际参数，核对必需目录/文件、输入artifactId/hash与路径边界。两者仅执行标准库只读检查，不访问网络、不运行第三方工具、不启动GUI，也不写归档产物。

共享配置必须保持实际机器路径/ID为null；运行配置必须设置captureId、expectedPlaceId/expectedUniverseId及必需版本/input角色。发生字段遗漏/未知角色/路径越界/hash不符，先修配置或输入，不绕过检查。通过结果只有静态范围，真实采集与ZIP验收仍由“01/02”给出的观察证据完成。
