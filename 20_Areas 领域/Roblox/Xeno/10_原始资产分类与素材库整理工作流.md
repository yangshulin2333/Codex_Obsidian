# 原始资产分类与素材库整理工作流

在已验收的原始客户端归档上，选择独立的 `organize_assets` 阶段，把实际取得内容整理为可查找的模型、网格、贴图、骨架/动画和音效素材库。**原始归档保持不变，不反编译 Luau，不自动启动 Studio 或 Play，不执行原游戏脚本。** 这是按原有结构提取资产与建立索引，不能补出未捕获结构、私有素材或完整玩法。

默认采集仍是 [[02_快速执行与验收清单|阶段 0 raw_archive]]。只有明确要求“整理素材库/分类资产”才运行本页；源码恢复与静态预览另见 [[06_字节码恢复与场景优化工作流]]，素材整理不会自动开启它们。换环境与配置见 [[08_环境迁移与参数配置]]。

## 1. 绑定输入、输出与工具角色

1. 从已验收归档或包索引绑定 `rawArchive`、`rawScene`、`downloadedAssetsManifest` 和 `rawScriptsIndex`。记录原始包/场景/清单的大小、SHA256、captureId、实际身份与范围。不能因为当前玩的游戏相同就改用另一份原件。
2. 将素材库输出到 Vault 外的独立目录。拒绝输出等于 raw 根、位于 raw 根内或覆盖唯一原件；也不要把来源 raw 放到输出目录内。修改/导出只发生在派生目录。
3. 本机参数放 Vault 外的 `asset-library.local.json`，由本目录 `asset-library.config.example.json` 复制后填写。`archive`、`output`、`luneExecutable` 只用于本机解析；共享文档/产物清单只保存角色和相对路径。
4. 发现当前 Python 和能解析本次模型格式的 Lune（或其他已审核模型解码器）。记录来源、版本、许可、工具及依赖 SHA256，使用小样本确认 decoder 覆盖。版本不支持的字段写诊断，不当作原件缺失。
5. 通用脚本放 `tools/asset_library/`，由功能角色绑定入口：`assetClassifier`、`modelBundleExtractor`、`libraryVerifier`。先读实际脚本和 `--help`，按当前接口传 `--archive`、`--output`、`--lune-executable`；不得从旧游戏脚本名、用户目录或安装版本推导入口。

共享模板用于记录本阶段参数和固定边界，独立于主 `config.example.json` 的严格 schema；不要把 `organize_assets` 填入主配置的 `run.mode`。主配置继续使用 `raw_archive`、`recover_source` 或 `preview`。素材库模板不是隐式下载器/自动执行器，使用者需按实际工具 CLI 传入已确认路径。

整套流程的便携入口为 `tools/asset_library/organize_assets.py`。**入口不自动读取 `asset-library.local.json`，路径必须通过CLI显式传入。** 本地配置只是保存参数，使用者或已审核适配层先读它并解析路径；相对本机路径以该配置所在目录解析，不按当前shell目录猜测。以下变量必须已绑定为实际路径，未设置的值不得代入旧案例；入口路径相对工作流根。

先用分类器预检正式原包。`--check-inputs-only` 校验来源metadata、manifest/inventory记录及全部绑定内容的大小/hash，不创建素材库、不复制资源、不调用Lune、不访问网络。可省略 `--output` 和 `--lune-executable`；执行证据写在raw之外的本机目录：

```powershell
python ./tools/asset_library/classify_downloaded_assets.py --archive $archiveRoot --check-inputs-only --evidence-dir $localEvidenceRoot
```

正式原ZIP完整解压后的控制metadata可能位于 `validation/`：例如根的 `download-validation.json` 可在 `validation/download-validation.json`，canonical记录的manifest/inventory可在 `validation/<原记录的根内相对路径>`。仅对这些受控metadata执行相同相对路径回退，且必须与记录的SHA256一致；资源payload仍从已绑定归档根定位，不能按同名文件乱搜或猜布局。主 `inventory.json` 和 `snapshot/scene.rbxlx` 仍须符合总入口的已验证输入schema。任意重新排列raw目录不属于自动迁移。

预检通过后，启动独立素材整理：

```powershell
python ./tools/asset_library/organize_assets.py --archive $archiveRoot --output $libraryRoot --lune-executable $luneExecutable
```

已有output默认拒绝覆盖；只有确认是同一输入hash、同一流程后才显式使用 `--resume`，复核复用文件与来源，保留已通过结果。总入口每次真实运行输入预检与素材库独立验收；可用 `--no-zip` 暂停在验收后的目录交付，默认另执行ZIP打包。同级旧ZIP在resume时只校验不覆盖，校验失败保留原包并停止。低层分类入口 `classify_downloaded_assets.py` 使用相同三个参数，可加 `--evidence-dir $localEvidenceRoot` 保存本机诊断。独立验收与打包入口分别是 `verify_asset_library.py` 和 `package_asset_library.py`：

```powershell
python ./tools/asset_library/verify_asset_library.py --library $libraryRoot --archive $archiveRoot
python ./tools/asset_library/package_asset_library.py --library $libraryRoot --output $libraryZip --evidence-dir $packageEvidenceRoot
```

ZIP与执行证据目录都放在素材库/raw之外，已存在的包保留后按当前接口核验，不覆盖旧结果。命令参数、stdout/stderr、退出码和hash写本机证据；共享笔记记录角色/相对路径，不复制机器路径。总入口、独立验收、ZIP打包的成功分别需要真实执行记录，不能把一个check的pass扩展成全部阶段完成。

## 2. 先按内容分类，保持用途关系

下载扩展名、asset ID、Animation 对象和 HTTP 成功都不足以判定实际素材类型。逐文件用 magic、MIME、解析结果和原始引用记录分类；错误 JSON/网页、无法解析文件与未知格式进入单独诊断，不伪装为模型/图片/动画。

| 分类 | 判定证据 | 素材库保留什么 |
|---|---|---|
| 组装模型 `assembled_models` | 原始场景/模型容器中的 Model 层级及实际几何 | 可独立浏览的模型包、原路径/referent、层级与依赖索引 |
| 原始网格 `meshes` | 实际 mesh payload/格式或明确网格引用 | 原始网格文件/hash；MeshId、使用对象与依赖，不假设含组装信息 |
| 贴图与图像 `textures` | 实际图像格式/尺寸及 class/property 引用 | 原文件/hash、格式/尺寸、用途数组与被引用对象 |
| 骨架/绑定 `rigs` | Bone、Motor6D、Attachment、关节/约束与父子链 | 骨架/关节层级、原变换、命名与模型关联；不当作动作片段 |
| 动画 `animations` | 容器实际解析出的 KeyframeSequence/Keyframe/Pose 或 CurveAnimation 曲线数据 | 原始动画容器/hash、真实 class/时长/轨道等可读指标与目标rig关联证据 |
| 动画引用 `animation_references` | 只有 Animation/AnimationId 或 URI | 单独引用清单及取得状态，不计已保存关键帧动画 |
| 音效 `audio` | 实际音频格式与可取得的媒体内容 | 原音频/hash、可读时长/编码、Sound属性引用/用途 |
| 其他与未知 | 字体、视频、普通容器、解码缺口等实际结果 | 原文件或artifactId、明示依赖、失败状态，不为凑分类丢弃 |

同一图像可同时用于 MeshPart 纹理、Decal/Texture、SurfaceAppearance/MaterialVariant 的 PBR 通道、UI ImageLabel/ImageButton、ParticleEmitter/Beam/Trail 等用途。以 `usageRoles` 数组保留 `class/property/instancePath/referent/URI`，不要把一份 PNG 只归入一个用途后丢失其他关系。PBR 各通道记录 Color/Normal/Roughness/Metalness 等实际属性；有贴图文件不证明当前引擎支持该用途的本地部署。

## 3. 提取最大不重叠模型包，同时索引所有嵌套模型

对原始场景建立包含全部 Model 的 `nested_models` 索引。每项至少保存原 referent、完整路径、父模型、子模型、class、几何数量、rig标记、resource refs 与来源 scene hash。嵌套模型仍可检索，即使没有另导出一份文件。

默认导出 `maximal_non_overlapping`：在可导出的组装模型候选中，选择没有另一可导出候选祖先的最大根，并将其子树作为一个 `modelbundle`。两个已导出包的原始对象集合不得重叠。不是把每个 nested Model 都重复导出，也不是按全场景 Folder/服务根强行装成一个模型。已加载但不属于这些模型根的松散几何可另建容器保存，必须单独计数并保证对象集合不重叠。无法导出的根单独记录原因；改变选择规则时写入本次配置与报告，不能悄悄换成碎片集合。

模型包尽量保留原始父子层级、名称、CFrame/尺寸、MeshPart/Part、Attachment、Bone、Motor6D、Joint/Constraint 和可读属性，记录序列化重写或 decoder 未覆盖项。跨包 Ref/关节与资源依赖保留在清单；未取得目标写 unresolved，不为消除报错删除父几何或随意拼接对象。

`meshes` 是单独几何文件，通常不包含原场景的组装、材质、关节和完整变换。`modelbundle` 保存已捕获的组装上下文；导出的模型不等于原游戏可运行物件。骨架与动画分别计数，有 Bone/Motor6D 不表示有关键帧；有动画容器也不证明与某一 rig 可直接匹配，骨骼/关节名和映射需要独立证据。

如果包里有 Script/LocalScript/ModuleScript，只保留资料与原始索引，不调用它们；导入后运行状态需单独审核。若工具把可运行脚本停用或剥离到资料区，必须记录变更数量、原路径和 hash，且仅作用于派生包。本阶段不把 bytecode 转为 Source，也不运行原脚本验证模型。

## 4. SHA256 去重与依赖闭合

原始内容先按实际 bytes 的 SHA256 去重。不同 asset ID/URI、请求和实例可映射同一物理文件；保留所有 alias、原始请求键和用途关系。区分资源引用数、下载请求数、分类条目数、物理文件数、唯一 hash 数、Model索引数与modelbundle数，不能混为“素材总数”。

派生序列化的模型包或重写manifest有自己的 hash，并保留来源 scene hash/原始referent集合和生成工具；不要因为输出 hash 变化就丢失输入身份。复制原始下载文件时，复制后大小/hash 必须与来源一致。

从本次 scene 属性、已有下载manifest、已解析容器和已取得文件的明示依赖构建关系。每项依赖写 `available`、`missing`、`restricted`、`unknown_format` 或 `unresolved` 与原始证据；空 URI、内置资源、在线引用分别处理。只做分类不自动扩大下载范围或绕权限，需补取时单独建立增量请求并沿用原归档下载边界。

动画容器必须实际 parse class；普通 `.rbxm` 容器不能仅凭后缀加入animations。把 decoder 错误、容器无关键帧、只有 Animation 引用、媒体/资源访问失败分别保存，不能以“存在文件”宣称骨骼动画已恢复。

## 5. 交付目录与最小索引

具体文件名以实际工具生成的 manifest 为准，目录中的路径均相对于素材库根。分类子目录可存一份原件或指向按 hash 保存的物理文件，不要求重复复制。

```text
<ASSET_LIBRARY_ROOT>/
  README.txt                        输入身份/范围、分类规则与限制
  index.html                        无外部网页依赖的离线检索入口
  index.json / index.csv            总索引；类别、相对路径、hash、来源
  download-index.json               下载文件/alias/用途/缺失和分类证据
  file-checksums.json               素材库文件集合、大小与SHA256
  models/assembled/index.json       最大组装包与全部nested Model索引
  models/                          组装容器、原始网格；按索引subtype区分
  textures/                        原始图像；PBR/UI/particle用途在清单里
  rigs/index.json                   骨架/关节资料与所属modelbundle索引
  animations/scene/index.json       场景内真实动作容器及出现/去重关系
  animations/                      经class解析确认的原始动画容器
  audio/                           可取得原始音频
  other/                           字体、metadata与未分类资料
  validation/                      原件保留/结构/样本解码的可迁移证据
<LOCAL_EVIDENCE_ROOT>/              命令/退出码/输入hash与阶段独立验收
<ASSET_LIBRARY_ROOT>.zip            独立打包成果
```

索引可采用 JSON/JSONL 与易读 CSV/HTML；链接必须相对素材库根，网页/表格不能只指向原工作目录的机器绝对路径。语义上至少能查到资源身份/角色、category/subtype、relativePath、sha256、bytes、来源输入hash/referent/instancePath、用途与依赖、status；具体字段由上述实际索引schema定义，不为满足示意字段名伪造数据。没有可用文件的条目保持索引和失败状态，不能生成虚假文件链接。动画列表中的rig/引用条目和真正动作文件分开看，不能把catalog大类的条目数当下载动画数。

原输入包仍单独保存；素材库README指出与原输入artifactId/hash的关系即可，不必再复制整份raw。工具许可证与游戏素材来源分开记录：下载成功或可读取不代表获得素材的版权、再分发/商用许可。未知license状态原样标注 `not-established`，不猜测为可自由使用。

## 6. 独立验收与迁移

- 原包/场景/清单的处理前后hash一致；原raw文件集合如已记录则复核，所有输出只在派生目录。
- 逐项重读素材库索引：路径不越界、文件存在、大小/hash一致；输出物理文件与manifest集合闭合。
- Model候选/全部nested索引/已导出最大根数量分别报告；导出根两两无祖先关系、原始referent集合无交集。导出包重新parse核对主要层级/几何/rig与明示引用，decoder缺口列清。
- 真实animation容器class统计与animation_references分开；rig数量与动画数量不互相代替。PBR/UI/particle等原用途关系不因SHA去重而丢失。
- 已知成功文件与缺失依赖可追溯到原始manifest/hash。别名去重后原引用/用途总数仍可闭合。
- README/索引可用相对路径在移动后的目录中打开；迁移只修改本地archive/output/decoder路径。异机重新核对工具兼容性，不借旧验证结果宣称新工具无损。

完整命令、参数、stdout/stderr、退出码保存在raw和素材库之外的本机evidence目录；原件前后hash、结构校验和样本解码摘要可复制到素材库 `validation/`，改用根角色/相对路径后与产物一起迁移，并纳入文件校验。模板和文档的静态检查只说明配置/链接可用，实际素材数量以本次分类与模型提取报告为准；尚未执行的生成/转换/Play不得标成功。打包时重验文件集合、ZIP CRC和每entry大小/hash，保留缺失/未取得/未测试状态。

XML导出文件带标准XML declaration时，某些解码器可能拒绝。先保留错误与原文件hash，只在送给解析器的内存字符串中去掉一条开头标准declaration再重试；成功也不得把这种兼容处理写回原文件或冒充Studio验收。核对实际实例/class与原索引，复验文件hash未变；其他decoder警告继续列未覆盖项。

## 历史实例：2026-10-14 原始素材库整理

| 全nested模型索引 | 7,629 | Model/模型类对象索引，未另行重复导出7,629份包 |
| 原始网格 | 2,370 | mesh文件，不能代替组装模型/关节/材质 |

本次独立素材库ZIP为644,724,925字节、7,486条目，CRC、entry集合和逐entry大小/SHA全部通过，打包后素材库来源文件hash未变。ZIP SHA256为 `44b6f59d6fff6147dc72b8f818ffbe057f8622862f6b11e3406cc75f5459b80f`。这是这一版交付身份，不作为未来重建包的固定hash；后续修改/重包必须重新验收。需要导入或播放验收时另设具体目标继续。

执行完成后停止在素材库交付状态。后续是否导入Studio、匹配骨架动画、转换其他格式或恢复Luau源码由新明确请求决定；任何派生修改仍保留原始输入。

## 素材库之后：独立 Demo 验证

明确需要在 Studio 试验模型和整套 HUD 时，进入 [[11_Demo素材与HUD试验工作流]]：先保存原生空场景基线，再导入一个模型、主 HUD 和可操作背包。模板 UI 与已捕获的运行态 HUD 分开溯源；原脚本剔除，交互使用新写演示代码。桥 URL、素材源目录、派生包根与目标场景通过本机参数传入。保留依赖缺口，并区别本地图片/mesh 副本与模型中的在线资源 URL。实际 Play、撤回和再次导入另存观察证据，原素材库与原始归档保持不变。
