# Xeno 客户端内容归档工作流

从下载 Xeno、验证真实执行，到保存当前客户端可读场景、下载资源、生成原生 `.rbxl` 与带启动入口的 ZIP。流程整理自 2026-10-09 的实际成功记录，工具版本和目标游戏参数需要在下次执行时重新核对。

## 从这里开始

下次可以填写“02”中的参数和任务提示，交给 Codex 按完整流程执行。手动执行时需要先审阅、参数化历史脚本；这份文档不是安装后自动适配所有游戏的一键工具。

- [[04_成功案例与参考实现|成功案例、脚本和验收证据]]：查实际实现及报告，避免把历史特例当成通用参数。

## 最终拿到什么

```text
项目归档/
  项目场景.rbxl
  启动场景.cmd
  先看这里_使用说明.txt
  snapshot/                 原始捕获与身份记录
  scripts/                  可读Source、bytecode及其索引
  assets/                   成功下载的资源与manifest
  terrain/                  需要时保存明确扫描范围及恢复证据
  validation/               下载、Studio与打包验收报告
项目归档.zip
```

`.rbxl` 可以用 Roblox Studio 打开。启动脚本只是找到本机已安装的 Studio 并打开包内场景的便捷入口；归档成果本身不依赖 Xeno。多个 Place 或楼层保留各自的 `.rbxl` 和资料目录。

“客户端归档完成”表示此次已读取内容有证据、文件与校验；不会自动得到服务端逻辑、所有楼层、未加载区域、受限资源或完整可玩的原游戏。场景里的部分资源引用仍可能依赖 Roblox 在线服务。

## 保存位置
