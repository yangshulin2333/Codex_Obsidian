**核心观点**

Codex App 被视频作者定位为 Codex 几种形态里最完整、最适合日常开发的一种：它不是传统 IDE，而是“项目级 AI 工作台”。它的强项在于多任务并行、权限沙箱、计划模式、内置浏览器验证、Git/云端协作、记忆、插件、Skills、MCP、部署和电脑自动化。

### **笔记**

#### 1. **安装与基础准备**
   - 使用前建议先装好 `Git`、`Node.js`、`VS Code`。
   - Codex App 支持 Windows 和 macOS。
   - 免费 ChatGPT 账户也能使用 Codex，但额度较低。
   - 首次进入会选择使用场景，Codex 会据此推荐插件和 Skills。

#### 2. **界面与基础使用**
   - Codex App 是三栏布局：
     - 左侧：项目与任务列表。
     - 中间：对话窗口。
     - 右侧：浏览器、文件、终端等多功能区域。
   - 可以同时开启多个项目、多个任务，并行执行。
   - 任务状态会显示执行中、等待批准、已完成等状态。
   - 对话可以归档、恢复、重命名，但搜索主要依赖对话标题。

#### 3. **权限与沙箱**
   - Codex 的权限系统围绕“沙箱”展开。
   - 默认情况下，Codex 可以读取和修改项目目录内文件。
   - 默认不能修改项目外文件，也不能随意联网。
   - 如果需要联网或访问更高权限，会触发审批。
   - 视频推荐使用“自动审查”模式：低风险操作自动通过，高风险操作仍需人工确认。
   - “完全访问权限”风险较高，应谨慎开启。

#### 4. **上下文管理与模型选择**
   - Codex 会显示当前对话上下文使用量。
   - 上下文过长时会自动压缩，也可以手动压缩。
   - 作者建议：完成一个任务后，最好新开对话，比长期压缩上下文更清爽。
   - 模型可按任务复杂度选择；视频中也提到快速模式会提升速度，但消耗更多额度。

#### 5. **AI 画图与中途引导**
   - Codex 可调用 AI 生图能力，为网页生成配图、地图、轮播图等。
   - 如果 AI 执行方向错了，可以使用 `Steer` / 引导功能中途打断并纠正。
   - 建议默认让新指令排队；需要立即纠偏时再使用引导。

#### 6. **计划模式**
   - 复杂任务建议开启 Plan 模式。
   - Codex 会先生成执行计划，并可能用问题卡片确认关键选择。
   - 用户确认后才开始改代码。
   - 视频示例：把一个普通网页项目迁移到 Next.js，并用内置浏览器验证结果。
   - 内置浏览器支持批注式反馈，例如点选页面元素，让 Codex 修改具体问题。

#### 7. **代码管理**
   - Codex App 不是完整 IDE，不能像 VS Code 那样直接编辑全部代码。
   - 推荐把项目初始化为 Git 仓库，再用 VS Code 等 IDE 辅助查看和编辑。
   - Codex 可以帮忙创建 `.gitignore`、初始化仓库、提交代码、推送到 GitHub。
   - 视频重点讲了两个 Git 技巧：
     - 用 Git 回滚不满意的代码改动。
     - 用 Git Worktree 并行开发多个分支，完成后合并回主干。

#### 8. **云端模式**
   - Codex 任务可以在本地执行，也可以在云端执行。
   - 云端模式前提：代码已同步到 GitHub。
   - 云端执行会拉取仓库、完成修改，然后生成 Pull Request。
   - 适合出门在外时用手机审批代码修改。

#### 9. **记忆系统**
   - 新对话默认没有历史上下文，因此复杂项目需要记忆文件。
   - 项目级记忆：在项目根目录创建 `AGENTS.md`，写入项目说明、开发规范、个人偏好等。
   - 全局记忆：在 Codex 设置里的自定义指令中配置，对所有项目生效。
   - 作者示例的全局规则：禁止用脚本批量删除文件，避免 AI 误删目录。

#### 10. **插件与自动化**
   - 插件用于连接第三方服务，例如 GitHub、Gmail、浏览器等。
   - 视频示例：让 Codex 查询 GitHub 仓库 star 数，并通过 Gmail 发邮件总结。
   - 可以把这类任务做成自动化，例如每周五下午定时执行并发邮件。
   - 自动化任务可以编辑频率、模型，也可以手动立即运行。

#### 11. **Skills**
   - Skills 是给 Agent 的专业能力包，也可以理解为“可复用工作流说明书”。
   - 来源包括：
     - 官方 Skills。
     - 第三方 Skills。
     - 自己编写的 Skills。
   - 视频示例：
     - 使用官方动画/视频相关 Skill 生成内容。
     - 使用第三方 PPT 风格 Skill 生成演示文稿。
     - 用 `Skill Creator` 自制“视频字幕转 Markdown 图文笔记”的 Skill。

#### 12. **MCP**
   - MCP 是模型上下文协议，本质是给 AI 的标准化工具箱。
   - 视频用 Supabase MCP 做示例：
     - 在 Supabase 创建项目。
     - 在 Codex 中添加 MCP 服务器。
     - 授权后重启 Codex。
     - 让 Codex 创建数据库表、后端接口，并把表单数据写入 Supabase。
   - MCP 适合把数据库、业务系统、云服务等能力接入 Codex。

#### 13. **项目部署**
   - 视频演示了使用 Netlify 插件部署 Next.js 项目。
   - Codex 可以通过插件完成登录、授权、部署，并返回公开访问域名。
   - 作者提到 Netlify 的域名在国内可直接访问。

#### 14. **电脑自动化**
   - `computer use` 目前视频中说明主要支持 macOS。
   - Codex 可以操作桌面应用、浏览器、聊天软件等。
   - 示例：
     - 打开聊天软件，给老板发送消息。
     - 打开 GitHub 项目看板，总结进度，生成英文简报并发送。
     - 把上述流程做成每天 17:00 自动执行的任务。
   - macOS 上建议开启“运行时防止系统休眠”。

### **最值得记住的实践建议**

- 复杂任务先开 Plan 模式。
- 每个复杂项目都写 `AGENTS.md`。
- 默认用自动审查权限，不轻易开完全访问。
- 一个任务完成后新开对话，避免上下文污染。
- 重要改动先 Git 提交，方便回滚。
- 多任务并行用 Git Worktree。
- 重复流程沉淀成 Automation 或 Skill。
- 外部系统集成优先考虑插件和 MCP。
