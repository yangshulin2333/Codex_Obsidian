# 低耦合规则

本文件约束这个工作流如何保持通用，避免变成某个项目的专用脚本。

## 工作流只负责什么

```text
1. 找 GUI 根节点。
2. 导出指定 GUI 子树。
3. 解析快照。
4. 对比 before / after。
5. 输出 UI 读懂报告。
6. 检查调用方传入的素材表，判断 AssetId 是否可用。
```

## 工作流不应该内置什么

```text
1. 不内置 ScreenGui 名字，例如 MainGui。
2. 不内置页面名，例如 MainPage、AttrPage。
3. 不内置面板名，例如 TaskPanel、KeyTipPanel。
4. 不内置某个项目的素材表路径。
5. 不内置某个项目的生成脚本路径。
6. 不内置某个项目的素材命名规则。
```

## 项目差异放在哪里

项目差异必须作为参数或报告内容出现：

```text
1. TARGET_JOBS / TARGET_PATHS：由总览导出、用户说明、或项目文档决定。
2. Snapshot 文件名：由当前项目和当前改动决定。
3. 生成脚本路径：由当前项目结构决定。
4. 检查命令：由当前项目工具链决定。
5. 素材表路径和素材根目录：由用户说明、项目文档、或当前项目文件决定。
```

HTTP 分段快照也是同一条规则：

```text
1. POST_URL 是运行参数，不写死到规则里。
2. TARGET_JOBS 是运行参数，不写死 GUI 名、页面名、面板名。
3. --out-dir 和 --name 是运行参数，不写死项目目录。
4. 项目可以复制一份专用脚本放在项目 Tools 里提高效率，但工作流包里的脚本必须保持通用。
5. 如果只需要同步一个页面，Codex 应只读取对应 segment，不把整个大 combined.json 当作默认上下文。
```

## 素材表低耦合规则

素材表检查工具必须通过参数接收路径：

```text
TablePath：当前项目的素材表 xlsx/csv。
AssetRoot：当前项目的本地 PNG 根目录。
FocusRelPath：可选，只检查当前 UI 涉及的几行。
OutPath：当前项目的检查报告输出路径。
```

不能把 `D:\SVN`、`MainGui`、`UI_AssetId_Map_For_UI_Build.csv` 写死进工具逻辑里。它们只能出现在本次项目调用命令或报告里。

AssetId 格式也必须通用：

```text
1. 123456
2. rbxassetid://123456
3. URL 中包含 id=123456
```

以上三种都应该被规范化成 `rbxassetid://123456`。

当 `.xlsx` 和 `.csv` 同时存在但内容不一致时：

```text
1. 使用用户明确提到的文件作为源。
2. 报告里写清楚实际读取的 TablePath。
3. 如果另一个文件只是辅助导出，可以由 Codex 同步或重生成。
```

## Codex 的默认行为

当用户只说“读一下这个项目 / 读一下这些文件”时：

```text
1. 不猜项目 GUI 名字。
2. 先读 WORKFLOW_MANIFEST.json。
3. 让用户运行总览导出器，或读取已有总览导出。
4. 从总览里选择候选 GUI 路径。
5. 默认让用户运行 HTTP 导出器。
6. 只有项目不能开启 HTTP Requests 时，才退回 Output 聚焦导出器。
```

## 当前项目示例的边界

当前项目的路径、页面名、面板名可以出现在：

```text
1. 本次对话的操作说明。
2. 项目的 UI 读懂报告。
3. 项目自己的交接文档。
```

不能写成工作流的固定规则。
