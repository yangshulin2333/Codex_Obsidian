# Roblox 带骨骼与本地动画模型迁移工作流

## 一句话目标

把一个带骨骼的 Roblox 模型从源 Place 迁移到目标 Place，并让目标 Place 的 Animation Editor 能加载原有本地剪辑。

这份流程处理的是 **编辑器本地剪辑**（`KeyframeSequence`），不是运行时已经发布的 `AnimationId`。

## 先理解四层对象

```text
Workspace.<模型>                         可摆放、可选中的骨骼模型
├─ AnimationController
│  └─ Animator                            编辑预览或运行时播放者
└─ AnimSaves : ObjectValue                指向该模型的本地剪辑容器
   └─ Value ─────────────────────────────┐
                                           ↓
ServerStorage.RBX_ANIMSAVES : Model       本地剪辑总仓库
└─ <模型> : ObjectValue                   该模型的剪辑容器
   ├─ <动画 A> : KeyframeSequence
   ├─ <动画 B> : KeyframeSequence
   └─ Value ─────────────────────────────→ Workspace.<模型>
```

记忆法：

- `Animator`：负责“播放”。
- `KeyframeSequence`：真正的“本地关键帧动画内容”。
- `AnimSaves.Value`：告诉 Animation Editor“这只模型去哪里找剪辑”。
- `RBX_ANIMSAVES`：本地剪辑的总仓库。

## 不可替换的结构契约

源资源中 `ServerStorage.RBX_ANIMSAVES` 的类型是 **Model**。迁移时保持为 `Model`，不要自行改成 `Folder`。

`Folder` 虽然也能容纳实例，但本工作流依赖 Animation Editor 原资源的本地保存结构。最稳妥的原则是：**名称、ClassName、父子层级、ObjectValue 引用都与源资源保持一致。**

同样，不要在 `RBX_ANIMSAVES` 下保留两个同名的 `<模型>` 容器。Explorer 看起来名称相同不代表它们是同一个实例；模型可能仍指向那个空容器。

## 迁移前检查（源 Place）

以 `<模型>` 代替实际名称，例如 `Polygonal Magma`。

- [ ] `Workspace.<模型>` 是 `Model`。
- [ ] 模型下存在 `AnimationController > Animator`。
- [ ] 模型下存在 `AnimSaves`，其类型是 `ObjectValue`。
- [ ] `ServerStorage.RBX_ANIMSAVES` 存在，类型是 `Model`。
- [ ] `ServerStorage.RBX_ANIMSAVES.<模型>` 存在，类型是 `ObjectValue`。
- [ ] 该容器内有预期数量的 `KeyframeSequence`。
- [ ] 随机点开一个剪辑，确认 `Length > 0`，例如 Idle。

> 只复制 `Workspace.<模型>`，通常只能迁移网格、骨骼和 `Animator`，不会可靠地迁移本地剪辑数据及跨 Place 的对象引用。

## 推荐迁移步骤：复制完整动画容器

### 1. 迁移模型本体

在源 Place 复制 `Workspace.<模型>`，粘贴到目标 Place 的 `Workspace`。

此时不要急着打开 Animation Editor；先完成剪辑容器和引用绑定。

### 2. 在目标 Place 准备总仓库

确认目标 Place 中存在：

```text
ServerStorage
└─ RBX_ANIMSAVES : Model
```

若目标中不存在，创建 **Model** 并命名为 `RBX_ANIMSAVES`。

### 3. 复制源 Place 的完整剪辑容器

在源 Place 复制整个对象：

```text
ServerStorage.RBX_ANIMSAVES.<模型> : ObjectValue
```

不要只选择其中某几条 `KeyframeSequence`；复制完整容器可以保留剪辑集合。

在目标 Place 粘贴到：

```text
ServerStorage.RBX_ANIMSAVES
```

如果目标中已有同名但为空的 `<模型>` 容器：

1. 先重命名为空容器，例如 `<模型>_EmptyReferenceBackup`；不要直接删除。
2. 再粘贴源容器。
3. 确保最终只有一个正式名称为 `<模型>` 的、含剪辑的容器。

### 4. 重新建立双向 Value 引用

跨 Place 复制后，`ObjectValue.Value` 可能变成空、指向旧对象，或指向同名的错误对象。必须在目标 Place 重新检查并绑定：

| 要选择的对象 | `Value` 必须指向 |
|---|---|
| `Workspace.<模型>.AnimSaves` | `ServerStorage.RBX_ANIMSAVES.<模型>` |
| `ServerStorage.RBX_ANIMSAVES.<模型>` | `Workspace.<模型>` |

在 Properties 面板中修改 `Value`。这里的 `Value` 保存的是**对象引用**，不是路径文字；名称相同也不能代替正确引用。

### 5. 重新打开 Animation Editor 并加载

1. 关闭已有的空白剪辑编辑器标签页。
2. 在 Explorer 选中 `Workspace.<模型>`。
3. 打开 Animation Editor / Clip Editor。
4. 点击 `⋯ > 加载（Load）`。
5. 选择一条剪辑，例如 `<模型>@Idle_Take 001`。
6. 时间轴应出现骨骼轨道和关键帧；按播放按钮做预览。

> 一个已经打开的“无标题动画”标签页可能保留旧的空白状态。完成引用修复后，应关闭并重新打开编辑器再判断结果。

## 验收清单

只有以下项目全部通过，才算“本地动画迁移完成”：

- [ ] `RBX_ANIMSAVES` 是 `Model`，不是 `Folder`。
- [ ] `RBX_ANIMSAVES` 下只有一个正式的 `<模型>` `ObjectValue` 容器。
- [ ] 源与目标的 `KeyframeSequence` 数量一致。
- [ ] 目标中至少一条已知剪辑的 `Length > 0`。
- [ ] `Workspace.<模型>.AnimSaves.Value` 指向含剪辑的容器。
- [ ] 该容器的 `Value` 指回 `Workspace.<模型>`。
- [ ] `Workspace` 根目录没有误粘的 `KeyframeSequence`。
- [ ] 重新打开 Animation Editor 后，`加载（Load）` 可点击且能看到剪辑列表。
- [ ] 加载 Idle 后，时间轴非空且模型发生骨骼姿势变化。

## 常见失败与定位

| 症状 | 常见原因 | 修复 |
|---|---|---|
| 模型有骨骼但剪辑编辑器为空 | 只复制了模型本体 | 迁移 `RBX_ANIMSAVES.<模型>` 容器并重新绑定 Value |
| `加载（Load）` 变灰 | `AnimSaves.Value` 指向空容器或无剪辑容器 | 找到含 `KeyframeSequence` 的容器并重新绑定 |
| Explorer 有动画名称但编辑器仍为空 | 同名容器重复，模型指向空的那个 | 保留含剪辑的容器为正式名称，重命名空容器，并修正 Value |
| 剪辑被粘贴到 `Workspace` 根目录 | 粘贴时没有选中目标动画容器或 Explorer 焦点错误 | 移到正确容器；不要把根目录副本当作已迁移成功 |
| `RBX_ANIMSAVES` 是 Folder | 手动创建时类型错误 | 改为与源资源一致的 `Model`，然后重新核对容器与 Value |
| Idle 能加载但游戏运行时不播放 | 本地 `KeyframeSequence` 未发布，或 AnimationId 无权限 | 进入“运行时播放”步骤，不要把编辑器加载成功误判为运行时完成 |

## 运行时播放是另一项工作

本流程完成后，Animation Editor 可以编辑和预览本地剪辑；这不等于游戏脚本已能播放。

运行时需要单独完成：

1. 在 Animation Editor 通过 `⋯ > Publish to Roblox` 发布需要使用的剪辑。
2. 将动画发布到当前体验对应的个人或群组所有者。
3. 记录生成的 `AnimationId`。
4. 在模型的 `Animator` 上通过 `Animator:LoadAnimation(Animation)` 获得 `AnimationTrack`。
5. 在 Play 测试中验证：无权限报错、轨道 `Length`、`IsPlaying`、`TimePosition` 和骨骼实际移动。

本地编辑器检查与运行时检查应分开验收：

```text
本地剪辑迁移完成 ≠ 已发布 AnimationId ≠ 游戏运行时已播放
```

## 最小排错顺序

以后遇到“复制模型后动画不见了”，按下面顺序查，不要先改脚本：

1. `Workspace.<模型>` 是否仍有 `AnimationController > Animator`？
2. `RBX_ANIMSAVES` 是否为 `Model`？
3. `<模型>` 的剪辑容器中是否真的有 `KeyframeSequence`，数量是否正确？
4. 两个 `ObjectValue.Value` 是否互相指向正确实例？
5. 是否存在同名的空容器？
6. 是否把剪辑误粘到 `Workspace` 根目录？
7. 关闭并重新打开 Animation Editor，再执行 `加载（Load）`。
8. 只有本地加载通过后，再处理 Publish、AnimationId、权限和脚本播放。
