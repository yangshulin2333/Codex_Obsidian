# Blender 骨骼动画导入 Roblox Studio 工作流（V3）

## 一句话说明

把带骨骼、蒙皮与动作的 Blender 角色安全导出为可直接交给 Roblox Studio 3D 导入器的单个 FBX；重点解决“导入后原地踏步”“武器/附件跑位”“部分骨骼不动”和“贴图缺失感叹号”。

本流程**不修改原始 `.blend`**：所有骨架改造、材质降级和导出都在内存副本或独立输出文件中完成。

## 适用范围与完成标准

适用：Blender 中已有网格、Armature、权重和至少一个 Action 的自定义角色（不要求是 R15）。

完成标准：

- [ ] 导出的 FBX 只有角色网格和一套骨架，包含一个动作。
- [ ] Blender 回读后，骨架、网格数量、顶点数和动作都还在。
- [ ] 抽样帧的顶点世界坐标与源文件一致，最大误差不超过 `0.001`（源文件单位）。
- [ ] Studio 3D 导入器中没有缺失外部贴图造成的感叹号；若原贴图缺失，明确交付无贴图材质版。
- [ ] 在 Studio 动画时间轴检查起点、中间、终点：全身、脊椎、附件/武器和脚步位移符合 Blender。

不在本流程自动保证的内容：面部 Shape Key、约束系统、布料/物理模拟、多动作合并，以及原始贴图文件已经丢失时的贴图复原。

## 0. 先做只读体检

在 Blender 中记录以下信息，再决定处理方式。不要只看场景时间轴；应以**活动 Action 的帧范围**为准。

| 检查项 | 必须确认的结论 | 目的 |
| --- | --- | --- |
| Armature | 名称、骨骼总数、所有顶级根骨骼 | 多根骨链必须一起处理，不能只接骨盆 |
| 网格 | 每个蒙皮网格的名称、顶点数、三角面数 | Roblox 导入限制按单个网格核对，不把全部分件的总面数当作单网格面数 |
| Action | 名称、真实起止帧、FPS、是否只有一个活动动作 | 防止时间轴终点比动作短而截断后半段 |
| 动画通道 | Armature 对象是否有 `location / rotation / scale` 曲线；根骨骼是否有位移 | 决定是否需要 V3 Root Motion 烘焙 |
| 权重 | 每顶点影响数、是否有未加权附件 | 防止 Studio 忽略复杂权重或把附件留在原地 |
| 材质 | 是否引用不存在的图片路径 | 预先处理 Studio 导入感叹号 |
| 静态姿势 | Rest Pose 和 Action 第 1 帧的武器/附件位置 | 区分“默认模型姿势”与“动画播放后的姿势” |

## 1. 根运动判定：不要一律强行烘焙

| 源动画情况 | 处理 | 典型现象 |
| --- | --- | --- |
| Armature **对象本身**有位置/旋转/缩放曲线 | 使用 V3：将对象位移烘焙到新增 `Root` 骨骼，再删除对象变换曲线 | Studio 动作能播放四肢，但角色在原地踏步 |
| Armature 对象静止，主根骨骼（如 `Bip001`）本身有位移 | 保留该骨骼动画；可增加结构性 `Root`，但不需要制造不存在的 Root 位移 | Blender 和 Studio 都应保留行走位移 |
| 对象和根骨骼都没有位移 | 这是原地动作；不要把它误判为导出错误 | 攻击、待机、原地施法等 |

### V3 Root Motion 转换规则

仅在第一种情况执行：

1. 新建名为 `Root` 的骨骼，位于原点。
2. 把**全部原始顶级根骨骼**设为 `Root` 子级；保存并恢复每根骨骼的 Rest Matrix，不能改变骨架静态形状。
3. `Root` 不参与蒙皮：所有网格对它的权重必须为 `0`。
4. 复制原 Action，绝不直接改源 Action。
5. 以动作首帧的 Armature 世界矩阵为基准，对每一帧计算：

   ```text
   RootDelta = inverse(ArmatureWorld[首帧]) × ArmatureWorld[当前帧]
   ```

6. 将 `RootDelta` 写成 `Root` 的位置、四元数旋转和缩放关键帧；保留全部原 Pose Bone 曲线。
7. 从复制后的 Action 删除 Armature 对象的 `location`、`rotation_euler`、`rotation_quaternion`、`scale` 曲线，并把 Armature 和所有网格对象固定到首帧矩阵。
8. 对首帧、中间帧、末帧逐网格比较转换前后的**评估后世界顶点坐标**；超过阈值立即停止，不输出 FBX。

> 多根骨链常见于角色身体、头发、挂件、武器或相机配件。只把其中一根接到 `Root` 会导致其余链条脱节或不随角色移动。

## 2. 材质与附件处理

### 外部贴图缺失

如果图片路径不存在，FBX 会把不存在的外部资源带给 Studio，常见表现是导入窗口红色感叹号。

- 有完整原贴图：重新绑定真实图片，并在干净导入目录中保留相对路径资源。
- 原贴图已丢失：清掉 Image Texture 节点，改为保留原材质颜色的 Principled 无贴图材质，并在交付说明中写明“无贴图降级版”。
- 不要把缺失路径原样留在 FBX 后交付；这不会恢复贴图，只会增加导入不确定性。

### 武器或附件默认竖在身旁

先区分两件事：

1. **模型静态预览**显示 Rest Pose；Action 未播放时，武器可能就是默认位置。
2. **动作播放后仍跑位**才是绑定/动画问题，需要检查附件是否是同一 Armature 的蒙皮网格、是否有正确权重，以及对应骨骼是否有曲线。

不要通过把武器单独移动到手里来“修复”动画；这样常会破坏后续帧。应优先修正 Rest Pose、蒙皮或动作首帧。

## 3. FBX 导出设置

导出前只选择 Armature 和其全部蒙皮网格；确保 Armature 没有被隐藏。不要把灯光、相机或场景辅助物作为对象导出。

| 类别 | 固定设置 |
| --- | --- |
| 骨架 | 不添加 Leaf Bones；导出全部需要的骨骼 |
| 动画 | Bake Animation；步长 `1`；简化系数 `0`；强制首尾关键帧；只导出当前动作 |
| 网格 | 不在导出时应用会破坏蒙皮关系的修改器或对象变换 |
| 坐标 | `Forward=-Z`，`Up=Y`；应用单位缩放，保持角色在 Blender 验证过的实际比例 |
| 文件 | 单个 FBX、唯一版本号；绝不覆盖已被 Studio 导入的旧版本 |

建议命名：

```text
<角色名>_Roblox_CustomRig_Animated_V3_RootMotion.fbx
```

即使本次不需要把对象位移烘焙到 `Root`，也可保留 `V3_RootMotion` 版本标识，表示它已通过本流程的骨架和动作验证；交付说明必须写清实际位移来自哪一根骨骼。

## 4. 两层验收：先 Blender，再 Studio

### A. Blender 自动回读（发布门槛）

用全新空场景重新导入 FBX，逐项确认：

- 只有一套 Armature，动作存在且帧范围完整。FBX 可能整体偏移 1 帧，例如源 `1–172` 回读为 `2–173`；只要时长和关键姿势一致即可接受。
- 每个蒙皮网格的名称、顶点数、三角面数与源文件相同。
- `Root` 存在，所有原顶级根骨骼均为其子级；所有网格对 `Root` 的权重为 `0`。
- 主根骨骼和至少一个网格在首帧、中间帧、末帧发生预期变化。
- FBX 没有外部图片引用。

### B. Roblox Studio 人工验收（不可省略）

使用 **3D 导入器**导入新文件，并在动画时间轴检查：

- [ ] 导入窗口没有贴图缺失感叹号。
- [ ] 骨骼覆盖全身；脊椎、手脚、头发/挂件均会动。
- [ ] 动作首帧的武器或附件位置正确。
- [ ] 中间帧没有局部骨骼固定、翻转或脱离。
- [ ] 行走/冲刺动作的角色整体位移与 Blender 一致；若源本来是原地动作，则确认它没有被意外移动。
- [ ] 新导入的 Model 与旧测试 Model 并存时，确认播放的是新实例，避免把旧结果误判为新文件问题。

Studio 验收不能由 Blender 回读替代；若没有可连接的 Studio 实例，应明确标为“待 Studio 目测确认”，不要声称已经在 Studio 成功。

## 5. 常见故障速查

| 现象 | 高概率原因 | 最小修复 |
| --- | --- | --- |
| 角色原地踏步 | 位移在 Armature 对象曲线，不在骨骼曲线 | 使用 V3 把对象变换烘焙到无权重 `Root` |
| 脊椎或身体局部固定 | 只导出了网格、骨架被隐藏，或未导出完整动作槽 | 明确选择 Armature + 全部网格；验证当前 Action 和回读动作曲线 |
| 武器在旁边竖着 | 看的是 Rest Pose；或武器未绑定到同一骨架 | 先播放动作确认；再检查武器网格、权重和对应骨骼 |
| Studio 导入有感叹号 | FBX 指向丢失的 PNG/TGA | 重新绑定真实贴图；没有源图则导出无贴图材质版 |
| 动画后半段缺失 | 场景结束帧小于 Action 结束帧 | 用活动 Action 的实际范围设置 Bake 起止帧 |
| 附件飘走 | 多根骨链未全部挂到 `Root`，或附件对象未随首帧矩阵冻结 | 处理所有顶级根骨骼，并逐网格做顶点对照 |
| 新文件看起来仍是旧问题 | Studio 中仍在看旧导入实例 | 使用新版本文件名/Model 名称，并删除或隐藏旧测试实例后复测 |

## 本流程的已验证经验

- 当源动作把角色整体位移写在 Armature 对象上时，V3 Root Motion 烘焙可以把行走位移保留到 Studio。
- 当源动作已将位移写入主根骨骼时，不应重复烘焙；保留骨骼曲线才是最小、最稳定的修复。
- 带多个独立根骨链的角色必须整体接入 `Root`，并使用逐网格顶点对照验证，而不是只看某一根骨骼是否存在。
- 贴图文件缺失是资产来源问题，不是 FBX 动画问题；无贴图降级版可以消除导入阻塞，但不能替代原贴图。
