# Roblox 通用游戏素材道具制作工作流

## 当前版本

- 版本：v1.3
- 状态：Review
- 当前用途：批量制作干净、稳定、适合图生 3D 的 Roblox RPG 低模道具参考图。
- 最短执行入口：[[快速执行卡_QUICK_START]]

v1.3 的主要变化：

1. 默认美术目标改成“Roblox 风格低模，但不粗糙”。
2. 三份重复合同合并为一份 `资产锁_ASSET_LOCK.md`。
3. 新运行只强制保留资产锁、运行状态和归一化配置；详细旧文档继续兼容。
4. 普通道具只保留两个人工确认点：正视图确认、最终联系表确认。
5. 精确组件计数只用于真正影响身份的零件，不再强迫统计每片装饰花瓣、裂纹或光斑。

## 生产目标

优先级：

```text
干净可用 > 轮廓清晰 > 低模结构 > 跨视图一致 > 材质分区 > 装饰细节
```

“低模但不粗糙”在本流程中表示：

- 用少量清楚的大形体构成轮廓、厚度和连接关系。
- 只把影响剪影、体积、连接或材质分区的内容做成几何体。
- 花纹、细裂纹、叶脉、微小高光优先交给贴图或材质，不堆成碎几何。
- 表面使用宽阔平面、干净曲面和受控倒角；避免随机三角切面和密集晶体碎片。
- 结构简单，但边缘、层次、厚度和材质交界必须清楚。

以下不是本流程想要的低模：纸片厚度、基础几何体拼凑、随意削面、锯齿轮廓、过多尖刺、密集嵌套花瓣、写实透明玻璃和高频噪点。

## 适用范围

适合武器、法器、消耗品、装备、宝箱、祭坛、工作台、家具和小型机关。角色整身、软体布料、毛发、大场景和宣传插画不走本流程。

## 视图数量

| 视图集 | 内容 | 使用条件 |
|---|---|---|
| 4 视图 | front / back / left / right | 结构简单，正面和侧面足以说明体积 |
| 6 视图 | 加 left45 / right45 | 分层、厚度或前后关系需要 45° 过渡证据 |
| 8 视图 | 再加 top / bottom | 顶底结构重要且有可靠证据 |

不要为了凑数选择更多视图。当前“炼狱红莲”和“幻彩之莲”按用户已确认的六视图规格执行，因为花瓣层次需要 45° 深度桥。

## 两个人工门

### 门 1：正视图确认

先只生成一张正视图。它必须：

- 是单一道具，完整、不触边、无 UI、文字、角色和场景特效。
- 已经符合 Roblox 低模目标，不能等到多视图阶段再简化。
- 轮廓、主要结构块、厚度暗示和主色区清楚。

用户明确确认后，才把该图作为设计锁继续扩图。

### 门 2：联系表确认

其余视图完成并归一化后，只展示一张联系表给用户总审。用户确认后才进入正式上传目录。

## 最小生产路径

```text
源图
  -> 低模正视图候选
  -> 用户确认正视图
  -> 用户确认左右侧向可见性合同
  -> 生成独特视图
  -> 仅按用户明确授权复用 / 镜像
  -> 自动归一化与联系表
  -> 用户确认联系表
  -> 正式上传目录
  -> 3D 结果反馈
```

### 1. 写一页资产锁

只记录会改变结果的内容：

- 资产身份、用途和视图集。
- `left/right` 各自必须看见、必须隐藏的结构；必要时也记录 `left45/right45`。
- 一句话剪影、主要结构块、厚度关系和材质区。
- 哪些细节保留为几何，哪些降为贴图 / 材质，哪些直接删除。
- 允许推断的背面结构和不能凭空发明的结构。
- Roblox 目标尺寸；未知时写 `SCALE_UNCONFIRMED`。

重复装饰不默认做逐片精确计数。只有数量本身是识别特征、接口合同或玩法信息时，才写成硬数量。

### 2. 生成正视图

正视图提示词只需要五件事：同一物品、低模造型、主要结构、主要材质、正交相机。避免把整份检查清单塞进提示词。

### 3. 扩展多视图

- 所有视图只旋转物体，不重新设计。
- 侧视必须是真 90°；45° 只做水平旋转。
- 生成任何侧视或对应 45° 视图前，Codex 必须主动询问并复述 `left/right` 各自必须看见、必须隐藏的结构。
- 如果命名容易混淆，先以“侧面 A / 侧面 B + 相机方向 + 可见结构”确认，再映射文件名。
- 不把“是否对称”作为默认问题，也不从正视图自行判断是否可镜像。
- `left/right` 分别按各自合同生成；只有用户明确授权共用同一几何时，才可本地镜像，并记录授权和来源。
- 背面证据不足时使用简单、合理的封闭结构，不增加新的视觉主题。

### 4. 自动归一化

归一化只处理整体等比缩放、居中 / 接地和补边。它不能修复结构、相机和轮廓错误。

v1.3 建议初值：

- 正常波动容差：`5%`。
- 自动整体修正上限：`12%`。
- 超过上限：只重做异常视图。

详见 [[NORMALIZATION_CONTRACT]]。

### 5. 联系表与交付

本地最终化先停在 `FILES_READY`，输出待审核目录和联系表。人工确认后运行审批脚本，状态才进入 `CONTACT_SHEET_APPROVED`。

```text

│  ├─ 运行状态_RUN_STATE.md
│  └─ 归一化配置_NORMALIZATION_CONFIG.json
├─ _候选图_Candidates/
├─ 01_已通过视图_Accepted_Views/
├─ _检查_Checks/
├─ 00_待审核上传_Staged_Upload/
└─ 00_正式上传_Hunyuan_Tripo/
```

`提示词记录_PROMPTS.md` 只在批量复用、修复失败或需要追踪提示词时添加。旧版的资产简报、身份锁和结构锁仍可读取，但新运行不再要求重复填写。

## 自动门与保留边界

以下门保留，因为它们直接防止错误交付：

- Accepted 目录必须真实包含所选 4 / 6 / 8 张图。
- 待审核图必须统一画布、文件名和 SHA-256 清单。
- 未确认左右侧向可见性合同，不得生成侧视或发布完整视图集。
- 用户已明确授权镜像时，镜像图必须来自本地确定性翻转，并记录来源。
- 90 秒无完成或新输出时报告 `GENERATION_STALLED`，停止静默等待，不自动重复提交。
- 机械处理只能到 `FILES_READY`；没有人工确认不能生成正式上传目录。
- 完成后必须回显运行目录、待审核 / 正式目录和联系表路径。

详细失败代码只在出现问题时查阅 [[FAILURE_CODES]]，不作为每次生图的必读提示词。

## 本地最终化

```powershell
& ".\scripts\Finalize-PropMultiview.ps1" `
  -RunDir "{RUN_DIR}" `
  -ViewSet Six `
  -CanvasWidth 1536 `
  -CanvasHeight 1024 `
  -BackgroundColor "#D7D7D7" `
  -ApprovedMirrorPairs # 仅在用户明确授权 right<-left 与 right45<-left45 时填写
```

联系表确认后：

```powershell
& ".\scripts\Approve-PropMultiview.ps1" `
  -RunDir "{RUN_DIR}" `
  -Decision CONTACT_SHEET_APPROVED `
  -ApprovedBy "human" `
  -ApprovalNote "同一物品、低模结构、比例和相机已确认"
```

## 图像生成状态规则

- 任务进行时，用户侧静默不得超过 45 秒。
- 连续 90 秒没有完成或新输出：停止等待、报告当前视图和 `GENERATION_STALLED`。
- 只扫描原任务、生成目录和运行目录一次；不自动重复提交。
- 每个视图最多一次初始生成和一次针对性修复。

## Workflow Check

- Missing gate：保留正视图确认、Accepted 完整集、归一化、联系表确认和 90 秒熔断。
- Removed redundancy：新运行把三份设计合同合并为一份资产锁，提示词日志改为按需。
- Manual/automatic boundary：用户确认正视图、左右侧向可见性合同和联系表；生成、获授权后的镜像、归一化和清单由工具处理。
- Verification evidence：联系表、归一化报告、SHA-256 清单、脚本回归测试和实际 3D 结果。
- Handoff impact：下一对话只需要读取快速执行卡、交接文档和两张原始卡面。
