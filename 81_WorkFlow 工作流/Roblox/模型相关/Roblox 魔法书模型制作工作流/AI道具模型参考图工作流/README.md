# AI 道具模型参考图工作流

这是一套通用的 Roblox 道具 image-to-3D 参考图工作流。

它适用于：

- 魔法书
- 武器
- 宝箱
- 药水瓶
- 装备道具
- 其他闭合、单体、可建模的 Roblox RPG 道具

不适合直接用于：

- 角色整身
- 大型场景
- UI 图标
- 宣传插画
- 需要复杂骨骼绑定的模型

## 核心原则

```text
工作流只规定方法，不绑定某个项目路径、某个等级批次或某个具体道具。
```

一次具体任务可以有自己的输出路径，但输出路径不应写死进工作流规则。  
工作流文档只使用变量：

```text
{PROJECT_ROOT}
{OUTPUT_ROOT}
{ASSET_TYPE}
{ASSET_NAME}
{VIEW_NAME}
```

## 目标

让 Tripo / 混元 AI / 3D Studio 等 image-to-3D 工具更容易理解道具的真实结构，而不是只生成一张好看的图标。

优先级：

1. 结构清楚
2. 视角稳定
3. 材质分区明确
4. 零件可解释
5. 最后才是华丽程度

## 标准目录结构

具体项目自行决定 `{OUTPUT_ROOT}`。推荐结构：

```text
{OUTPUT_ROOT}/{ASSET_NAME}_参考图/
  design_lock.md
  front.png
  back.png
  left.png 或 spine_left.png
  right.png 或 page_edge_right.png
  top.png
  bottom.png
  left45.png
  right45.png
  orthographic_preview_contact_sheet.png
  reference_preview_contact_sheet.png
  reference_notes.md
  failure_log.md
  失败对照/
```

说明：

- 书本类道具可以使用 `spine_left.png` 和 `page_edge_right.png`。
- 武器类道具可以使用 `left.png` 和 `right.png`。
- 其他道具按真实结构命名，但必须能表达六个正交方向。

## 固定视图标准

前 6 张是正交参考图：

| 视图 | 文件名建议 | 目的 |
|---|---|---|
| 正面 | `front.png` | 主视觉、主要结构、核心识别点 |
| 背面 | `back.png` | 背部结构、背面材质、背面连接点 |
| 左侧 | `left.png` / `spine_left.png` | 左侧厚度、连接方式、书脊或刀背等结构 |
| 右侧 | `right.png` / `page_edge_right.png` | 右侧厚度、页边、刀刃、瓶壁等结构 |
| 顶部 | `top.png` | 顶部厚度、边缘、开口或页层 |
| 底部 | `bottom.png` | 底部厚度、接地面、封底或底座 |

后 2 张是辅助建模图：

| 视图 | 文件名建议 | 目的 |
|---|---|---|
| 左 45 度 | `left45.png` | 解释正面和左侧之间的厚度关系 |
| 右 45 度 | `right45.png` | 解释正面和右侧之间的厚度关系 |

### 结构端点语义

生成顶部、底部或长边视图前，必须先定义：

```text
{CLOSED_END}：允许闭合、包覆或连接的结构端
{OPEN_END}：必须保持开放、可辨认内部层次的自由端
```

这两个变量由资产真实结构决定，不绑定某一类道具。对闭合书本：

```text
左端书脊 = {CLOSED_END}
右端页口 = {OPEN_END}
```

书本顶部和底部视图中的右侧纸页必须一直延伸到开放端。上下封面的护角可以分别存在，但不能彼此连接成 U 形、C 形端框、竖向端板或跨页金属桥。任何把页口封死的结构都属于一票否决。

## 相机与遮挡硬规则

图像模型不会真正建立三维相机，单写 `orthographic` 不能保证几何正确。每个视图还必须声明：

```text
相机偏航角 yaw
相机俯仰角 pitch
相机翻滚角 roll
允许出现的可见面
必须被遮挡的远侧面
```

默认安全配置：

| 视图类型 | 相机配置 | 允许看到 | 必须隐藏 |
|---|---|---|---|
| 严格正面 | yaw 0 / pitch 0 / roll 0 | 正面 | 大面积左右侧面、顶部、底部 |
| 右前辅助视图 | yaw 约 30 / pitch 0 / roll 0 | 正面、右侧 | 左侧、顶部、底部 |
| 左前辅助视图 | yaw 约 -30 / pitch 0 / roll 0 | 正面、左侧 | 右侧、顶部、底部 |
| 右上辅助视图 | yaw 约 30 / 轻微俯视 / roll 0 | 正面、右侧、顶部 | 左侧、底部 |
| 左上辅助视图 | yaw 约 -30 / 轻微俯视 / roll 0 | 正面、左侧、顶部 | 右侧、底部 |

一票否决规则：

```text
同一张图不得大面积展示一对相反表面：
左侧与右侧不能同时出现；
顶部与底部不能同时出现。
```

曲面或凸出结构可以在远侧轮廓露出极窄边缘，但远侧完整装饰、宝石、锁扣或侧板不得被“翻出来展示”。

### 单相机可见面清单

生成每张辅助视图前，必须先填写：

```text
主表面：
近侧面：
远侧面：
允许可见面：
必须遮挡面：
远侧面最多允许露出的内容：极窄轮廓 / 无
```

生成后不能只判断“像不像 3/4 视图”，必须逐项核对：

1. 远侧面是否形成独立、连续的材质带或侧板。
2. 远侧面是否出现完整宝石、锁扣、轴套、护板或其他自包含装饰。
3. 画面是否同时存在两个相反侧面的独立厚度区域。

任意一项为“是”，即使 Prompt 写了 `orthographic`，也必须判定为单相机失败并重生整张。

对书本右前辅助视图，左侧完整书脊、圆柱轴套、书脊宝石或多段书脊绑带均属于失败；左边最多只能看到前封面的极窄转角。

`left45.png` 和 `right45.png` 是历史文件名。对结构复杂的资产，允许使用更安全的约 30 度偏航角，不必为了名字强行达到 45 度。角度服务于结构可信度。

## 执行流程

### 1. 写资产 Brief

不要直接开始出图。先写清楚：

```text
资产类型：
目标风格：
适用游戏：
核心识别点：
材质分区：
禁止内容：
最终用途：
```

### 2. 效果图确认与设计锚定

需要先确认外形时，可以生成一张 `effect.png`。它只用于确认配色、轮廓、核心识别点和装饰层级，不是正式建模视图。

效果图必须满足：

- 单相机，正面为主。
- 最多只允许一个近侧面。
- 不得同时展示左右或顶部/底部相反表面。
- 不得使用场景、粒子或强光效掩盖结构。
- 所有凸出装饰必须能判断其固定底座。

效果图确认后，先填写连接层级：

```text
L0 主体：封面、背面、书脊、页块
L1 基础：金属边框、宽底座、角部固定座
L2 浮雕：翼片、齿轮、轨道、角、装甲板
L3 核心：宝石、棱晶、嵌入式发光件
```

L2 和 L3 必须通过 L1 连接到 L0。无法说明连接路径的装饰应删除、合并或降低凸出高度。

效果图通过后，必须在 `design_lock.md` 同时冻结两类信息：

```text
视觉 DNA 锁：
- 造型语言
- 材质语言
- 主色 / 辅色 / 核心色
- 装饰密度
- 块面大小
- Roblox 游戏资产质感

几何锁：
- 主轮廓比例
- L0-L3 连接层级
- 关键零件清单与数量
- 每个零件所属表面
- 正面与背面凸起高度
- 开放端 / 闭合端语义
```

效果图只提供视觉与设计身份，不提供正式相机关系。后续任何视图都不得继承效果图中的透视、侧面宽度或顶部曝光。

#### 零件清单与表面归属

复杂资产必须为关键零件建立稳定 ID：

```text
P01 中央核心：1 个，属于正面，L3
P02 左侧装甲组：1 组，属于正面，L2
P03 右侧装甲组：1 组，属于正面，L2
P04 书脊箍带：3 道，属于左侧，L1
```

每生成一张图都要核对数量。不能把同一零件复制到背面、远侧面或上下两条封面轨道。

### 3. 决定视图命名

根据资产类型选择侧面命名。

示例：

```text
书本：spine_left / page_edge_right
武器：left / right
宝箱：left / right
药水瓶：left / right
```

命名要服务建模理解，不要为了套模板牺牲语义。

### 3.1 侧向可见性确认门

生成任何 `left/right` 或对应的 `left45/right45` 前，Codex 必须主动询问并复述：

```text
左侧输出必须看见什么、必须隐藏什么？
右侧输出必须看见什么、必须隐藏什么？
```

对单侧结构记录数量、位置、顺序和遮挡关系。如果文件名含义容易混淆，先用“侧面 A / 侧面 B + 相机方向 + 可见结构”确认，再映射正式文件名。不要让用户只回答“是否对称”，也不要从效果图或 `front.png` 自行推断另一侧。

未确认时停止侧视生成并记录 `SIDE_VISIBILITY_CONTRACT_MISSING`。镜像或复用只在用户明确授权两个输出共用同一几何时允许，并记录来源；否则记录 `UNCONFIRMED_SIDE_MIRROR`。

### 4. 先校准严格正面

先把已确认效果图重构为 `front.png`：

- yaw 0 / pitch 0 / roll 0。
- 只显示正面，不显示书脊、页边、顶部或底部。
- 保留效果图的配色、轮廓和连接层级。
- 删除效果图因斜角展示产生的侧面信息。

严格正面没有通过前，不生成其他视图。

### 5. 再生成其余 5 张正交图

正交图必须先通过自检，再生成 45 度图。  
如果正交图之间已经冲突，45 度图只会把问题放大。

左右侧视分别遵守已确认的可见性合同。相机角度正确但显示了另一侧专属结构，仍判定为 `SIDE_VISIBILITY_CONTRACT_BROKEN`。

### 6. 再生成 2 张 45 度图

45 度图只用于解释厚度和连接关系，不用于做宣传展示。

要求：

- 不强透视
- 不广角
- 不裁切
- 不增加正交图没有解释过的新零件
- 不用复杂光效掩盖结构
- 明确近侧面和远侧面，远侧面必须被主体遮挡
- 默认 pitch 0，不显示顶部和底部；确需俯视时只允许顶部出现

### 7. 生成联系表

必须有两个预览：

```text
orthographic_preview_contact_sheet.png
reference_preview_contact_sheet.png
```

用途：

- 第一张只看 6 个正交方向是否互相解释。
- 第二张看完整 8 图是否同一资产、同一比例、同一结构。
- 同时核对 `design_lock.md` 中的关键零件数量和表面归属。

#### 联系表生成前的文件规格门禁

- 8 张正式图必须使用同一画布比例和同一目标尺寸。
- 正方形项目默认统一为 `1:1`；不允许把横图或竖图直接拉伸进正方形格子。
- 源图尺寸不一致时，只允许等比缩放并补白边，或重新生成；不得改变物体长宽比。
- 联系表绘制必须保持每张图原始宽高比。
- 失败图、候选图和原始比例备份必须放入单独子目录，不得混入正式 8 图文件名。
- 生成联系表后再次自动读取 8 张正式图的尺寸；存在缺图或尺寸不一致时，不进入下一件资产。

### 8. 自检和修正

按 `CHECKLIST_8视图自检.md` 检查。

发现问题时：

```text
只修有问题的视图，不无意义重做全套。
```

失败图必须立即移入 `失败对照/`，并在 `failure_log.md` 记录：

```text
失败视图：
失败代码：
实际像素问题：
误导 3D 的风险：
重生时唯一需要改变的条件：
```

正式文件名只能指向已经通过人工可见内容检查的版本。Prompt 写对了不等于图片通过。

### 9. 写 reference_notes.md

每个资产输出目录都要有说明文件，至少包括：

```text
资产目标
8 张图分别提供什么建模信息
本次修正了哪些图
仍然存在什么风险
是否适合继续用于 image-to-3D
```

### 10. 单资产闭环

批量资产必须逐个完成：

```text
效果图确认
-> front 校准
-> 6 张正交图
-> 2 张辅助图
-> 联系表
-> 自检与修正
-> reference_notes
-> 下一件资产
```

不允许同时生成多件资产的同名视图后再统一检查，这会增加设计串线和漏检概率。

### 11. image-to-3D 测试后反查

3D 结果如果出问题，不要先怪 3D 工具。先反查参考图：

```text
模型哪里错了？
哪张图可能给了错误信号？
是不是某个侧边、顶部或 45 度视图误导了厚度？
是不是有无法解释的零件？
```

## 解耦规则

工作流禁止写死：

- 固定项目路径
- 固定 Level 批次
- 固定资产名称
- 固定工具账号或平台
- 固定输出目录
- 只适用于某一本魔法书的规则

工作流允许写：

- 通用变量
- 资产类型差异
- 检查标准
- 失败模式
- 修正策略
- 案例经验，但必须标明“案例”，不能作为主流程依赖

## 常见失败模式

| 失败现象 | 常见原因 | 修正策略 |
|---|---|---|
| 侧边长出无法解释的块 | 参考图里有假扣件、贴片、浮动硬件 | 删除或简化该零件 |
| 顶部材质错误 | 45 度图把顶部画成封皮或金属块 | 重做顶部和 45 度图，明确材质 |
| 厚度被拉宽 | 侧视图太厚或 45 度透视太强 | 重做侧视图和 45 度图 |
| 3D 只像图标 | 背面、侧面、顶部信息不足 | 补齐正交图，不靠单张图生成 |
| 细节糊成噪声 | 装饰过密或材质分区不清 | 降低装饰密度，强化大块面 |
| 正面、左侧和右侧同时完整出现 | 图像模型把多个视图拼成伪 3D | 固定近侧面，遮挡远侧面，按可见面矩阵重生 |
| 顶部和底部同时出现 | 相机关系不成立或图标式构图 | 固定 pitch，只保留一个垂直方向表面 |
| 开放端被护角或端板封死 | 只检查了材质，没有检查结构端点语义 | 保留分离护角，删除跨接件，让开放端的内部层次延伸到边界 |
| 箍带、晶体或装甲数量漂移 | 没有关键零件清单，生成时逐图重新发明 | 按 `design_lock.md` 的零件 ID 和数量重生偏离视图 |
| 顶部/底部两条轨道都出现正面浮雕 | 没有声明正面与背面的轨道归属 | 只允许正面轨道显示高凸轮廓，背面轨道保持低平 |
| 端盖额外长出晶体、窗或尖刺 | 端盖语义不明确，模型自动补华丽结构 | 端盖写成实体块并锁定附加零件数量为 0 |

## 文件说明

- `README.md`：通用执行流程。
- `CHECKLIST_8视图自检.md`：视图级质量门禁。
- `PROMPT_TEMPLATES.md`：通用 Prompt 模板。
- `STATUS.md`：当前迁移状态和维护记录。
- `EFFECT_TO_8VIEW.md`：效果图转完整 8 视图的单资产闭环门禁。
- `DESIGN_LOCK_TEMPLATE.md`：视觉 DNA、几何、零件数量与表面归属锁定模板。
