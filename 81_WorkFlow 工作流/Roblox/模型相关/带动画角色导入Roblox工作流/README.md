# 带动画角色导入 Roblox 工作流

把已有网格、贴图、骨骼和动画的角色导入当前目标 Studio 场景；仅在不兼容时经过 Blender 整理。动画、角色控制和性能按用户本次要求验收，不默认扩展为完整打包交付。

**本流程来自可丽案例：已完成本地导出、FBX 回读和 Studio 导入预览；尚未完成最终导入、游戏内播放和手机实测。** 不把“文件能预览”写成“角色已经能在游戏里流畅使用”。具体文件、数据和未完成项见 [[01_可丽案例与验收记录]]。

## 默认执行规则：直接导入，不额外另存

依据 2026-08-28 用户反馈修订；以下规则适用于后续执行，案例页保留当时的操作事实。

- **最短路径：检查当前场景和目标模型 → 必要转换 → 直接导入 → 检查结果 → 完成。** 已导入就复用，不重新导入、上传或创建重复模型。
- 默认不新建测试场景、不 Save As `.rbxl`、不自动保存或发布项目、不在 `ServerStorage` 堆放备份，也不每次建立新版本目录。保存、备份和打包只有用户明确要求时才执行。
- 保留用户原 ZIP、FBX、贴图不覆盖，不等于再复制整套资源。已有可用 FBX 就直接用；确需转换时只生成必要的派生 FBX/贴图。角色模板及出生实例属于功能需要，不额外复制成备份。
- 只修改本次目标对象；正常改动优先使用 Studio 撤销/变更记录。若必须覆盖未知成果、无法可靠撤销或目标项目不明确，先说明具体风险并确认，不自行通过另存整份项目绕过选择。
- 用户只要求导入：实际对象、外观、比例、贴图和骨架检查完成即结束；要求替换默认角色/待机：接着做对应运行验证。手机性能仅在实际测试后下结论。
- **保存不属于导入验收条件。** 不主动打开保存对话框；保存取消或失败不推翻已完成的导入/运行结果，若用户单独要求保存，则独立报告保存状态。未保存改动仍留在当前场景，不关闭窗口；持久化风险简短说明一次，不反复催促。

## 1. 先选对流程

- 已有完整蒙皮和动画，想先保留原动作：走本页的 **Custom Rig** 路线。
- 从参考图生成 Roblox R15 外壳：走 [[../Roblox角色模型/README|Rig 比例锁定与 15+ 分件 Tripo 工作流]]；它不等于已有骨骼动画的转换。
- 静态武器、魔法书等道具打包：走 [[../Roblox 可直接导入版打包流程/README|静态模型打包流程]]。不能未经验证，把该流程的网格合并、贴图规格和脚本直接套给蒙皮角色。
- 要替换标准 R15 玩家、兼容默认动作或发布商城 Avatar：另立骨架适配与 Avatar 验收任务；仅改骨骼名字不是重定向。

触发输入：角色 ZIP、FBX、Blend 或目录；目标平台和角色用途；希望保留的动作与表情。缺少手机型号、同屏数量和目标帧率时，可以先做兼容性基线，但不能承诺性能。

## 2. 工作流与验收阶段

```text
检查源文件与当前场景
├─ 已导入目标模型 → 检查并复用
├─ 已有兼容文件 → 当前场景预览 → 最终导入 → 检查结果
└─ 需要转换 → Blender 整理 → 必要 FBX 导出与回读 → 当前场景导入
导入检查通过 → 完成；仅按本次要求继续动画/控制或性能验收
保存 / 另存副本 / 发布 / 打包：用户另有明确要求才执行
```

| 阶段 | 执行者与输入 | 用户可见结果 / 证据 | 允许推进的条件 |
| --- | --- | --- | --- |
| G0 源检查 | 读取原文件或检查已导入对象，不覆盖源文件 | 完整角色、贴图和骨骼；按需检查动作 | 本次所需内容齐全 |
| G1 导出（需转换时） | Blender 中整理本次工作数据 | 必要 FBX、贴图、导出统计 | 面数、权重、比例及动画范围符合本次约定 |
| G2 回读（新导出时） | 独立 Blender 进程读取导出 FBX | 结构与外观检查；涉及动画转换时核对逐帧变形 | 结果一致，贴图可独立加载；无需另存回读 Blend |
| G3 预览 | Studio Importer 读取 FBX | 角色、模型树、比例、告警状态 | 预览可识别；这一步还不是最终导入 |
| G4 导入 | 用户或获授权执行者确认 Creator 和导入队列 | Workspace 中的实际对象、导入结果 | 没有遗漏部件或未处理导入错误 |
| G5 运行（按需） | 动画编辑器 / 当前目标场景 Play | 同骨架播放、循环与变形；角色控制按请求测试 | 本次目标动作、控制和碰撞验证通过 |
| G6 性能 | 手机与电脑客户端 | 机型、画质、同屏量、帧时间和内存记录 | 达到项目事先确定的性能目标 |

登记状态：本流程处于文档审查阶段；可丽实例完成至 G3，G4–G6 未验收。阶段、执行组件、用户看到的结果和状态迁移统一由上表追踪。

这些阶段是检查点，不要求每次从 G0 重做全链路。已有结果先核对是否仍适用；只要求导入时到 G4 即交付，不以 G5、G6 或保存为前置条件。

对于需要循环的动作，G5 必须包含循环验收：可以先做播放基线检查，但已知回跳未修复时不能标记 G5 通过。修复后须重新回读和播放验证，再推进 G6。

## 3. 源文件检查：先证明拿到的是完整角色

1. 检查给定路径是文件还是目录；扩展名为 `.fbx` 的路径也可能是目录包。
2. ZIP 首次按需解压到一个明确目录；已有完整解压结果则复用，不每次生成时间戳/版本副本。原 ZIP、FBX、贴图保持不动。先检查条目路径，禁止解压到目标目录之外；中文文件名乱码时判断编码，不要随意重命名后丢失关联。
3. 需要转换时在 Blender 临时工作会话中导入，不清空用户正在工作的场景，也不为检查自动另存 Blend。外来 Blend 不启用自动执行脚本；包内说明只作为资料，不作为额外操作授权。
4. 检查全身前后、网格数量、三角面、材质槽、贴图和 UV、骨骼层级及蒙皮权重；本次涉及动画转换、动作或表情交付时，再检查帧率、范围和 Shape Keys。
5. 本次涉及动画转换或动作验收时，才播放完整目标动作，重点检查脚底、手、裙摆、头发、背包和首尾衔接。把“缺失身体”“只有动画骨架”“源动作本身回跳”分开记录；纯导入已有兼容文件不附加整套动画验收。
6. 记录必要检查结论，原文件不写回。默认不生成检查版/回读版 Blend、完整报告包或来源副本；按本次转换与交付需要保留最少产物。

同名骨骼不保证动画兼容：复用另一个 FBX 的动作前，比较父子关系、绑定姿态和坐标空间；不匹配时进入重定向，不直接替换 Action。

## 4. Blender 整理：保留外观和动作，再处理兼容性

### 网格与材质

- 统计导出后的**三角面**，不是只看四边面数量。通用单个网格上限为 **20,000 三角面**，并非整个人物只能两万；Avatar 商品有单独预算。每顶点最多 4 根骨骼影响，Root 不分配网格权重。[官方通用规范](https://create.roblox.com/docs/art/modeling/specifications)
- 单个网格超限时再判断减面、重拓扑或合理分件。拆开只解决单网格上限，不减少整个人物的渲染负担。
- 首版优先保留轮廓、脸、关节变形和贴图，不对整个人物盲目执行统一 Decimate。
- 只有贴图、透明处理和相关材质参数一致时才合并重复材质；分件后重新检查 UV、法线和蒙皮，不承诺“材质槽数量 = 最终 Draw Calls”。
- 贴图使用可追踪的简单文件名，保留 alpha。修 UV 前先判断是错误还是有意平铺，不把所有越界 UV 一律钳制到 0–1。
- 第一版不自动替换贴图、虚构 PBR 或缩图。原游戏着色器不一定能直接迁移；可丽案例只重建基础颜色材质。

### 骨骼、比例与动画

- 在绑定姿态下统一网格、骨架和动作的坐标转换。不要只缩放网格，也不要把姿态旋转清零当成“应用变换”。
- 采用本案例约定时：Blender `Unit System=None`，单位缩放 1；角色在 Blender 中朝 `-Y`、`Z` 向上；导出 `Z Forward / Y Up`，Studio 使用 `Stud`。不要叠加另一套 `0.01` 补偿。[官方单位与朝向说明](https://create.roblox.com/docs/art/blender)
- 目标身高由项目决定。可丽使用 5.5 studs，**不是 Roblox 对所有角色的固定要求**。
- 必要时增加原点处、无网格权重的 Root，保留原骨架的父子关系。没有直接权重的骨骼仍可能是必要父级，不能一键删除。
- 在本次工作数据上烘焙骨骼动画，不写回原文件。只移除经确认的固定位置偏移；保留动作内部相对位移。是否做原地循环是另一个决定，不能默认抹掉根运动。
- Shape Key 表情单独列入保留清单。可丽首版冻结了首帧笑脸，未导出眨眼；这不是通用表情转换方案，也不表示所有表情在 Roblox 都不受支持。

## 5. FBX 导出设置

下面是本案例使用并经回读验证的配置；更换模型、骨架或 Blender 版本后仍须重新验收。

| 设置 | 本路线的值 |
| --- | --- |
| 导出对象 | 只选择最终 Mesh 和 Armature，不含相机、灯光和参考物 |
| Scale / Apply Scalings | `1` / `FBX Unit Scale` |
| Forward / Up | `Z Forward` / `Y Up` |
| Apply Transform（实验性空间烘焙） | 关闭，本案例 `bake_space_transform=False` |
| Add Leaf Bones | 关闭 |
| Only Deform Bones | 关闭，保留必要的无直接权重父级 |
| Armature FBX Node Type | `Null` |
| Triangulate / Smoothing | 三角化；`Normals Only`，回读检查自定义法线 |
| Bake Animation | 动画版开启；绑定姿态静止版关闭 |
| Key All Bones | 开启 |
| NLA Strips / All Actions | 均关闭，只导出当前目标动作 |
| Force Start/End Keying | 关闭；先确保目标首尾帧已有真实采样 |
| Sampling Rate / Simplify | `1` / `0` |
| Path Mode / Embed Textures | `Copy` / 开启；另附同内容贴图作补图用 |

基础选项参考 [Roblox FBX 导出说明](https://create.roblox.com/docs/art/modeling/export-requirements)；完整实际参数见案例中的导出脚本与 `export_report.json`。本路线的 FBX 嵌图策略不覆盖其他静态道具流程的 GLB / 外部贴图策略。

每个动作单独命名、单独导出，避免多个 Action 混进一个文件。可丽跑步是 30 FPS、0.8 秒：导出时间轴 0–24，Blender 默认回读显示 1–25，代表相同的 25 个采样点。不能仅凭帧号偏移判断动作损坏，应比较秒数和采样姿态。

## 6. 新转换文件的回读：检查导出结果，而不是只看源 Blend

本节仅用于新转换或修改过的导出文件；已验收且未改变的兼容文件不重复走此链路。回读不要求保存 Blend 或渲染预览文件。

1. 在独立空白 Blender 进程中读取刚导出的 FBX，核对贴图解析来源，避免原工程缓存掩盖缺图；只有排查路径依赖时才按需隔离文件，不默认复制到另一目录。
2. 对照网格、骨骼、层级、材质、贴图、权重和尺寸；本次涉及动画转换时再核对动作帧率和时间范围。
3. 动画/变形转换需做一致性验证时，无减面且拓扑可对应则比较采样顶点与骨骼变换，必要时逐帧全量比较；重拓扑后改用采样表面误差与视觉检查，不能强行逐顶点对应。
4. 从**回读后的 FBX**检查轮廓、破面及本次涉及的动作。默认在视口检查；用户要求预览或诊断确有需要时才渲染文件，并标明来自 Blender，不作为 Studio 运行证据。
5. 检查嵌入图是否实际存在；未改贴图时比较 SHA256。若缩图、烘焙或重绘，记录变更，不能要求与原图哈希相同。
6. 如果提供绑定姿态版，检查它与动画版的绑定网格一致、且没有意外动画。

任何异常先返回对应阶段处理，不把异常报告和旧 FBX 打包成“最终版”。本案例的数值误差是结果，不是所有角色通用的合格阈值。

## 7. Studio 导入预览与实际导入

先确认当前目标 Studio 窗口、项目和界面语言；自动化连接不可用时可以人工操作，但“配置了 MCP”不代表已连接。直接在目标场景执行已授权的导入，不自行新建 Place 或另存整份项目；不改无关对象，不把旧预览当成新验收。

1. 先查目标模型是否已存在；已导入就复用并跳到结果检查。否则选择现有兼容主 FBX；确实是 ZIP 才按需解压。Studio **文件 → 导入（File → Import）**，只选择本次文件。
2. 本路线使用下表。界面名称可能随版本或选中对象变化，以含义和当前官方说明为准。

| 设置 | 值 / 检查点 |
| --- | --- |
| Rig Type | `Custom`，不要强制选 R15 |
| Keep Zero Influence Bones | 开启；保留必要父级，非性能优化按钮 |
| Scale Unit / Scale Factor | `Stud` / `1`，与本次导出约定一致 |
| World Forward / World Up | `Front` / `Top` |
| Import Only As Model | 开启，将部件组织在一个 Model 下 |
| Merge Meshes | 关闭，保留已验收的分件结构 |
| Set Pivot to Scene Origin | 本案例开启 |
| Uses Cage | 本案例关闭，未制作分层服装围笼 |
| Creator / 导入队列 | 确认资源所属账户或项目群组，只选择本次目标文件 |

3. 检查完整角色、部件树、贴图、朝向、比例与错误提示；记录检查结果，不为预览另存场景。错误标记需展开到具体对象定位。
4. 用户明确要求“导入 Studio”，且目标项目、Creator 和资源范围清楚时，执行该范围内必要的最终 Import，不为同一步反复索要确认。若只要求“导出文件”或“看预览”，停在最终 Import 之前；账户/群组归属或上传范围不明时才询问。`Upload to Roblox` 关闭不能当成保证完全离线的开关；导入授权不等于发布游戏或商城商品授权。
5. 最终导入后检查 Workspace 中实际对象、外观、部件、贴图、比例、骨架和错误。只要求导入时到此结束。若要求替换默认角色/加入待机，再配置目标角色并 Play 验证出生、动作及请求涉及的移动/重生；不重复导入、不默认备份原模型。FBX 含动画，不等于按 Play 就自动变成可控制主角。
6. 报告已完成内容和仍未验证的部分，不主动触发保存/另存/发布。导入结果与保存状态分别记录。

导入器字段和操作入口依据：[Roblox Importer](https://create.roblox.com/docs/studio/importer)。可丽案例实际观测证据见 [[01_可丽案例与验收记录#Studio 预览记录]]；该案例未执行最终 Import 和实际对象验收，不能代表其他角色的当前状态。

## 8. “能用且不卡”的后续验收

先保留画质基线；性能优化必须有对照，不能只凭三角面数判断。绘制调用、贴图内存、阴影、动画和同屏对象都可能成为瓶颈。[官方性能优化说明](https://create.roblox.com/docs/performance-optimization/improve)

- 先确定目标手机、电脑、目标帧率、画质档和预计最大同屏角色数。
- 测试空场景基线、1 个角色、目标同屏数量、最重场景；记录平均帧率、帧时间波动、内存、近远镜头和发热后的持续表现。
- 按测量结果做下一版：优先减少不必要材质/透明叠层，再评估贴图尺寸、骨骼与更新开销、减面或远距离低细节版本。
- 每次只改一类因素，保留同镜头前后对比，重新验证变形和循环。不要承诺所有手机同一画质下都流畅。
- 写实观感还需要造型、纹理、材质和光照配合；把风格化角色转成 FBX，不会自动变成参考游戏里的写实人物。

## 9. 失败、恢复与停止条件

| 情况 | 处理与回退 |
| --- | --- |
| 缺身体、贴图或目标动作 | 停在 G0，列出缺项；不靠空骨架或局部模型冒充完整角色 |
| 单网格超限 / 权重超过 4 | 在本次工作数据上修正并回读，不覆盖源文件；权重裁减必须复查关节变形 |
| 尺寸大/小约 100 倍或横躺 | 核对单位、FBX 缩放和导入轴；不叠加随意倍率补丁 |
| 贴图白色、表情黑块 | 检查图像加载、材质映射与 alpha；不要把整个人物设半透明 |
| 骨骼缺失 / 肢体扭曲 | 检查父级、无权重骨骼、绑定姿态与动画空间；返回本次整理步骤 |
| 循环回跳 | 对比源动作和导出动作首尾；先区分源问题与转换问题，再单独修循环 |
| 工具卡住或预览无响应 | 本流程建议：连续 60 秒无进展先记录日志/界面，检查是否仍计算；5 分钟仍无变化再报告阻塞。不是自动强退阈值，勿终止用户未保存的窗口 |
| 网络超时 / 导入结果不确定 | 查询实际队列和已创建资产后再决定是否重试；不盲目连续上传造成重复资产 |
| 同名输出或模型已存在 | 先核对来源、内容与本次用途；可用则复用。必须替换未知成果时先确认，不通过自动新增版本/副本避开判断 |
| 多人同时编辑 / 来源已变 | 暂停冲突写入并核对当前状态，不覆盖他人改动 |
| 部分导入成功 | 记录已生成对象/资产及失败项，只重试明确失败部分；本地撤销不等于删除云端资产 |
| 可选保存被取消或失败 | 不反复点击另存；导入/运行验收仍按实际结果记录。用户明确要求的保存任务单独说明未完成 |

回退原则：不覆盖源文件和未知成果，优先撤销本次明确可撤销的场景改动。不能可靠回退的替换操作先确认方案，备份须明确需要并获授权；不默认创建项目副本。现有副本、失败产物和云端资产不自动删除，清理另按明确范围执行。

## 10. 最小交付与下一次复用

按请求交付，不默认整套打包：

- **导入 / 替换角色 / 加待机**：当前 Studio 场景中的实际结果 + 简短验证结论；不附带另存项目、ZIP 或多套备份。
- **导出可导入文件**：必要主 FBX 和所需贴图；已有合格文件直接复用。BindPose 版、编辑 Blend、视频、完整报告和哈希清单按需提供。
- **明确要求打包、归档或交接**：才整理相应文件和证据，不把完整可丽案例的产物清单当成每次必做项。知识库不重复保存大型模型或工程副本。

需要交接时记录：来源、目标场景/对象、已验证结果、重要变更和限制、未完成项。只有文件身份需要追踪时补哈希；只涉及简单导入时不要另建整套交接文档。实际接收须核对对象/文件，不能只看“成功”字样。

可复制给下一次执行者：

> 将这个角色 [路径] 直接导入当前目标 Studio 场景；已导入则复用。仅做必要转换，不覆盖原文件，不新建测试场景、不另存项目、不额外备份或打包。核对最终对象、外观、贴图、比例和骨架后结束；只有本次同时要求替换角色、动画或性能优化时才继续相应验证。目标项目、资源归属或覆盖范围不清楚时再问。不要把预览/本地回读当成 Studio 运行验收，也不要把未保存当成导入未完成。

## Feedback Loop

- Goal: 删除导入任务中自动另存副本、完整打包及无关验收的隐含要求。
- Boundary: 本次只改既有工作流与整理日志；不操作 Studio、不保存场景、不删除已有副本。
- Check used: 对照用户反馈、原工作流与实际操作偏差；检查默认路径、复用/冲突/取消分支、格式和独立只读审查。
- Result: 按本次请求终止流程，保存与导入状态分开；不借文档修订升级任何案例的运行或性能状态。

## Knowledge Capture

- Context/ADR/doc updated: 原工作流 v0.2 与整理日志；沿用既有导航，不新建重复流程。
- Handoff needed: 后续执行先读“默认执行规则”，按用户当前请求和当前场景状态选择起止点。
- Follow-up: 下一次实际导入核对有无多余副本、重复导入或保存动作；本次不重新执行模型任务。

## Workflow Check

- Missing gate: 缺少“用户要求完成即停止”的边界，曾把另存场景变成导入收尾条件；现明确剥离。
- Manual/automatic boundary: 已明确的导入与必要调整直接执行；未知目标、冲突覆盖或新增发布范围先确认；保存/备份/打包不自动附带。
- Verification evidence: 本次依据用户反馈和前序操作记录修订；历史可丽证据仍在案例页，未重新验收。
- Handoff impact: 模型已导入就从现有对象继续；历史专用脚本与完整交付清单不是默认任务模板。
- Rule/doc update: 当前场景直导、必要产物、按需验收、保存状态独立；保留原参数和案例事实。
