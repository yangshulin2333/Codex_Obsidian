## 2026-06-06：Meshy 武器低模流程初步验证

### 问题

用户希望把 Meshy 生成的复杂武器控制到 `3000-4000 面`，用于 Roblox。

### 尝试

1. 从 Meshy 生成高模武器。
2. 导入 Blender。
3. 挂颜色贴图预览。
4. 自动降面测试：
   - `4000 面`
   - `3000 面`
   - `4000 面 + Smooth`
   - `8000 面`
5. 对比别人做的参考模型 `1`。

### 结论

1. 当前 Meshy 高模从 `168198 面`压到 `4000 面`后，护手和骷髅区域会变成大三角块。
2. 这不是单纯参数问题，而是源模型不是低模结构。
3. 参考模型 `1` 约 `3946 面`，但效果好，原因是它从源头就是低模资产。
4. 下一步应重新做低模风格参考图，而不是继续修当前高模。

## 2026-06-07：Meshy 导出包转 Roblox 直接可导入格式

### 问题

用户从 Meshy 下载了 `weapon_0011.fbx`，放在：

```text

```

直接导入 Roblox Studio 报错。随后解压出的真 FBX 能导入模型，但 Roblox 卡在：

```text
base_color_texture
上传失败，请稍后一次。如果问题持续发生，请提交错误报告通知我们。
```

### 诊断

用文件头检查发现：

```text
weapon_0011.fbx
```

实际文件头是：

```text
PK
```

结论：这个文件不是 FBX，而是 ZIP 压缩包伪装成 `.fbx`。

解压后内部包含：

```text
Meshy_AI__0606154053_texture_fbx\Meshy_AI__0606154053_texture.fbx
Meshy_AI__0606154053_texture_fbx\Meshy_AI__0606154053_texture.png
```

贴图为：

```text
2048x2048 RGB PNG
```

### 处理

先做了保底方案：

1. 导出 `weapon_0011_no_texture.fbx`，不带贴图引用。
2. 压缩贴图为：
   - `weapon_0011_texture_1024.png`
   - `weapon_0011_texture_1024.jpg`
3. 让模型先进入 Roblox，再手动填贴图。

用户指出：之前工作流可以直接生成可用格式，不希望分开导入。

随后做了直接导入方案：

1. 用 Blender 后台导入真 FBX。
2. 将原始贴图压缩成 `1024x1024 jpg`。
3. 重新创建简单材质并绑定贴图。
4. 导出直接导入版本：
   - `*_direct_1024tex.fbx`
   - `*_direct_1024tex.glb`
5. 保留 `*_mesh_only.fbx` 作为贴图失败时的保底版本。


2. Roblox 导入失败如果卡在 `base_color_texture`，优先处理贴图大小、材质引用和路径。
3. 以后交付优先给用户一个直接可导入的 `*_direct_1024tex.fbx`。
4. `.glb` 作为第二优先级，因为 GLB 对嵌入贴图更稳定。
5. `mesh_only.fbx + 手动 TextureID` 只是最后保底，不作为首选流程。
