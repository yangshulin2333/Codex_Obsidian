# 剑类效果图到多视图 V2

## 定位

这条入口只负责为 Tripo、混元 AI 等 image-to-3D 工具生成剑类图片参考，不负责 FBX / GLB 打包。

通用规则来源：

```text
../Roblox 魔法书模型制作工作流/AI道具模型参考图工作流/
```

这里仅补充剑类语义，不复制或写死具体项目、等级、配色和输出路径。

## 为什么替换旧图片入口

旧流程的有效部分：

- 先锁定一张正面。
- 后续视图必须属于同一把武器。
- 侧视图必须是真实窄侧面，不能压扁正面冒充。
- 旧版曾按“对称/非对称”分流，并在部分情况下默认镜像另一侧；实践证明这会掩盖逐方向可见性差异，现已废止为执行规则。

旧流程不足：

- 效果图与工程视图阶段没有完全隔离。
- 风格锁偏重参考图相似，没有结构化记录系列视觉 DNA。
- 缺少 L0-L3 连接层级、关键零件数量和所属表面。
- 缺少顶部、底部与 45 度连接解释。
- 失败稿隔离和联系表门禁不够统一。

## 默认流程

效果图未确认前，不批量生成正式多视图。

## 剑类视觉 DNA 输入

每次任务填写，不写死：

```text
造型语言：
主色 / 辅色 / 核心色：
金属材质：
宝石或能量材质：
装饰密度：
块面尺寸：
刃面处理：
Roblox 游戏资产质感：
禁止风格：
```

“与某套道具同系列”时，只继承视觉 DNA，不复制原道具轮廓或部件用途。

## 剑类 L0-L3

```text
L0：剑身、剑茎、握柄主体。
L1：护手、剑脊、宝石托座、柄头承力块。
L2：刃面装甲、翼形护手、冠形结构、大块浮雕。
L3：嵌入式晶体、能量槽、核心宝石。
```

规则：

- L2/L3 必须通过 L1 连到剑身或握柄。
- 不允许晶体直接悬浮在刃面外。
- 不允许护手只有正面贴片而没有侧面厚度。
- 长刺、翼板和冠部必须有宽根部。
- 不使用链条、细丝、漂浮碎片和无法从侧面解释的薄饰片。

## 效果图相机门禁

首张效果图建议直接采用近正交正面，减少后续校准损失：

```text
yaw 0
pitch 0
roll 0
主表面：剑的正面
近侧面：无，最多只有刃口极窄厚度
远侧面：背面，必须隐藏
```

剑刃正面轮廓的左右切削边可以同时出现，它们属于同一个正面轮廓；禁止的是同时大面积展示剑的正面和背面。

效果图要求：

- 单把完整闭合武器，竖直居中。
- 纯白或浅灰背景。
- 无人物、手、场景、粒子、烟雾或大面积光效。
- 不做斜放、横放、俯视或广角游戏图标构图。
- 高级感来自大块面、材质和真实凸起，不来自碎刺数量。

## 多视图专项门禁

### XYZ 几何锁与相机取景

生成正式视图前，必须在 `design_lock.md` 定义资产的三个真实轴，并选定一个基准长度：

```text
X：左右宽度
Y：武器长轴
Z：正面到背面的厚度

front/back = X × Y
left/right = Z × Y
top/bottom = X × Z
```

- 先锁定 X:Y:Z 几何比例，再单独决定每张输入图的正交相机取景倍率。
- 同一张图内部的两个投影轴必须等比缩放，禁止横向或纵向单独拉伸。
- 理论同相机尺度可用于检查几何，例如 Y=100、X=34、Z=4.5；它不是平台输入必须遵守的画布占比。
- 轴向图若在缩略图中接近一条线，允许记录一个统一相机放大倍数；建议让长边占画布 `60%-80%`。
- 放大后仍必须保持原 X:Z 比例、平行投影和表面归属，不能重新生成大面积正面。
- `design_lock.md` 必须同时记录理论包围盒、交付包围盒和放大倍数。
- 联系表使用最终交付图片，不在拼图阶段额外改变倍率。

### front / back

- 同一总长、剑刃轮廓、护手宽度、握柄和柄头。
- 背面可以简化纹样，但不能变成另一把剑。
- 正面核心不能无理由复制为背面同样高凸核心。

### left / right

- 生成前，Codex 必须主动询问并复述 `left.png`、`right.png` 各自的 must-visible、must-hidden、方向性结构 P-ID/数量/位置和遮挡关系；用户确认后才能开始。
- 必须是 90 度工程侧视图。
- 剑刃只显示真实厚度与刃口楔形，不保留宽正面刃面。
- 护手只显示前后深度，不保留正面展开宽度。
- 默认分别生成并逐图验收，不以“是否对称”决定是否镜像。
- 只有用户明确授权指定输出对共用几何，且 `design_lock.md` 记录授权原文、输出对与日期时，才允许镜像或复用。
- 合同缺失记为 `SIDE_VISIBILITY_CONTRACT_MISSING`；图像违反合同记为 `SIDE_VISIBILITY_CONTRACT_BROKEN`；未获授权的镜像/复用记为 `UNCONFIRMED_SIDE_MIRROR`。

### top / bottom

- 对竖直长剑，top / bottom 是沿武器长轴观察的轴向端视，不是另一张完整竖剑图。
- `top.png`：相机从剑尖看向柄头；`bottom.png`：相机从柄头看向剑尖。
- 严格平行投影下，剑刃和握柄的纵向可见长度应接近 0，画面应是紧凑的截面叠层。
- 轴向图必须沿用 XYZ 几何锁；允许 X 与 Z 同倍放大以提高平台可识别性。
- 轴向主体长边建议占画布 `60%-80%`；过小可能被平台判为空图，过大则容易裁切。
- 顶/底图只表达 `X × Z`，不得把 `X × Y` 的剑身、护手翼板或晶体正面“压扁后横放”。
- top / bottom 不得出现沿纵深延伸的握柄、剑刃、透视汇聚线或“道路式”长轴。
- 正面宝石、晶体槽和护手晶面不能旋转到轴向端面；完整正面装饰计数应为 0。
- 柄头宝石属于正面时，bottom 的柄头端必须是实体金属端盖，只允许极窄彩色侧边。
- 不新增正面没有登记的尖刺、晶体、箍带或端盖。
- 如果 image-to-3D 平台不支持轴向端视，优先使用 front/back/left/right/left45/right45，不要把错误 top/bottom 强行加入输入。

### left45 / right45

- 生成前，Codex 必须主动询问并复述两张 45 度图各自的 must-visible、must-hidden、方向性结构数量/位置和遮挡关系；不能直接沿用侧视合同而跳过确认。
- 水平相机、低透视。
- 每张只显示正面与一个近侧面。
- 背面完整纹样和相反侧面不得翻出。
- 只解释厚度与连接，不增加华丽结构。
- 整把武器必须作为一个刚体绕长轴旋转；剑刃、护手、握柄、箍环、柄头和嵌件使用同一个 yaw。
- 不允许只有剑身出现侧面，而护手、握柄纹路、中央宝石或柄头宝石仍完整正对相机。
- 45° 时，正面平面装饰应产生一致的横向缩短；近侧厚度必须从剑尖连续到护手和柄头。
- 默认分别生成并逐图验收；镜像或复用只在用户明确授权指定输出对且设计锁留有记录时允许。

## 一票否决

- 生成 `left/right/left45/right45` 前没有经用户确认的逐输出可见性合同：`SIDE_VISIBILITY_CONTRACT_MISSING`。
- 侧向输出违反 must-visible、must-hidden、方向性结构数量/位置或遮挡：`SIDE_VISIBILITY_CONTRACT_BROKEN`。
- 未经用户明确授权而镜像或复用另一侧几何：`UNCONFIRMED_SIDE_MIRROR`。
- 正面和背面同时大面积可见。
- 侧视图仍保留完整正面刃面或展开护手。
- 剑刃厚度接近剑刃宽度。
- 晶体、翼板、冠部或柄头零件漂浮。
- 关键零件数量跨视图变化。
- 45 度图变成斜放游戏图标。
- 45 度图只有剑身侧转，护手或柄部仍以正面贴片朝向相机。
- top / bottom 显示完整剑身长度或强纵深透视。
- top / bottom 使用了未记录的缩放，或 X 与 Z 的放大倍数不一致。
- top / bottom 主体占比过小，在平台缩略图中无法形成可辨认轮廓。
- top / bottom 展开大面积 `X × Y` 正面结构，而不是 `X × Z` 截面。
- 正面宝石或护手晶面被翻到剑尖 / 柄头轴向端。
- 加入人物、手、地面、场景、文字、粒子或强光效。
- 联系表中的任一视图明显像另一把剑。
