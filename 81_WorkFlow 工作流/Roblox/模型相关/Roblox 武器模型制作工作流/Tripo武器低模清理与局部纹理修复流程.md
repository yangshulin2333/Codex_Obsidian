# Tripo 武器低模清理与局部纹理修复流程

## 定位

用于处理已经由 Tripo、混元 AI 或其他 image-to-3D 工具生成、整体可用但存在局部纹理或结构瑕疵的 Roblox 武器模型。

目标不是重新设计武器，而是：

```text
保留已通过的几何、UV 和原始外观
-> 只修明确异常区域
-> 生成 Blender 母版
-> 生成 Roblox 512 导入包
-> 在 Blender 和 Roblox Studio 两次验收
```

本流程不绑定具体武器、材质名、项目目录或输出盘符。

## 路径变量

```text
{SOURCE_PACKAGE}    原始模型包或下载目录
{SOURCE_FBX}        实际 FBX
{SOURCE_TEXTURE}    原始 Base Color
{WORK_DIR}          本次可回滚工作目录
{DELIVERY_ROOT}     最终交付目录
{WORKFLOW_ROOT}     Roblox 武器模型制作工作流目录
```

## 人工与自动边界

| 环节 | Codex / Blender MCP | 用户 |
|---|---|---|
| 原始包识别 | 查找真实 FBX、`.fbm`、Base Color | 确认来源模型 |
| 只读审计 | 检查几何、UV、材质、贴图和选中状态 | 指出肉眼可见瑕疵 |
| 局部修复 | 生成候选、实时切换视角、自检 | 确认保留或回退 |
| 导出验证 | 回导 FBX / GLB，核对面数、UV、贴图 | 无 |
| Studio 验收 | 给出导入顺序和检查清单 | 在目标游戏中导入、判断比例和观感 |

执行 Blender MCP 修改时，用户要求实时观察的情况下，必须直接操作当前可见 Blender 会话。禁止在另一个隐藏 Blender 文件里修改后才告知结果。

## 阶段 0：建立可回滚副本

开始前保存：

```text
原始 FBX
原始 Base Color
原始 .blend 或首次导入副本
```

输出使用新目录和新文件名。没有得到明确指令时，不覆盖 Tripo 原文件。

## 阶段 1：只读拓扑与 UV 审计

先检查，不修改：

- 当前选中的对象是否为目标低模。
- 网格对象数量。
- 顶点数、三角面数和 UV 层名称。
- 材质槽和 Base Color 图片路径。
- UV 是否存在、是否超出预期图集。
- 是否有开放边、非流形面、漂浮碎片或明显穿插。
- 法线方向是否异常。
- 正面、背面、左右侧面、顶面和底面能否互相解释。

记录审计基线：

```text
mesh_count=
vertices=
triangles=
uv_layers=
materials=
base_color=
geometry_modified=false
```

未完成基线记录前，不进行减面、合并、重拓扑或重新展开 UV。

## 阶段 2：先判断问题属于哪一类

### A. 只有显示或材质绑定问题

表现：

- Tripo 中正常，Blender 中发白或贴图缺失。
- TextureID 删除后 Roblox 变白。
- FBX、材质节点或图片路径没有正确关联。

动作：

```text
恢复原 UV
-> 恢复原 Base Color
-> 恢复材质参数
-> 不改几何和 UV
```

### B. 只有局部纹理异常

表现：

- 底盖、底面或少量侧面出现错误颜色。
- 某些 UV 岛采样到了不合理区域。
- 大部分 Tripo 纹理已经可用。

动作：

```text
以原 Base Color 为底图
-> 建立异常面目标遮罩
-> 保护其他 UV 面
-> 只重绘目标像素
-> 补有限 padding
```

禁止重绘整张 UV 图集。

### C. 几何或拓扑问题

表现：

- 轮廓塌陷、穿模、开放边、漂浮件。
- 重要金边或护手只是贴图，没有实体厚度。
- 法线修复后仍有明显几何破面。

这不是纹理修复。应转入独立的 Blender 几何清理或重建流程，不能用 Base Color 掩盖。

## 阶段 3：局部纹理修复合同

修复前必须写清：

```text
Keep：必须保持 Tripo 原样的表面
Edit：允许修改的表面
Drop：需要废弃的旧候选
Add：需要补充的底盖、金属框或晶体信息
Next：本轮只验证哪个视角
```

目标面可依据以下信息组合识别：

- 面法线方向。
- 物体局部坐标范围。
- 连通区域。
- UV 岛。
- 人工确认的面索引或顶点组。

不能只依赖一条宽泛规则。例如，只用“所有朝下的面”可能误伤从侧面可见的斜面。

### UV 写入规则

1. 从原始 Base Color 复制出候选图。
2. 先生成“保留面像素保护遮罩”。
3. 再生成“目标面写入遮罩”。
4. 保护遮罩优先级高于目标遮罩。
5. 只在目标区域写入颜色。
6. padding 只扩展到空白或同目标区域，不能覆盖邻接保留岛。
7. 每次扩大目标范围后，必须重新检查正面、侧面和底面。

## 阶段 4：三视角自检

每轮局部修复至少检查：

### 正面

- 身份特征、主色、金边、晶体没有变化。
- 没有出现新色块、断裂或材质漂移。

### 侧面或 45°

- 原 Tripo 纹理仍连续。
- 没有因为底面遮罩扩大而污染护手、剑根或剑身侧边。
- 斜面不出现突然的纯色补丁。

### 严格底面

- 异常底盖已变成可解释的实体结构。
- 颜色归属与相邻金属、晶体一致。
- 没有脏污采样、随机人脸状纹理或拉伸。

若底面更干净但侧面变差，优先回退目标范围，不接受“底面通过、侧面牺牲”。

## 阶段 5：母版与游戏版

### Blender 母版

建议保留：

```text
{ASSET_NAME}_fixed.blend
{ASSET_NAME}_fixed.fbx
{ASSET_NAME}_fixed_2k.png
repair_report.json
```

2K 用于继续修复和近距离检查，不直接代表 Roblox 最终规格。

### Roblox 默认版

默认：

```text
Base Color：512x512
格式：JPG 或 PNG
单网格单材质优先
保留 UVMap
保留原三角面数，除非另有性能优化任务
```

对于玩家手持、屏幕占比较大的主武器，如果 512 在目标设备上明显糊，再单独测试 1024。不要因为源图是 2K/4K 就直接把高分辨率当作游戏默认值。

## 阶段 6：导出与回导验收

至少输出：

```text
*_direct_512tex.fbx
*_direct_512tex.glb
*_embedded_512tex.fbx
*_mesh_only.fbx
*_texture_512.jpg 或 png
README_import_order.txt
```

导出后必须临时回导：

- FBX 和 GLB 都只有预期网格。
- 三角面数与基线一致。
- UV 层存在。
- 贴图尺寸为 512x512。
- 贴图路径或内嵌图片可解析。
- 回导后视觉没有回到旧纹理。

GLB 回导时顶点数可能因 UV 缝、法线或材质边界拆分而增加；只要三角面数、轮廓和 UV 正常，不应单凭顶点数变化判断几何被重建。

## 阶段 7：Roblox Studio 导入

按优先级：

```text
1. direct 512 FBX + 同目录 512 贴图
2. direct 512 GLB
3. embedded 512 FBX
4. mesh-only FBX + 手动上传 512 贴图
```

首次迭代建议关闭 `Upload to Roblox`，只加入 Workspace 检查；确认无误后再上传资产，避免产生大量废弃 Asset。

Studio 验收：

- 模型完整，没有缺面。
- 正面、侧面和底面与 Blender 一致。
- 贴图不是白色，也没有回到旧版。
- 比例适合角色和场景。
- `CanCollide=false`，展示道具通常 `CanTouch=false`、`CanQuery=false`。
- 手持武器最终使用 Tool / Handle 或项目既有装备系统，不直接依赖导入模型的初始坐标。

## 失败恢复

| 现象 | 优先处理 |
|---|---|
| FBX 贴图上传失败 | 保持贴图同目录，再试 GLB |
| 模型变白 | 检查 TextureID / TextureContent 或 SurfaceAppearance |
| FBX 比 GLB 大很多 | 检查 FBX 缩放元数据，重新走标准打包脚本 |
| 底面修好但侧面变差 | 缩小目标面范围，恢复原 Base Color |
| 纹理修复后 UV 错位 | 回退到原 UV，不重新自动展开 |
| 轮廓或护手破损 | 转几何清理流程，不继续涂贴图 |

## 完成门

只有全部满足才标记完成：

- [ ] 原始资产未覆盖。
- [ ] 几何和 UV 基线已记录。
- [ ] 非目标表面保持原 Tripo 外观。
- [ ] 正面、侧面、底面自检通过。
- [ ] FBX / GLB 回导通过。
- [ ] 512 贴图尺寸通过。
- [ ] Studio 导入和目标游戏内比例通过。
- [ ] 个案写入 `工作记录.md`，主流程不写死个案路径。
