# 01 立项与跨部件设计锁

## 新项目前置门

如果本轮是全新武器，先执行 [[新武器_新对话启动模板]] 的 `NEW_PROJECT_BOOTSTRAP`。必须记录 `run_mode=NEW_PROJECT`、当前输入来源和历史案例隔离状态；猫猫剑、冰晶战锤等案例只能提供流程证据，不能提供拆件数、尺寸、轴向、接口、视图数量或材质预算默认值。

未通过该门时停止并记录 `NEW_PROJECT_BOOTSTRAP_SKIPPED`；发现未经授权继承案例参数时记录 `CASE_PARAMETER_INHERITED_WITHOUT_AUTHORIZATION`。

## 目标

把模糊的武器想法变成可拆解、可生成、可拼接的项目合同。这个阶段不生产正式多视图，也不进入 Blender 精修。

## Gate P0：项目 Brief

从 [[PROJECT_LOCK_TEMPLATE]] 复制 `PROJECT_LOCK.md`，至少确认：

- 使用场景：Roblox RPG、展示、Tool、NPC 掉落物或商店预览。
- 玩家视角与目标风格：风格化、高级低模、写实或卡通。
- 目标平台：Tripo、混元 3D、其他图生 3D；平台允许的视图数。
- 成品总长变量、单位和三角面预算；未知时写 `SCALE_UNCONFIRMED`，不要猜。
- 颜色、材质和识别点；哪些是几何，哪些是贴图，哪些是运行时效果。
- 明确不做的内容。

通过条件：用户明确确认范围和设计方向，状态进入 `BRIEF_READY`。

## Gate P1：完整武器效果图

效果图是拆件和装配比例的共同母版。要求：

- 单把完整武器，完整、不触边、背景干净。
- 优先正视或接近正交的轻微 3/4 展示；另保留严格正视装配参考。
- 不展示角色、手、UI、地面、烟雾、粒子、Trail、光束或大面积泛光。
- 识别点、主配色、部件边界和接口附近轮廓清楚。

用户至少确认：

1. 总轮廓和武器类型。
2. 剑刃/头部、护手/中段、握柄、尾饰等主区域比例。
3. 正面方向和成品主轴。
4. 哪些装饰必须成为几何。

候选命名：`master_effect_candidate_vNN.png`。正式提升后命名：`master_effect.png`，并记录 SHA-256。未确认时记录 `MASTER_EFFECT_NOT_CONFIRMED`。

## Gate P2：部件拆分

### 拆件依据

满足任一条件时考虑独立部件：

- 形体、材质或厚度语言明显不同。
- 需要单独提供多视图，避免 3D AI 把遮挡处粘连。
- 需要在 Blender 独立缩放、位移或旋转。
- Roblox 中需要独立 SurfaceAppearance、运行控制或后续替换。
- 连接处可以被外框、端环、护圈或内部重叠遮挡。

不要为了“看起来专业”过度拆件。每增加一个部件，就增加一套多视图、AI 生成、对齐和贴图维护成本。

### 部件 Manifest

| 字段 | 说明 |
|---|---|
| `component_id` | 固定编号，如 `01`、`02` |
| `role_name` | 稳定英文名，如 `Blade`、`Guard`、`Handle`、`Pommel` |
| `display_name` | 中文名称 |
| `axis_range` | 在整剑主轴上的归一化区间 |
| `visible_length` | 装配后的外露长度 |
| `max_width/max_thickness` | 宽度和厚度包络 |
| `source_connector` | 公插头、母槽、内部重叠或无 |
| `target_component` | 接到哪个部件 |
| `hidden_overlap` | 插入深度或内部重叠 |
| `material_regions` | 主要材质区 |
| `separate_in_studio` | 是否需要独立 MeshPart |

### 装配主轴与坐标

在项目锁中统一定义：

```text
Length：从尾端指向武器尖端
Width：正视图的横向
Thickness：前后厚度方向
Front：哪一外表面面对正视相机
```

不要用 Blender 当前世界坐标替代语义轴。源模型可能旋转或导出轴不同，但语义不能变。

### 比例合同

建议先将整把武器长度归一化为 `L = 1000`，再记录各站位。注意：

- 区段可见长度与零件真实网格长度不是一回事。
- 插头、母槽和内部重叠会使零件真实长度之和大于成品外廓长度。
- `TARGET_LENGTH_STUDS` 是项目变量；只在导出前转换为目标 Roblox 尺寸。
- 非等比缩放只能在用户看过正、侧结果后使用，并记录 XYZ 乘数；不能把它当默认修复。

### 连接合同

每个接口必须从 [[JOINT_CONTRACT_TEMPLATE]] 建立独立 `JOINT_<ID>.md`，并写清：

```text
JOINT_ID：
From component -> To component
共享对位区：形状、比例和位置
中心轴与 FRONT：
最终可见表面所有者：
代理副本所在部件：
接口类型：公插头 / 母槽 / 内部重叠 / 隐藏转接芯
截面：圆 / D 形 / 圆角矩形 / 自定义
插入深度：
隐藏防转结构：D 形平边 / 偏置键 / 缺口 / 无
可见接缝：允许 / 必须隐藏
遮挡件：端环 / 外框 / 无
对齐后删除项：
导出前唯一性检查：
```

设计原则：

- AI 图生 3D 适合生成装饰外壳，不适合保证精密盲孔、贯穿孔和严格公差。
- 两份参考图可显示同一个共享对位区，帮助识别装配位置；它是定位代理，不自动成为两边都要保留的最终表面。
- 两次独立 AI 生成只能近似复现共享对位区，不能证明几何尺寸相同。精确基准、插头、母槽和防转结构必须在 Blender 中量化重建。
- 每个共享可见外壳只能指定一个 `final_surface_owner`；另一部件上的副本标记为 `ALIGN_PROXY_<ID>_DELETE_AFTER_ALIGN`。
- 静态 Roblox 武器优先用 Blender 的简单圆柱、方块或 D 形芯做隐藏连接，允许内部少量重叠。
- 要做可替换零件、真实插拔或打印结构时，另补端视图和剖面图，不把工程孔槽塞进装饰四视图。
- 接口沿整把武器的装配轴，不能按装饰图案的视觉中心开槽。

## Gate P2J：共享对位区与接口合同

P2 拆件后，逐接口检查：

- `JOINT_ID / From / To` 唯一且明确。
- 共享对位区、中心轴和 `FRONT` 已确认。
- 最终所有者、代理副本和对齐后删除项已确认。
- 隐藏防转结构与插入深度已确认。
- 已明确 AI 只提供近似外壳，Blender 负责精确接口。

全部接口的 `joint_contract_gate=PASS` 后，项目才进入 `JOINT_CONTRACT_APPROVED` 并开始正式部件效果图；缺失时记录 `JOINT_CONTRACT_INCOMPLETE`。

## 部件效果图顺序

1. 先确认完整武器。
2. 按从视觉核心到辅助件的顺序逐件生成。
3. 每次只展示一个明确标注的候选文件。
4. 部件图保持整体效果图的材质、颜色和结构，不重新设计成另一把武器。
5. 用户确认后复制到稳定的 `effect.png`；临时生成路径只作来源记录。

## Gate P3：部件效果图确认

每个 `required` 部件必须在 `RUN_STATE.md` 记录：

- canonical `effect.png` 的稳定绝对路径与 SHA-256。
- 用户确认原文与确认日期。
- `effect_gate=PASS`；未开始、处理中、失败分别使用 `NOT_STARTED / IN_PROGRESS / FAIL`。

只有全部 `required` 部件的 `effect_gate=PASS`，项目总状态才进入 `COMPONENT_IMAGES_APPROVED`。`optional / deferred` 必须在 P2 已确认，不能在某个部件生成失败后临时修改。

## P2 验收清单

- [ ] 完整武器效果图已经确认并落盘。
- [ ] 每个部件有唯一 ID、名称和角色。
- [ ] 正面、主轴、宽度轴、厚度轴已定义。
- [ ] 各部件的比例包络和接口对象已明确。
- [ ] 可见长度与隐藏重叠分别记录。
- [ ] 每个接口有独立 JOINT 合同，包含共享对位区、中心轴/FRONT、最终所有者、代理副本、防转、插入深度和删除项。
- [ ] 已声明 AI 只负责近似装饰外壳，精确接口在 Blender 重建。
- [ ] 没有把特效作为部件几何。

拆件通过后进入 `COMPONENT_SPLIT_LOCKED`；全部 P2J 接口合同通过后进入 `JOINT_CONTRACT_APPROVED`。
