# 狼首月牙战斧：视图合同与正式参考集复盘

## 一句话结论

高级武器不应预设每个部件都要四视图或六视图；每个部件必须先锁定用户认可的 `required_final_views`，再用逐图单相机合同生成，并把已确认图与候选/平台输入分开管理。

## 本次可复用事实

- `axe_head` 的正式集是 `front / back / left / right`。狼首是立体主体，侧视必须保留单侧耳朵、眉骨、口鼻、下颚等轮廓，而不是只显示月牙刃厚。
- `axe_handle` 用户明确只要两张：正视与 `Side A`。它没有左右对称授权，`Side A` 保持语义名，不强制改成 left/right；背视保留为历史参考，但不进入本次正式集。
- 严格侧视需要写成可验收的相机合同：`camera_count=1 / ORTHOGRAPHIC / yaw=90° / pitch=0° / roll=0°`。三分之四、透视、拼接或以拉伸伪造的图都应判失败。
- “严格 90°”不等于把实体压扁。尾环、狼首、端面等关键结构仍须呈现真实侧向厚度和局部剪影。
- 全部确认图需要汇总到一个干净项目级目录；候选、联系表、提示词、未选历史图和平台上传包不能混入。

## Flow Map

```text
确认 effect.png
-> VIEW_REDUNDANCY_GATE
-> PART_VIEW_CONTRACT_GATE
   -> required_final_views / not_required_views
   -> 单相机与关键侧向轮廓合同
-> 逐张候选（准确路径）
-> 用户逐图确认
-> 00_formal_model_references（只含确认 PNG）
-> 平台槽位核对
   -> 可接受：建立部件级上传包
   -> 不可接受：记录限制并由用户决定补图或改走 Blender
```

## 状态与交接

| 状态 | 进入条件 | 退出条件 |
|---|---|---|
| `PART_VIEW_CONTRACT_PENDING` | front 已确认 | 用户确认视图列表、排除项和逐图相机合同 |
| `VIEW_CANDIDATE_PENDING` | 某个 required 文件合同已锁定 | 用户对准确文件名明确确认 |
| `FORMAL_REFERENCE_SET_READY` | 所有 required 文件已确认并完成映射 | 平台槽位/图数已核对，或用户决定下一建模路径 |
| `PLATFORM_LIMIT_RECORDED` | 平台不接受当前确认图数 | 用户批准补图或改用其他路径 |

## Workflow Check

- Missing gate：此前只有“单正视图或四视图”的分流，没有锁定两张等自定义视图集、未选历史图及项目级正式参考包。
- Manual/automatic boundary：用户批准视图列表、每张候选、排除项和下一建模路径；Codex 只生成单图候选、建立非破坏性副本、计算哈希和检查目录。
- Verification evidence：本案例的正式参考目录包含 6 张 PNG；每张与确认源图 SHA-256 一致，尺寸正确，角点背景为 `#B3C0C5`。精确清单见当前运行的 `_docs/FORMAL_REFERENCE_SET.md`。
- Handoff impact：Blender / 图生 3D 接手者可以只读取正式参考 Manifest，避免把候选、未选背视或错误的三分之四侧视带入下一阶段。
- Rule/doc update：本次规则已同步到主入口、P4 执行规范、两份视图合同模板、Manifest、清单、失败码、运行状态模板和注册表；工作流仍保持 `Review`，需另一把武器复验后再评估升级。
