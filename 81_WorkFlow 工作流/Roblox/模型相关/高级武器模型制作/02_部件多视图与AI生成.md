# 02 部件多视图与 AI 生成

## 目标

把每个已确认部件转换为能给 Tripo、混元 3D 等平台提供一致几何证据的正式视图集，再单独生成 3D 网格。

完整相机和验证规则以 [[../Roblox 魔法剑模型制作工作流/README|魔法剑多视图工作流]] 为准；本文件只补充拆件型高级武器的跨部件纪律。

## 一次只处理一个部件

单部件运行目录必须绑定：

- `component_id` 与英文角色名。
- 已确认的部件 `effect.png`。
- 完整武器 `master_effect.png`，仅用于颜色、比例和连接位置参考。
- 项目锁中该部件的轴向区间、厚度和接口合同。
- 独立 `RUN_STATE.md`。

不要把四个部件的视图混入同一次 3D 生成任务。

## 视图集选择

| 视图集 | 文件 | 适用情况 |
|---|---|---|
| 单正视图 | front | 近似轴对称或四向信息高度重复，且用户明确授权 front-only |
| 用户声明视图集 | 例如 front / side_a_90 | 用户明确指定该部件只需哪些语义视图；每个文件仍须独立生成、逐张确认，不把 `side_a` 强行命名成 left/right |
| 基础 4 视图 | front/back/left/right | MULTI_VIEW 的默认基础包；先用它做首轮 AI 网格 |
| 辅助 45° 对 | left45/right45 | 仅 P5A 证明四视图无法约束端面、侧壁或中央机构的空间过渡，且用户确认后创建 |
| 顶底证据 | top/bottom | 顶底结构重要且有可靠证据；按平台能力或工程用途单独标记 |
| 工程补图 | axial/section | 插孔、槽位或可替换接口需要工程表达；不混入平台标准槽位 |

不要为了凑数量使用缺乏证据的视图。六视图不是高级武器默认值；基础四视图与辅助 45° 对使用两个独立目录。轴向证据不足时，先做简单 Blender 代理或保持四视图，不凭想象生成。

## PART_VIEW_CONTRACT_GATE

在 `VIEW_REDUNDANCY_GATE` 后、生成任一非 front 方向前，每个部件还必须锁定下列内容：

- `required_final_views`：本次正式参考集确切需要的语义视图及文件名，例如 `front.png / side_a_90.png`。
- `not_required_views`：本次明确不入正式集的方向，例如 `back / side_b / top / bottom`；此前已确认但仅作历史参考的图片也必须写在这里，保留原文件但不混入正式交付。
- `view_set_authorization`：用户原话与日期。`front-only`、两张视图或基础四视图都不能凭惯例推断。
- `camera_contract_per_view`：每图的 `camera_count=1`、`projection=ORTHOGRAPHIC`、yaw/pitch/roll、可见/隐藏结构和地标；若用户要求精确 90°，它不是“接近侧面”的建议，而是硬门。
- `critical_side_profile`：若主体包含立体狼首、兽首、雕像或朝向性机构，必须列出侧视仍应可读的轮廓地标；不能为了表现刃厚而把真实立体主体完全抹掉。
- `formal_reference_package` 与 `platform_input_package`：前者收纳所有已确认正式参考，后者仅收纳平台实际接受的已确认文件。平台槽位不足不能倒逼复制、翻转、镜像或伪造视图。

`required_final_views` 的数量不是默认参数。只有用户明确批准才可以是 1、2、4 或其他有证据的数量；但任何单图都必须有独立候选、准确路径和用户确认，不能用“这张也差不多”替代审批。

## VIEW_REDUNDANCY_GATE

`front` 通过后、生成 `back/left/right` 前，每个部件都必须执行本 Gate：

1. Codex 判断该部件是否为冗余候选，并记录依据：近似轴对称、绕主轴重复、front/back/left/right 仅有材质高光变化等。
2. 同时检查反例：方向性装饰、非对称截面、D 形键、隐藏槽孔、前后层级或侧面厚度是否会丢失。
3. 若为候选，Codex 必须主动询问：`该部件四向几何信息高度重复，是否明确改用仅 front.png？若不明确同意，将继续原多视图与 SIDE_VISIBILITY_CONTRACT。`
4. 只有用户明确同意，才记录 `view_mode=FRONT_ONLY_USER_APPROVED`、用户原话/日期、`required_views=front`，并将侧向合同记为授权豁免。
5. 用户拒绝、未回答、只说“继续”或表达含糊时，记录 `view_mode=MULTI_VIEW`，继续原视图集与 [[SIDE_VISIBILITY_CONTRACT_TEMPLATE]]。

`front-only` 只减少重复平台输入，不表示物体没有厚度或接口。若正视图不足以说明孔槽、端面或装配结构，仍需 `engineering_reference_only` 补图或 Blender 重建。授权只对当前 Component ID 有效，不跨部件复用。

## DEPTH_BRIDGE_GATE

本门同时锁定 `CROSS_SECTION / END_PROFILE`，并判断是否需要 45° 空间桥接证据。

每个 `MULTI_VIEW` 部件在生成侧视前必须记录一张几何卡：

- `primary_volume`：板体 / 柱体 / 棱柱 / 体块 / 组合体。
- `CROSS_SECTION`：主截面形状、层数和厚度分布。
- `END_PROFILE`：沿端轴观察时的真实外轮廓。
- `near_end_face`：平面 / 凸面 / 尖端 / 开孔，以及它与侧壁的分界。
- `side_wall`：端面之后可见的真实厚侧壁与连接方向。
- `front_mechanism_at_45`：正面机构刚体旋转后应如何正交压缩。
- `four_view_sufficient`：在首轮 P5A 前写 `UNKNOWN`，P5A 后更新为 `YES / NO`。

若 `CROSS_SECTION / END_PROFILE` 不能用文字或低成本体块明确表达，记录 `CROSS_SECTION_END_PROFILE_NOT_LOCKED`，先做灰模/基础体 Proxy，只验证空间关系，不验证材质与装饰。

基础四视图完成后先进行首轮 AI 3D。只有 P5A 出现以下证据，才能记录 `p5a_outcome=SPATIAL_BRIDGE_REQUIRED`：

1. 正视和端视单独看都成立，但端面与侧壁被错误连接。
2. 中央正面机构在正视与端视之间被融合、球化或重新设计。
3. 宽体锤头、箱体、双壳或凸出机构的遮挡顺序无法由四个端点视图约束。

如果是某张基础图本身错误，写 `BASE_VIEW_DEFECT` 并只修该基础图；如果只是生成器随机发散，写 `GENERATOR_DRIFT` 并保留视图包。不得把所有失败都归因于“缺 45°”。

## 正面与背面

- `front` 必须由用户确认，成为当前部件唯一视觉设计锁。
- `back` 是同一物体转到另一外表面，不能重新设计。
- 即使正背外观相同，也要先写明“两个外侧装饰面相同”，再分别验收。
- 双面装饰会直接影响侧视厚度；侧视必须表现前层、实体芯、后层或已确认的贴合关系。

## 单部件视图执行顺序

1. 以已确认 `effect.png` 生成并确认 `front`。
2. 填写 [[VIEW_SET_CONTRACT_TEMPLATE#VIEW_REDUNDANCY_GATE]]，再锁定 `PART_VIEW_CONTRACT_GATE` 的 `required_final_views / not_required_views / view_set_authorization`。
3. 对 `required_final_views` 中每个方向单独定义相机、可见/隐藏、地标和文件名；不对称部件可使用 `Side A / Side B`，不得为了文件习惯强行映射成 left/right。
4. 每张目标图仅生成一个候选，先检相机与几何，向用户展示准确文件与稳定路径；收到该文件的明确确认后才固化为成图。未确认视图不进入正式集。
5. 生成带文件名标签的联系表；通过后把本部件所有已确认的 `required_final_views` 非破坏性复制到项目级 `00_formal_model_references/`，并以 `{component_role}_{semantic_view}.png` 命名、写入 `FORMAL_REFERENCE_SET.md`。
6. 根据平台槽位，从正式参考集中挑选平台实际接受的文件进入 `00_final_image_to_3d_upload`。图数不匹配时记录平台限制并向用户确认补证据策略；禁止复制、翻转、镜像或把候选冒充正式图。
7. P5A 若判定 `SPATIAL_BRIDGE_REQUIRED`，Codex 先展示证据并询问用户是否进入 `VIEW_EVIDENCE_REPAIR`；确认后分别锁定 `left45/right45` 合同。
8. 两份合同均通过后，可独立并行生成两张正式候选：`left45` 只使用 `front + left`，`right45` 只使用 `front + right`。候选分别预检、分别确认，不合成一张输出、不互相镜像。
9. 两张 45° 图通过后提升到 `01_auxiliary_45_upload`，只重生成当前部件并回到 P5A。`top/bottom/axial/section` 只有在另有可靠证据时才补；工程补图标记 `engineering_reference_only=true`，不得误塞平台槽位。

每个视图都在视图集合同中记录 `camera_direction / must_visible / must_hidden / landmarks / platform_slot / canonical_path / SHA-256 / approval`。侧视模板只负责 left/right 专项，不代表其他视图可以缺合同。

## 侧向可见性合同

在生成 `left/right` 以及相应 45° 图前，Codex 必须逐文件主动询问并复述：

```markdown
## left.png
- 摄像机从哪一侧朝物体中心观察：
- 必须看见：
- 必须隐藏：
- 方向性结构的数量、顺序和位置：
- 遮挡关系：
- 厚度层级：
- 插头、槽位或端面如何投影：
- 相机：严格单摄像机 90° 正交

## right.png
- 摄像机从哪一侧朝物体中心观察：
- 必须看见：
- 必须隐藏：
- 方向性结构的数量、顺序和位置：
- 遮挡关系：
- 厚度层级：
- 插头、槽位或端面如何投影：
- 相机：严格单摄像机 90° 正交
```

关键规则：

- 不把“是否对称”作为默认分流问题。
- `left` 与 `right` 默认分别生成、分别确认。
- 只有用户明确授权指定 `source.png -> target.png` 时，才允许几何复用或本地镜像；授权不跨资产、不跨部件。
- 90° 侧视必须由一台正交相机取得，只能看见真实侧面投影，不能展开成宽正面，也不能用 3/4、拼接或混合相机图冒充。
- 严格 90° 不是“压扁一切”的许可：合同中声明的立体狼首、兽首、尾环、端面等关键轮廓仍须保留真实侧向实体厚度与局部剪影。
- 某侧需要看到刃口，另一侧需要看到背部凹痕时，合同必须分别记录；不能因轮廓相近而复制。

合同缺失：`SIDE_VISIBILITY_CONTRACT_MISSING`。违反可见/隐藏、数量、位置或遮挡：`SIDE_VISIBILITY_CONTRACT_BROKEN`。未经授权镜像：`UNCONFIRMED_SIDE_MIRROR`。

### 45° 空间桥接相机合同

- 投影必须是 `ORTHOGRAPHIC`。
- `front = yaw 0°`；`left45/right45 = yaw -45°/+45°`，正负映射以当前项目坐标合同为准。
- `pitch = 0°`、`roll = 0°`；禁止高机位、低机位和电影式 3/4 镜头。
- 近端与远端不得发生透视性的近大远小；同源结构保持相同物理尺度，只允许正交遮挡与投影差异。
- 平击打端必须仍是既定平面/多边形端面，端面之后能读出厚侧壁；不能球化、鼓包或变成薄圆片。
- 中央正面机构必须随整个刚体旋转而正交压缩；不能保持完整正视圆形，也不能被重新设计。
- 远端只显示合同允许的侧壁与遮挡，不新增第二个近向端面或重复部件。

45° 候选先检查相机、端面、侧壁、中央机构和近远尺度；几何通过后才允许清背景。背景后处理不能修复 `VIEW_45_CAMERA_INVALID / END_PROFILE_SPHERIZED / OBLIQUE_PROJECTION_BROKEN`。

## 厚度与接口门

每个部件至少回答：

- 主体是平板、楔体、圆柱、双壳还是体块。
- 最大厚度在哪里，向边缘如何收束。
- 宝石、护圈、爪、刃框是浮在表面、嵌入还是贯穿。
- 正背都有装饰时，侧面看见几层；层间是实体芯、共享接缝还是空腔。
- 插头/槽位是否应该在该视图可见；装配后是否隐藏。

若这些问题没有答案，记录 `THICKNESS_NOT_LOCKED` 或 `CONNECTOR_NOT_LOCKED`，停止正式视图提升。

### 共享对位区在参考图中的规则

- 只有对应 `JOINT_<ID>.md` 已通过 P2J，才允许在两个部件图中重复共享对位区。
- 两份图中的共享区应保持同一轮廓、层数、厚度比例、朝向和相对尺度；不重复蓝色发光环、首节握柄等合同外结构。
- 代理副本只帮助 AI 识别接口位置和 Blender 粗对位，文件/对象语义必须是 `ALIGN_PROXY_<ID>_DELETE_AFTER_ALIGN`。
- 不把“图上相同”写成“3D 尺寸相同”。Tripo / 混元的两次独立输出只能近似，不能作为工程公差证据。
- 若平台容易把代理与主体粘成错误外壳，停止在正式输入图中重复代理，改用 Blender 的简单基准几何；不能为了保留代理而牺牲部件主体。

## 图像输出规范

- 单一道具、完整、居中、稳定画布。
- 纯色背景，无渐变、阴影、地平线、UI、文字或特效。
- 同一部件所有视图保持总尺度、材质区和细节密度一致。
- 背景清理和补边不能修复错误相机或错误结构。
- 正式统一画布只允许在纯色背景上平移与补边，主体像素尺度必须保持不变；允许裁去纯背景后等量补边，但不得裁到物体、用裁切改变主体占比、逐图缩放、非等比拉伸或透视校正。若尺度已漂移，重做漂移图。
- 每张候选都使用唯一文件名；用户反馈必须绑定该文件名。

正式目录示例：

```text
{component_run}/
├─ _docs/
├─ _imagegen_candidates/
├─ _checks/
├─ 00_final_image_to_3d_upload/
│  ├─ front.png
│  ├─ back.png
│  ├─ left.png
│  └─ right.png
└─ 01_auxiliary_45_upload/   # 仅 P5A 触发后创建
   ├─ left45.png
   └─ right45.png
```

项目级 `00_formal_model_references` 必须恰好等于全部已确认的 `required_final_views`，且只包含语义唯一的 PNG。`00_final_image_to_3d_upload` 必须恰好等于当前平台接受的正式输入清单；经授权的单正视图通常为 1 张、基础四视图通常为 4 张，但用户声明的两张或其他视图集以 Manifest 为准。`01_auxiliary_45_upload` 若存在，必须恰好只有已确认的 `left45.png/right45.png`。平台提交清单不得把代理、工程图、联系表、提示词、运行状态或失败稿混入任一上传目录。

高级武器流程的 `4 + 2` 双目录是对外部 Six 单目录规则的显式覆盖：基础包保持可复用，辅助证据可追溯到 P5A，不让未触发的部件被误判为“缺少六视图”。

## 联系表与逐图验收

1. 每张图先全分辨率单独检查。
2. 再做带明确标签的 contact sheet，核对同一部件身份、总尺寸、材质和旋转逻辑。
3. 用户确认联系表后，才提升为正式上传目录。
4. 最终回复列出每张图的准确名称和稳定绝对路径；不要只说“第一张/第二张”。

## 交给 Tripo / 混元 3D

每个任务只上传一个部件的正式视图。生成后记录：

- 平台、模型版本和任务 ID（如果可用）。
- 使用的正式文件清单和哈希。
- 输出模型格式、贴图和原始面数。
- 已知异常：厚度、粘连、漂浮、背景融合、接口缺失、正面贴片拉伸等。

## Gate P5A：AI 网格视觉验收

至少用正视、侧视和 3/4 检查：

- 轮廓、方向性结构和识别点与视图一致。
- 厚度不是纸片，也没有无依据地膨胀。
- 正背装饰没有错误融合或漂浮。
- 接口附近有足够实体可供 Blender 重建连接。
- 不要求 AI 产出精密孔槽；若装饰壳正确，内部接口可在 Blender 补。
- 若网格带有共享对位区副本，已登记其 `JOINT_ID`、最终所有者和待删除代理；不能把两份近似网格当成已匹配接口。
- 面数是接收信息，不是质量证明；三角面上限是限制，不是目标。

每次 P5A 必须记录：`p5a_attempt / platform_task_id / input_manifest / outcome / evidence_path / next_action`。`outcome` 只使用：

- `NOT_EVALUATED`：尚未执行首轮 P5A；这是初始状态，不是一次验收结果。
- `PASS`：进入 P5B。
- `BASE_VIEW_DEFECT`：只修异常基础图并重建基础 Manifest。
- `SPATIAL_BRIDGE_REQUIRED`：进入部件级 `VIEW_EVIDENCE_REPAIR`，经用户确认后补辅助 45° 对。
- `GENERATOR_DRIFT`：视图证据不变，只重跑当前部件一次。

失败时先定位责任范围，不要整套部件一起返工。`FRONT_ONLY_USER_APPROVED` 若首轮模型证明单图证据不足，必须重新询问是否升级为基础四视图，不能绕过四视图直接补 45°。

### 正式生图预算与停止条件

1. 每个目标视图每轮只生成 1 张正式候选。
2. 两张 45° 合同已锁定时，允许以两个独立任务并行生成，减少等待；每个任务只加载 `front + 对应 90° 侧视图`。
3. 同一视图第一次几何失败后，必须先修合同；如果空间关系仍说不清，再用简单 Proxy。
4. 同一视图连续 2 次正式失败，记录 `FORMAL_IMAGEGEN_RETRY_BUDGET_EXCEEDED`，停止盲目生图；转 Blender 正交块模渲染或要求补充证据。
5. 背景扁平化、补边和哈希只在几何通过后执行。

视觉通过后，将原始模型与贴图复制到 `03_ai_mesh_source/{component}/`，把该部件标记为 `ai_mesh_gate=IN_PROGRESS`；此时还不能写项目级 `AI_MESH_ACCEPTED`。
