## 记录规则

- 固定脚本：`scripts\Prepare-RobloxWeaponImport.ps1`
- 默认 Studio 导入包输出根目录：`%USERPROFILE%\Documents\RobloxImportPackages`
- 标准优先导入文件：`_IMPORT_ONLY` 干净目录第一层的短名主 GLB，例如 `输出名_faces实际面数_1024tex.glb`。
- 标准 FBX 贴图策略：FBX 仅作为兼容排查或 fallback，优先使用同目录外部相对贴图，不默认内嵌贴图。
- 标准 FBX 尺寸策略：`fbx_scale_mode=match_glb_world_scale`，导出后必须回导校验 `fbx_glb_scale_match=True`。
- 兼容测试文件：`输出名_faces实际面数_embedded_1024tex.fbx`
- 纹理规格：默认 `1024x1024`；`512` 仅用于低配包、极轻量批量包或上传限制排查。
- 每次成功或失败都追加记录。

## 2026-07-07 13:09 MagicWand-01_3292 - FBX 导入尺寸修正

### 触发原因
- 用户反馈外部贴图 FBX 可以导入，但在 Roblox Studio 中明显比 GLB 大。
- 截图显示模型 `Scale=1`，但世界中的显示尺寸远大于 GLB 导入效果，说明问题更可能来自 FBX 单位/节点缩放，而不是用户手动缩放。

### 根因判断
- 旧 FBX 二进制检查结果：
  - `UnitScaleFactor=1`
  - `Lcl Scaling=(100,100,100)`
  - `vertex max dimension=1`
- 结论：mesh 顶点本身仍是 1 单位，FBX 文件额外写入了 100 倍节点缩放；Blender 读回时会抵消这层缩放，但 Roblox Studio 会把它作为真实节点缩放应用。

### 修正
- 在 `scripts\Prepare-RobloxWeaponImport.ps1` 的三类 FBX 导出中加入：
  - `global_scale=0.01`
  - `apply_unit_scale=True`
  - `apply_scale_options='FBX_SCALE_ALL'`
- 新增脚本输出标志：`fbx_scale_mode=roblox_unit_1`

## 2026-07-29 22:46 FBX / GLB 尺度门禁修正

### 触发

- 一个已经在 Blender 中正常化的 Tripo 低模长剑通过旧版脚本导出。
- 回导发现 direct FBX 约为 GLB 的 `0.01` 倍。
- 原因是旧版无条件设置 `global_scale=0.01`，重复缩小了已正常尺度的来源。

### 修正

```text
fbx_global_scale=1
fbx_scale_mode=match_glb_world_scale
```

导出后自动回导 direct FBX 和 GLB，比较整体包围盒。任一轴相对误差超过 `1e-4` 时直接失败。

### 验证

```text
faces=2928
FBX=0.396718 x 0.093483 x 1.198457
GLB=0.396718 x 0.093483 x 1.198457
fbx_glb_scale_match=True
texture=512x512
```

### 新规则

- 不再用某个旧来源的 `0.01` 补丁作为全局规则。
- 正确标准是 FBX 与 GLB 保持相同世界尺寸。
- 历史输出仍保留原记录，但新资产必须通过自动尺寸门禁。
