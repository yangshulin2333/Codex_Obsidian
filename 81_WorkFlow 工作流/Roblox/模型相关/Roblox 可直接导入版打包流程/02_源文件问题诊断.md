# 源文件问题诊断

更新时间：2026-07-07

## 常见结论

源文件无法直接导入 Roblox，通常不是模型几何坏了，而是源包结构不适合 Roblox 导入器。

最常见情况：

```text
路径名看起来是 xxx.fbx
但实际是一个目录
目录里才有真正的 tripo_convert_*.fbx
贴图在旁边的 tripo_convert_*.fbm 目录里
```

Roblox 直接导入这种源包时，容易找不到外部贴图，或出现贴图上传失败。

## 诊断命令

```powershell
Get-Item -LiteralPath "用户给的路径" | Select-Object FullName,Mode,Length,LastWriteTime
Get-ChildItem -LiteralPath "用户给的路径" -Force | Select-Object Mode,Name,Length,LastWriteTime
```

如果输出类似：

```text
Mode   Name
----   ----
d----- tripo_convert_xxx.fbm
-a---- tripo_convert_xxx.fbx
```

说明它是 Tripo 风格目录包。

## 典型源包类型

| 类型 | 表现 | 处理方式 |
| --- | --- | --- |
| 真 FBX 文件 | `Mode=-a----`，有文件大小 | 直接作为 `-InputPath` 交给固定脚本 |
| `.fbx` 目录包 | `Mode=d-----`，里面有 `tripo_convert_*.fbx + .fbm` | 目录本身作为 `-InputPath` |
| 伪 FBX ZIP | 文件扩展名是 `.fbx`，实际文件头是 ZIP | 固定脚本自动解压 |
| 下载目录 | 目录里有多个 FBX/贴图 | 固定脚本自动选主要 FBX 和颜色贴图 |

## 为什么不要直接导入源 FBX

Tripo/Meshy 下载包经常依赖外部资源：

- FBX 内部材质引用外部贴图。
- 贴图放在 `.fbm` 子目录。
- 颜色贴图、法线贴图、粗糙度贴图等混在一起。
- 文件夹名可能以 `.fbx` 结尾，容易误判为单个 FBX 文件。
- Roblox 导入器不一定能稳定解析这些外部贴图关系。

固定脚本会做这些兼容处理：

- 自动找到真正的 FBX。
- 自动选择颜色贴图，避开 normal、roughness、metallic、emissive 等非颜色贴图。
- 把贴图压缩成 `1024x1024`。
- 用 Blender 后台重新绑定材质。
- 重新导出 Roblox 更容易接受的 FBX/GLB。
- 优先 FBX 使用同目录外部相对贴图，避免 Roblox 对 FBX 内嵌贴图上传不稳定。
- 额外保留 embedded FBX 作为兼容性排查文件。
- 保留 mesh-only 保底文件。

## 常见问题和处理

### 问题：路径以 `.fbx` 结尾，但 Roblox 导不进去

可能原因：

```text
这个 .fbx 其实是目录包，不是单个 FBX 文件。
```

处理：

```powershell
Get-Item -LiteralPath "路径" | Select-Object FullName,Mode
```

如果 `Mode=d-----`，直接把这个目录交给固定脚本。

### 问题：Roblox 报 base_color_texture 上传失败

可能原因：

```text
贴图或材质上传失败，不一定是模型坏了。
```

处理顺序：

1. 先试 `_IMPORT_ONLY` 干净目录第一层的短名主 GLB。
2. 如需确认是否是 FBX 贴图封装问题，再试 `*_faces实际面数_direct_1024tex.fbx`，并保持 `*_faces实际面数_texture_1024.*` 与 FBX 在同一目录。
3. 再试 `*_faces实际面数_embedded_1024tex.fbx`。
4. 最后用 `*_faces实际面数_mesh_only.fbx + *_faces实际面数_texture_1024.*` 手动贴图。

经验结论：

```text
如果 GLB 可以导入，而 FBX 报 base_color_texture，通常是 Roblox 的 FBX 贴图上传/引用链路不稳定。
优先把 FBX 做成“外部相对贴图 + 同目录 JPG”，不要默认内嵌贴图。
```

### 问题：FBX 导入后比 GLB 大很多

可能原因：

```text
Blender 默认 FBX 导出可能写入 Lcl Scaling=(100,100,100)。
Blender 自己读回时可能会抵消这层缩放，但 Roblox Studio 会把它当作真实节点缩放应用。
```

处理：

1. 重新跑当前固定脚本。
2. 确认脚本输出包含 `fbx_scale_mode=match_glb_world_scale`。
3. 验证自动回导结果满足：

```text
fbx_dimensions=(x, y, z)
glb_dimensions=(x, y, z)
fbx_glb_scale_match=True
```

当前脚本使用：

```text
global_scale=1
apply_scale_options='FBX_SCALE_ALL'
```

导出后脚本会回导 direct FBX 和 GLB，任一轴尺寸不一致就中止。旧版固定 `global_scale=0.01` 可能把已经正常化的模型缩小 100 倍，不再使用。

### 问题：脚本生成了 512 文件

可能原因：

```text
命令显式传入了旧参数 `-TextureSize 512`，或复用了旧输出目录。
```

处理：

1. 重新执行固定脚本，并明确传入 `-TextureSize 1024`，或直接使用脚本当前默认值。
2. 删除或忽略同目录下旧的 `*_direct_512tex.*`。
3. 最终只交付 `_IMPORT_ONLY` 干净目录里的 `<序号>_faces<实际面数>_1024tex.glb`。

### 问题：输出名混乱

可能原因：

```text
源路径名太短，例如 2-1.fbx；或者多个系列重复使用同名。
```

处理：

用父目录补充语义：

```text
D:\Download\3DModel\MagicBook\2-1.fbx
-> MagicBook-2-1
```

## 给用户解释时的短句

可以这样说：

```text
你的源文件主要不是模型坏了，而是导出包结构不适合直接丢进 Roblox。
这个路径看起来像 .fbx，但实际是目录包，里面是真 FBX 加 .fbm 贴图目录。
Roblox 直接导入时容易找不到或无法上传外部贴图。
我已经用固定脚本重新绑定材质，并导出了外部贴图版 `faces实际面数_direct_1024tex.fbx` / GLB / embedded 兼容版 / mesh-only 保底文件。
```
