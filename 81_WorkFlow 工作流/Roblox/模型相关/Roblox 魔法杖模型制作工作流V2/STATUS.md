## 2026-07-11 失败复盘

本轮 10 把精灵魔法杖暴露两个系统性缺陷：

1. 固定列宽 / 手写矩形裁切截断了越过列边界的鹿角和顶部装饰。
2. 侧视提示词反复强调“压缩”和“越窄越好”，并使用整杖高度的 `6%-8%` 作为目标，导致宝石、托架和杖身纸片化。

失败码：

```text
FRONT_CROP_TOUCHES_EDGE
FRONT_CROP_CLIPPED
FRONT_CROP_NEIGHBOR_CONTAMINATION
SIDE_DEPTH_COLLAPSE
SHAFT_DEPTH_COLLAPSE
GEM_DEPTH_COLLAPSE
HOLDER_DEPTH_COLLAPSE
```

## 已做决策

- 固定列宽只允许定位，不允许作为最终裁切。
- 背景干净时使用前景遮罩扣图；重叠或阴影粘连时人工抠图。
- 正视图前景触边立即停止，不能继续生成多视图。
- 废止 `6%-8% 整杖高度`作为通用侧视厚度目标。
- 深度按杖身、宝石、托架和尾部分别记录。
- 生成顺序改为 `front -> left45 -> left90`。
- `left90` 同时参考 `front` 和已确认的 `left45`。
- 90°侧视必须同时通过“角度正确”和“体积不坍缩”两道门禁。
- 归一化只允许等比例缩放和平移，禁止横向压缩。

## 升级为稳定版的条件

至少完成 3 类结构的试跑：

- 厚切割宝石 + 托架。
- 圆形 / 凸面宝石 + 圆柱杖身。
- 鹿角 / 花瓣 / 卷叶等复杂镂空顶部。

每类都必须提供：

- 完整扣图和源图对照证据。
- 组件级深度合同。
- 通过审核的 45°深度桥接图。
- 同时通过角度与体积门禁的 90°侧视图。
- 混元 3D / TripoAI 结果截图。

连续 3 把通过后，再决定是否命名为 V3 或将 V2.1 标记为稳定版。
