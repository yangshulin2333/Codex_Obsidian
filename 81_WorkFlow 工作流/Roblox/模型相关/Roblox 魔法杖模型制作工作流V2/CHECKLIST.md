# 检查清单

> [!warning] 当前优先执行 [[V2.1_稳定图片实验流程]]
> 以下旧清单保留兼容性，但裁切、生成顺序和侧视宽度判断已由本页新增门禁覆盖。

## A. 正视图扣图与完整性门禁（优先）

- [ ] 原始效果图已只读保留。
- [ ] 固定列宽只用于定位，没有直接作为最终裁切。
- [ ] 已优先使用前景遮罩扣图；自动遮罩不可靠时使用手工多边形遮罩。
- [ ] bbox 四周安全边距至少 `64px` 或顶部最大宽度的 `12%`。
- [ ] 前景距离上、下、左、右裁切边缘均大于 `8px`，建议大于 `16px`。
- [ ] 鹿角、叶尖、花瓣、晶体尖端、尾坠完整。
- [ ] 没有混入相邻魔法杖像素。
- [ ] 归一化画布没有第二层明显矩形底图。
- [ ] 已生成源图对照 / 扣图预览。

硬拒绝：`FRONT_CROP_TOUCHES_EDGE`、`FRONT_CROP_CLIPPED`、`FRONT_CROP_NEIGHBOR_CONTAMINATION`。

## B. 组件级深度合同（优先）

- [ ] 已记录杖身正面宽度与预期侧面直径。
- [ ] 已记录宝石正面宽度与预期侧面深度。
- [ ] 已记录托架正面宽度、前后错层与预期侧面深度。
- [ ] 已记录尾部正面宽度与预期侧面深度。
- [ ] 没有把“侧视占整杖高度 6%-8%”当作通用目标。
- [ ] 深度假设不确定时已标记 `DEPTH_ASSUMPTION_UNCONFIRMED`。

## C. 新视图顺序（优先）

- [ ] `front.png` 完整通过。
- [ ] Codex 已主动询问并复述四份侧向可见性合同，用户已确认。
- [ ] 先生成并审核 `left45.png`，用来锁定深度。
- [ ] `left45.png` 没有增删组件，且前后关系可信。
- [ ] `left.png` 同时参考了 `front.png` 和已确认的 `left45.png`。
- [ ] `right.png` / `right45.png` 分别按自己的合同生成；如使用镜像，已有用户明确点名的来源与目标授权记录。

## D. 90°侧视双门禁（优先）

角度门禁：

- [ ] 看不到大面积正面宝石面。
- [ ] 托架没有以完整正面形状展开。
- [ ] 不是 80°、45°或 3/4 视图。

体积门禁：

- [ ] 圆柱杖身侧面宽度接近正面杖身宽度，没有缩成细线。
- [ ] 宝石显示侧体、侧棱或凸起，不是单条彩色线。
- [ ] 托架保留前后错层和厚度，没有融合成针状轮廓。
- [ ] 尾部保留真实体积。
- [ ] 侧视厚度不低于组件深度合同下限。

硬拒绝：`SIDE_VIEW_NOT_90_DEGREE`、`SIDE_DEPTH_COLLAPSE`、`SHAFT_DEPTH_COLLAPSE`、`GEM_DEPTH_COLLAPSE`、`HOLDER_DEPTH_COLLAPSE`、`SIDE_VISIBILITY_CONTRACT_MISSING`、`SIDE_VISIBILITY_CONTRACT_BROKEN`、`UNCONFIRMED_SIDE_MIRROR`。

## 0. 任务边界

- [ ] 当前目标是生成 Roblox 魔法杖 3D AI 输入图，不是做展示海报。
- [ ] 输出用于混元 3D / TripoAI 等图生 3D 工具。
- [ ] 已明确目标魔法杖编号或单张参考图。
- [ ] 已确认这是一把中短手持魔法杖，不是长法杖、长枪、剑、骨棒或其他武器。

## 1. 正视图确认

- [ ] 已优先尝试从源图裁切目标魔法杖作为 `front.png`。
- [ ] 如果重新生成正视图，已确认没有改设计。
- [ ] `front.png` 中顶部、托架、杆身、尾部清晰。
- [ ] `front.png` 没有背景场景、文字、水印、UI 图标。
- [ ] 用户已确认 `front.png` 可以作为后续视图基准。

未确认正视图时，不允许继续生成其他视图。

## 2. 比例锁

- [ ] 已把整把魔法杖高度定义为 `100%`。
- [ ] 已记录画布尺寸，默认 `1024x2048`。
- [ ] 已记录目标物体高度，推荐约 `1720px`。
- [ ] 已记录顶部主元素高度比例。
- [ ] 已记录顶部托架 / 固定结构高度比例。
- [ ] 已记录握柄 / 杖身高度比例。
- [ ] 已记录底部装饰 / 尾坠高度比例。
- [ ] 已记录正面最大宽度比例。
- [ ] 已记录严格 90°侧面最大宽度比例。
- [ ] 已记录 45°视图最大宽度比例。

硬规则：

- [ ] 不允许顶部被放大导致杆身变短。
- [ ] 不允许杆身长度漂移。
- [ ] 不允许底部尾坠变成新宝石、尖刺、刀刃或额外装饰。
- [ ] 不允许用缩放掩盖错误视角。

## 3. 组件锁

- [ ] 已列出 1 个顶部主元素。
- [ ] 已列出 1 个顶部托架 / 固定结构。
- [ ] 已列出 1 根握柄 / 杖身。
- [ ] 已列出中部装饰数量和位置。
- [ ] 已列出金属环 / 束带数量和位置。
- [ ] 已列出 1 个底部装饰 / 尾坠。

硬规则：

- [ ] 不能添加新翅膀。
- [ ] 不能添加新尖刺。
- [ ] 不能添加链条。
- [ ] 不能添加布条。
- [ ] 不能添加藤蔓或花朵，除非源图本来就有。
- [ ] 不能添加额外宝石。
- [ ] 不能添加魔法特效。
- [ ] 不能添加背景装饰。
- [ ] 不能删除原有组件。
- [ ] 不能把某个组件换成其他形状。

## 4. 颜色和材质锁

- [ ] 顶部主元素颜色和材质已写死。
- [ ] 金属件颜色和材质已写死。
- [ ] 握柄 / 杖身颜色和材质已写死。
- [ ] 中部宝石颜色和材质已写死。
- [ ] 底部装饰颜色和材质已写死。

硬规则：

- [ ] 不允许宝石换色。
- [ ] 不允许金属从金色变成银色、铜色或黑铁色，除非源图就是这些材质。
- [ ] 不允许木材、骨骼、金属、水晶等材质互换。

## 5. 侧向可见性合同锁

- [ ] `left.png` 的必须看见 / 必须隐藏结构已确认。
- [ ] `right.png` 的必须看见 / 必须隐藏结构已确认。
- [ ] `left45.png` 的必须看见 / 必须隐藏结构已确认。
- [ ] `right45.png` 的必须看见 / 必须隐藏结构已确认。
- [ ] 每份合同都记录了单侧细节的准确数量、位置和前后遮挡关系。
- [ ] 文件名与相机观察方向的映射已由 Codex 复述并得到确认。
- [ ] 没有用“对称 / 非对称”的分类替代这一步。
- [ ] 镜像默认未授权；如使用，用户已明确点名来源文件和目标文件，且原话与日期已记录。

未确认合同不得生成侧向视图，标记 `SIDE_VISIBILITY_CONTRACT_MISSING`。违反合同标记 `SIDE_VISIBILITY_CONTRACT_BROKEN`。未经用户明确授权镜像标记 `UNCONFIRMED_SIDE_MIRROR`。

## 6. 视图文件检查

最终上传目录必须只有：

- [ ] `front.png`
- [ ] `back.png`
- [ ] `left.png`
- [ ] `right.png`
- [ ] `left45.png`
- [ ] `right45.png`

最终上传目录不能有：

- [ ] `top.png`
- [ ] `bottom.png`
- [ ] 候选图。
- [ ] contact sheet。
- [ ] 提示词。
- [ ] JSON。
- [ ] 失败版本。

## 7. left / right 垂直 90°门禁

`left.png` 和 `right.png` 必须是正侧面。

逐项检查：

- [ ] 看不到大面积正面宝石。
- [ ] 主宝石显示侧体、倒角或凸起，不显示宽正面，也不坍缩成彩色细线。
- [ ] 托架 / 爪 / 叶片形成侧面重叠关系，同时保留前后错层和厚度。
- [ ] 金属环变成窄侧带或椭圆边。
- [ ] 正面专属装饰没有完整展开。
- [ ] 侧视宽度明显小于正视图。
- [ ] 侧视宽度明显小于 45°视图。
- [ ] 侧视宽度不低于组件级深度合同下限。
- [ ] 画面不是左前 / 右前。
- [ ] 画面不是 45°。
- [ ] 画面不是 3/4。
- [ ] 各自必须看见 / 隐藏的结构、数量、位置和遮挡关系符合已确认合同。

硬拒绝：

- [ ] 如果主宝石仍显示宽正面，标记 `SIDE_VIEW_NOT_90_DEGREE`。
- [ ] 如果侧视看起来约 80°而不是 90°，标记 `SIDE_VIEW_NOT_90_DEGREE`。
- [ ] 如果为了看清细节而牺牲侧面角度，标记 `SIDE_VIEW_NOT_90_DEGREE`。
- [ ] 如果角度正确但宝石、托架、杖身或尾部成为纸片，标记 `SIDE_DEPTH_COLLAPSE`。

## 8. 45°视图门禁

- [ ] `left45.png` 是左前 45°，不是正侧面。
- [ ] `right45.png` 是右前 45°，不是正侧面。
- [ ] 45°视图能看到前面设计和侧面厚度。
- [ ] 45°视图宽度大于 `left/right`。
- [ ] 45°视图宽度通常小于或接近 `front/back`。
- [ ] 组件数量、颜色、材质没有变化。
- [ ] `left45.png` 和 `right45.png` 分别符合自己的已确认可见性合同。

## 9. 背视图门禁

- [ ] `back.png` 和 `front.png` 是同一把魔法杖。
- [ ] 背面轮廓与正面一致或合理对应。
- [ ] 背面组件数量不变。
- [ ] 背面材质区不变。
- [ ] 背面可简化雕刻，但不能改造成新武器。

## 10. 归一化检查

- [ ] 所有图片为 `1024x2048`。
- [ ] 所有视图物体高度约 `1720px`。
- [ ] 上下边距一致。
- [ ] 物体居中。
- [ ] 没有明显缩放不一致。
- [ ] 已生成 bbox 测量表。
- [ ] 已生成最终 contact sheet。
