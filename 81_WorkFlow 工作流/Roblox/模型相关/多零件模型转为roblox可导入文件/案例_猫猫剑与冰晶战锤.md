## 前几版暴露的问题

- 有一版贴图内部文件名缺少 `.png/.jpg` 扩展名。
- 有的导出混用了 `UnitScale=1 + Object Scale=100`，有的又使用另一套单位策略。
- 有的对象保留非零位移，公共坐标和交接语义不清楚。
- 贴图曾出现“只改扩展名”和“真实另存格式”混淆。
- Studio 红叉没有返回足够的服务器错误，无法把所有失败归为一个原因。

因此最终不是继续随机修改某一个参数，而是按猫猫剑的结构重建完整导出副本，并强制空场景回导。

## 可复用结论

1. 多零件必须在 Blender 中完成拼接，Studio 不负责重新对位。
2. 每个部件保留独立 Mesh，但共享公共枢轴和同一单位策略。
3. 每个 Mesh 一套材质；图片必须真正按对应格式另存。
4. 当项目明确需要 FBX 时，`Copy + Embed Textures` 可以作为兼容回退；当前默认首测仍是顶层主 GLB，外部贴图保留作事实源和诊断证据。
5. 空场景回导是发布前强制门，但不能替代 Studio 云端验收。
6. 同会话已知成功 FBX 与无贴图候选，是定位 Studio 红叉最有效的两个 A/B 控制。

## 不能升级为默认的案例参数

- 猫猫剑必须四件、战锤必须两件。
- 所有武器总长都等于 4.6 或 7.156855 Stud。
- 所有贴图都必须 1024。
- 所有项目都必须使用同一个 Forward 轴。
- 只要存在或不存在 `.fbm` 就一定成功或失败。
