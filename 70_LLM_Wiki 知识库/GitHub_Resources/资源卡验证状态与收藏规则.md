# 资源卡验证状态与收藏规则

## 一句话说明

资源库的目标不是存链接，而是记录“这个资源有什么用、我验证到哪一步、以后在什么场景能复用”。

## 状态分层

| 状态 | 含义 |
|---|---|
| `collected` | 只是收藏，还没看 |
| `skimmed` | 粗看过，知道大概用途 |
| `studied` | 认真看过并做了笔记 |
| `tried` | 实际尝试过 |
| `verified` | 在本地项目或真实任务中验证可用 |
| `deprecated` | 不再推荐，保留原因和替代方案 |

长期有价值的资源至少应该达到 `studied`；工具类资源最好达到 `tried` 或 `verified`。

## 资源卡必须回答

- 它是什么？
- 适合什么场景？
- 我为什么收藏？
- 有没有使用或验证记录？
- 风险和限制是什么？
- 关联到哪个项目、工作流或学习目标？

## 不建议只保存

- 只有链接，没有用途。
- 只有标题，没有判断。
- 不知道是否看过。
- 不知道是否过时。
- 不知道和自己哪个项目有关。
