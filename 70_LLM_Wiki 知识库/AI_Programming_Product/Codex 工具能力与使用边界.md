# Codex 工具能力与使用边界

## 一句话说明

Codex 更适合被当作“项目级 AI 工作台”，而不是无限记忆聊天框或传统 IDE；它的价值来自项目文件、工具权限、验证闭环、Git 和可复用工作流。

## 核心能力

| 能力 | 适合做什么 |
|---|---|
| 读写文件 | 项目修改、文档整理、批量小修 |
| 运行命令 | 构建、测试、格式化、脚本验证 |
| 内置浏览器 | 前端预览、网页检查、可视化反馈 |
| 图片生成 | 概念图、UI 参考、游戏素材草案 |
| 插件 / MCP | 连接 GitHub、数据库、办公系统等外部服务 |
| Skills | 把重复流程沉淀成可复用能力包 |
| Automations | 稳定流程的定时执行 |

具体功能和模型名称会随版本变化，长期笔记只保留工作流原则，不把某个视频里的版本号当作永久事实。

## 最值得保留的使用原则

- 复杂任务先规划，再执行。
- 每个复杂项目都写 `AGENTS.md`。
- 不轻易开启完全访问权限。
- 一个任务完成后新开对话，避免上下文污染。
- 重要改动先 Git 提交，方便回滚。
- 多任务并行优先用 worktree 或独立线程。
- 重复流程沉淀成模板、Skill 或自动化。
- 外部系统集成优先考虑插件或 MCP。

## 提示词四要素

| 要素 | 含义 |
|---|---|
| Goal | 要完成什么 |
| Context | 相关文件、背景、约束 |
| Constraints | 技术、范围、安全、风格限制 |
| Done When | 完成标准和验证方式 |

没有 `Done When` 的任务容易停在“看起来做了”，但无法判断是否完成。

## 权限和风险

| 风险 | 处理方式 |
|---|---|
| 批量删除或移动 | 先清单、再小批量、保留日志 |
| 项目外文件 | 明确路径和原因 |
| 真实账号/密钥 | 不在明文笔记和代码里暴露 |
| 高风险系统 | 先读规则、先确认边界、保留回滚路径 |
| 自动化 | 先手动跑通，再升级定时任务 |

## 什么时候升级成 Skill

适合升级成 Skill：

- 流程会重复使用。
- 有明确输入、输出和验收。
- 需要固定检查清单。
- 用户希望 Codex 自动按同一套规则执行。

不适合升级成 Skill：

- 一次性想法。
- 规则还不稳定。
- 需要大量临时人工判断。
