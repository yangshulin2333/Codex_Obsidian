## 关键判断

1. 不能把“本地 Git 已有提交”等同于“可以直接上传远端”。当前没有远端地址。
2. 直接把整个 Vault 当普通笔记仓库上传风险很高：体积大、二进制历史难以审阅，视频和 ZIP 也不适合普通 Markdown 同步。
3. 现有大文件已经进入历史；只在 `.gitignore` 里新增规则，不能清除历史中的大对象。
4. 在用户确认之前，不执行历史重写、不删除大型资产、不批量恢复已有删除项。

## 建议边界

### 推荐：笔记仓库与大型资产分开

- Git 远端保存 Markdown、配置、脚本、清单和必要的小型证据图。
- 视频、项目 ZIP、`.rbxl`、完整工程副本和批量生成图使用本地备份、网盘、对象存储或单独资产仓库。
- 新建干净的可上传历史，保留当前 `.git` 作为本地回滚备份，确认远端验收后再决定是否归档旧历史。

### 备选：使用大文件扩展

- 仅在目标 Git 服务支持、配额和单文件上限明确时考虑。
- 需要迁移已有历史，而不只是对未来文件启用大文件规则。
- 迁移会改写提交历史，必须先做可恢复备份并由用户确认。

## 上传前门禁

- [ ] 用户提供目标 Git 服务和远端仓库地址。
- [ ] 用户确认仓库应为私有还是公开。
- [ ] 用户确认采用“笔记与大型资产分开”还是“大文件扩展迁移”。
- [ ] 扫描待上传文本中的凭据、地址、卡号和账号类敏感信息。
- [ ] 生成提交预览，核对删除、移动、新增和忽略项。
- [ ] 本地提交完成后，再执行远端推送并核对远端分支。
